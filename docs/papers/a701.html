SGP-TOD: Building Task Bots Effortlessly via Schema-Guided LLM Prompting

SGP-TOD：通过 Schema 引导的 LLM 提示轻松构建任务型对话机器人

简介

论文针对传统任务型对话机器人需要大量标注数据与微调、维护和功能扩展成本高的问题，提出 SGP-TOD——一种完全免训练的 schema 引导提示方法。方法将任务 schema（本体槽位取值 + 策略骨架）作为符号知识注入冻结 LLM 的提示：DST Prompter 用 belief instruction 引导 LLM 做对话状态跟踪并据此查询数据库，Policy Prompter 用 policy skeleton 引导 LLM 按预定义对话策略生成系统动作与回复。在 Multiwoz、RADDLE、STAR 上取得 SOTA zero-shot 性能，显著超过 few-shot 提示与微调方法；在 STAR 上仅用 2 个格式化示例轮次即可匹敌用 1,000 条对话训练的 SAM，标注成本至少降低 1,000 倍。域扩展实验中只需在 schema 中增改少量模板轮次即可让已部署机器人获得新功能，Success 比 few-shot-GPT3.5 高 32%。对团队的核心启示：用显式、结构化的任务说明组织上下文比堆隐式示例更稳定高效，且可通过编辑 schema 而非重训来扩展 Agent 能力。

问题

构建端到端任务型对话机器人并使其集成新功能，主流做法是对 PLM（T5、GPT-2 等）做微调，依赖充足标注数据与反复重训，人力和算力开销大；而 few-shot in-context learning 的效果又高度依赖示例质量、不稳定。论文探究：能否以最少人工投入，用冻结 LLM 直接构建可在新任务上零样本工作的 task bots。

方法

SGP-TOD 把端到端对话生成系统性拆分为三个子任务，全部由冻结 LLM 完成：(1) Belief State Prediction——DST Prompter 将任务指令、belief instruction（任务/域名 + 全部槽位名 + 分类槽的可行取值或非分类槽的少量取值示例，状态用 SQL 形式表示）、格式化示例与对话历史组装进提示，引导 LLM 预测 belief state，再用其查询数据库得到 DB state；(2) System Action Determination 与 (3) Dialog Response Generation——Policy Prompter 注入 policy skeleton（约 10-20 个模板对话轮次，覆盖基本用户行为与典型 DB 结果对应的系统动作与回复），引导 LLM 依次生成系统动作与 delexicalized 回复，最后自动后处理为自然语言。扩展新功能时只需在 policy skeleton 中插入、修改或删除少量模板轮次，无需重新训练或收集数据。

关键结果

Multiwoz 2.0/2.2 上取得 SOTA zero-shot 端到端性能，显著超过 few-shot 方法，Inform/Success 与 full-shot 微调方法相当；SGP-TOD-CHATGPT 比 zero-shot 提示 IT-LLM-CHATGPT-ZS 的 Success 高 40%、BLEU 高 3%，比 few-shot 提示方法 Success 高约 30 分

RADDLE 四个单域任务上，Combined 全面超过 few-shot 提示与 few-shot 微调方法（含在多个异构对话语料预训练的 SOLOIST）

STAR 上仅用 2 个格式化示例轮次即达到或超过用 1,000 条对话训练的 SAM，标注成本至少降低 1,000 倍；增加格式化示例轮次对性能影响可忽略

域扩展（Restaurant-ext）：SGP-TOD-GPT3.5-EXT 的 Success 比 FEW-SHOT-GPT3.5 高 32%、比 SOLOIST+TEACH 高 48%；仅用旧 Restaurant schema 的 SGP-TOD 也比 SOLOIST 的 Inform 高 10+ 分、Success 高 30+ 分

消融实验（Multiwoz，GPT-3.5）：去掉 Policy Prompter 使 Success 降约 15%、BLEU 降约 3%；去掉数据库信息使 Success 降约 3%；去掉 DST Prompter 使 Inform 降约 40%、Success 降近 17%

LLM 对比：Multiwoz 上 SGP-TOD-GPT3.5 优于 Codex 与 ChatGPT 版本；STAR 上 Codex 优于 GPT-3.5，作者推测与 Codex 在代码数据上预训练、更擅长解读动作标签有关

创新点

与并行的 few-shot ICL 方法 IT-LLM 相比：(i) 用槽位名+取值示例而非槽位描述构造提示，进一步减少人工；(ii) 在 Policy Prompter 中提供 policy skeleton，使回复遵循预定义对话策略。与 zero-shot 迁移方法相比，不需要源域微调，也不需要 slot/action 描述等额外标注。核心主张是用显式、简洁、全面的任务 schema 注入符号知识，优于从训练语料挑选对话轮次的隐式示例引导；且能力扩展通过编辑 schema 而非重训完成。
