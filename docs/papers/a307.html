Architecting Secure AI Agents: Perspectives on System-Level Defenses Against Indirect Prompt Injection Attacks

构建安全的 AI Agent：抵御间接提示注入攻击的系统级防御视角

简介

这是一篇立场论文，针对 LLM Agent 处理不可信外部数据时的间接提示注入攻击，提出系统级防御的架构愿景。论文给出由 orchestrator、plan/policy approver、executor、policy enforcer 等组成的高层架构，用 plan（做什么）与 policy（允许做什么）结构化分析并控制 Agent 行为，并提出三个立场：动态重规划与策略更新必不可少；某些安全决策仍需 LLM，但须严格约束模型可观察内容与决策范围；模糊场景应将个性化与人机交互纳入核心设计。具体方案包括：解耦指令识别与指令跟随决策（模型显式复述意图跟随的指令，系统按来源追溯并裁决），以及让 LLM 在运行时合成步骤级程序化校验器验证环境反馈。作者还指出现有基准（如 AgentDojo 97 个任务中仅 6 个需要策略更新/重规划、攻击载荷均为静态）会带来虚假的安全感与实用性。全文无实验，属于设计立场与研究方向论述。

问题

LLM Agent 在消费检索到的邮件、网页、第三方工具输出等不可信数据时，易被嵌入的恶意指令触发危险动作（间接提示注入），这是 Agent 在高风险场景安全落地的首要障碍。现有防御分模型级、文本级、系统级三类，但论文认为：流行的 plan-execution isolation 与静态 policy 在动态环境中牺牲实用性；完全依赖模型鲁棒性不可靠；现有基准任务简单、攻击载荷静态，使许多防御'在纸面上看起来很好'。论文要回答的核心问题是：如何架构既高实用又安全的通用 Agent，尤其是如何在允许动态重规划与策略更新的同时，可靠区分良性更新与恶意更新。

方法

提出高层系统架构：orchestrator 依据任务生成 plan 与 policy，plan/policy approver 审批，executor 生成具体动作，policy enforcer 依据 policy 批准或阻断，环境反馈或拒绝反馈可触发下一轮 plan/policy 更新；并形式化定义 plan（执行步骤序列/有向图）与 policy（步骤与执行历史上的谓词，可用 Cedar 等 DSL 表达）。在此架构上论证三个立场，并给出两个可操作提案：(1) 解耦指令识别与指令跟随决策——让模型显式 verbalize 意图跟随的指令，系统用词/子串匹配做来源追溯，再按三种模式处置（外部指令默认阻断、需人工确认、结构化指令状态裁决，其中 LLM judge 只看结构化状态与 diff、不看原始环境文本）；(2) 让 LLM 在运行时合成步骤特定的程序化校验器（如字段级完整性约束、在 DOM-to-JSON 结构上提取并校验）验证环境反馈。核心设计原则：能用规则就用规则；必须用模型时，把模型当作输入与任务均受严格约束的 bounded security decision module，从而实现系统级与模型级防御的协同设计。

创新点

这是立场论文而非新防御系统，主要区别在于：(1) 论证 plan-execution isolation 与静态/一次性 policy 在动态环境中必然失效（良性运行时错误、调试类任务、任务相关最小权限无法预先枚举），主张安全感知的动态重规划与策略更新，并指出这会引入'外部数据影响 plan/policy'的新攻击面（对应 dual-LLM 设计中隔离 LLM 到特权 LLM 信息流的安全化难题）；(2) 提出让 LLM 参与安全决策的折中框架——不追求 100% 形式化保证，而是通过严格约束模型输入与决策范围来提高攻击者成本；(3) 系统性质疑现有基准（缺乏需要重规划的多步任务、静态攻击目标与载荷、缺乏自适应攻击者），解释了为何省略关键组件的防御仍能报告高实用高安全；(4) 把个性化与 HITL 从'兜底手段'提升为模糊场景的核心设计考量。
