Knowledge Graph-Guided Retrieval Augmented Generation

知识图谱引导的检索增强生成（KG2RAG）

简介

现有 RAG 依赖语义相似度检索孤立 chunk，结果同质冗余、缺乏 chunk 间事实关联，且按相似度直接拼接进 prompt，限制了 LLM 生成全面可靠回答的能力。KG2RAG 框架分三步：离线用 LLM 从文档 chunk 抽取三元组构建 KG 并建立 chunk-KG 关联（查询无关、支持增量更新）；在线先做语义检索得到种子 chunk，再以 BFS 遍历相关子图的 m-hop 邻域做图引导扩展，召回含相同/相关实体的跨文档 chunk；最后用连通分量最大生成树过滤冗余边，以 KG 为骨架用 DFS 组织成连贯段落，按三元组表示的 cross-encoder 相关性排序填入 top-k 预算。在 HotpotQA、Shuffle-HotpotQA、MuSiQue、TriviaQA 上，KG2RAG 在回答质量与检索质量上均稳定超过基线：fullwiki 设置至少提升 8%，distractor 设置检索精度提升超 7.9%，对超参 k、m 不敏感，随机删除 5%/10% 三元组仍保持稳健。效率方面，其 KG 构建的 token 成本、LLM 调用次数与耗时低于 LightRAG 和 GraphRAG，检索与生成耗时接近 Semantic RAG。

问题

现有 RAG 研究主要用关键词或语义相似度检索与 query 最相似的孤立 chunk，检索结果同质冗余，忽略了 chunk 之间的内在关系，无法进一步激活 LLM 的推理能力；且检索到的 chunk 通常按相似度分数顺序直接拼接进 prompt，导致信息碎片化，限制 LLM 生成全面、可靠回答的能力。

方法

KG2RAG 是一个用知识图谱为 RAG 提供 chunk 间 fact-level 关系的框架，包含三个阶段：(1) 文档离线处理：按句子/段落结构切分 chunk，用带示例的 prompt 驱动 LLM（LLaMA3-8B）从每个 chunk 抽取 (head entity, relation, tail entity) 三元组并关联回源 chunk，形成 chunk-KG 关联；该过程与 query 无关，可离线一次性构建并支持增量增删文档。(2) KG 增强的 chunk 检索：先用 embedding 模型（mxbai-embed-large）+ 余弦相似度取 top-k 种子 chunk，再从 KG 中抽取种子 chunk 对应的相关子图，用 BFS 遍历 m-hop 邻域扩展子图，读出所有关联 chunk，从而召回与 query 语义相似度不高但含相同/相关实体的跨文档 chunk，避免冗余与同质化。(3) KG-based context organization：作为 filter，将扩展子图转为无向加权图，对每个连通分量生成最大生成树（MST）以剔除冗余边；作为 arranger，以权重最高的边为根用 DFS 将 chunk 串成连贯段落，并用 cross-encoder reranker（bge-reranker-large）基于三元组表示对 MST 段落做相关性排序，按序填充直到达到 top-k chunk 预算，最终连同 query 一起送入 LLM 生成回答。

关键结果

在 HotpotQA 上，所有 RAG 方法相对 LLM-only 在 F1 上提升超过 29.1%，Shuffle-HotpotQA 上提升超过 26.4%；其中 KG2RAG 一致最优，尤其在 fullwiki 设置与 Shuffle-HotpotQA 上。

fullwiki 设置下（候选文档规模是 distractor 的数千倍），KG2RAG 相比基线至少提升 8%。

Shuffle-HotpotQA 上，KG2RAG 在 distractor 与 fullwiki 设置分别至少提升 2.5% 与 6.4%。

distractor 设置下检索精度显著更优：HotpotQA 与 Shuffle-HotpotQA 上分别超过 7.9% 与 6.9%；fullwiki 设置下精度与召回均一致优于其他 RAG 方法。

用 Llama-3 对 HotpotQA 全部 66,581 篇文档做三元组抽取，构建出含 211,356 条三元组、98,226 个实体、19,813 种关系的 KG，每个三元组关联其源 chunk。

鲁棒性：从 KG 中随机删除 5% 或 10% 的三元组后，KG2RAG 仍保持稳健并优于基线。

效率：KG 构建阶段 KG2RAG 的 token 成本、LLM 调用次数与时间成本均低于 LightRAG 与 GraphRAG；每查询的检索与生成耗时低于 LightRAG/GraphRAG、非常接近 Semantic RAG。

超参敏感性：KG2RAG 对 topk 最不敏感（k 过大如 15 时召回提升但回答质量不成比例提升），m=1 即为合适设置，对 m 同样低敏感。

创新点

与按语义相似度取孤立 chunk 的传统 RAG、基于句级文本相似度构建文档 KG 的 KGP（论文指出其本质近似于简单扩大上下文窗口）、以及面向 query-focused summarization、先做层次化 KG 切分与社区检测的 GraphRAG 不同，KG2RAG 直接利用 KG 的 fact-level 结构与事实知识做跨文档 chunk 扩展，并以 KG 为骨架把 chunk 组织成连贯段落、按段落级（三元组表示）相关性重排；同时 chunk-KG 关联与查询无关，可离线一次性构建并支持增量更新，区别于 sentence window retrieval 只考虑同一文档内物理邻近的做法。
