OpenICL: An Open-Source Framework for In-context Learning

简介

该论文针对 In-context Learning (ICL) 实现碎片化的问题：检索与推理方法分散在不同项目中、不同模型/数据集/任务的预处理要求各异，导致方法难以系统比较与复现。作者提出开源框架 OpenICL，采用松耦合的 Retriever + Inferencer 架构：Retriever 支持 corpus-level 与 instance-level 的 Random、TopK、BM25、VoteK 等免训练检索方法，Inferencer 支持 PPL、生成式与 Chain-of-Thought 等推理策略，并可递归调用以实现多阶段方法；上下文通过 PromptTemplate 拼接，并借助数据并行与模型并行（Megatron、Zero）提升大模型推理效率。作者在 SST-2、PiQA、GSM8K、WMT16 de-en、Gigaword 五个任务上，用 GPT-Neo (2.7B)、XGLM (7.5B)、text-davinci-003 GPT-3 (175B) 验证了组件可灵活组合并复现 SOTA 方法结果（正文未列出具体数值）。对团队而言，它是组织 few-shot 上下文、管理提示模板与搭建 LLM 评测流水线的直接工程参考。

问题

ICL 已成为使用和评测 LLM 的新范式，但其实现复杂：涉及多样的检索与推理方法，且不同模型、数据集和任务的预处理要求各不相同；现有项目实现高度定制化，缺乏统一框架，使系统化评测与不同方法间的比较变得困难。

方法

OpenICL 遵循三个设计原则：模块化（P1）、效率（P2）、通用性（P3），采用松耦合的两大组件。Retriever 负责从已有训练数据中检索 in-context 示例，支持 corpus-level（整个测试集一组示例）与 instance-level（逐条测试输入检索）两种粒度，内置 Random、TopK、BM25、VoteK 等免训练检索方法；Inferencer 支持 PPL-based、channel、生成式与 CoT 等推理策略，可递归调用以支持 chain-of-thought、selection-inference 等多阶段方法，并可挂接 scorer 评估预测。上下文通过 PromptTemplate 组织，用 </E>、</Q> 占位符区分 in-context 示例与测试输入。效率上实现数据并行与模型并行（支持 Megatron 与 Zero）；通用性上支持 decoder-only 与 encoder-decoder 两类模型、本地 checkpoint 或 API（如 OpenAI GPT-3）两种接入方式，并集成 HuggingFace datasets；将示例数设为 0 还可无缝支持 prompt learning。

创新点

论文指出现有 ICL 实现高度定制化、缺乏统一框架，OpenICL 以松耦合的模块化设计填补这一空缺：将多种示例检索方法（TopK/BM25/VoteK 等）与推理策略（PPL/生成式/CoT 等）整合在同一框架下，便于系统化比较与快速原型验证。与专注 prompt learning 的 OpenPrompt 相比，OpenICL 的重心在示例检索与推理策略的整合，同时可通过将示例数设为 0 兼容 prompt learning；此外内置数据/模型并行以支撑大规模 LLM 评测，这是其作为评测工具的差异化定位。
