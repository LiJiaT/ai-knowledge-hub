Generated Knowledge Prompting for Commonsense Reasoning

面向常识推理的生成知识提示（Generated Knowledge Prompting）

higharXiv提示技术RAG与检索思维链与推理评测基准成本与效率基于arXiv版本
下载原文 PDF

简介

论文研究在已有大规模预训练模型（T5-11b、GPT-3）的前提下，外部知识能否继续提升常识推理表现，且不依赖结构化知识库与任务定制监督。方法为 Generated Knowledge Prompting：先用「指令+5 个人工编写的问题-知识演示对」的 few-shot 提示驱动 GPT-3，为每个问题采样约 20 条知识语句，再把每条知识与问题拼接后交给推理模型打分，选择被最强知识支持的答案。结果显示方法在 NumerSense、CSQA2、QASC 三个基准刷新 SOTA，零样本场景提升 7%-10%，优于模板式 self-talk，与检索式知识大体相当。对团队而言，这是「生成式上下文增强」的代表工作：当检索语料缺失或质量差时可用模型自产知识扩充上下文，且证明小模型配合生成知识可逼近大模型效果，对提示设计与推理成本优化均有直接参考价值。

问题

检验外部知识在最大规模预训练模型之上是否仍能提升常识推理；已有引入外部知识的方法依赖高质量、高覆盖的域内结构化知识库，且常需任务定制的知识融合监督与联合微调，在缺乏合适知识库的任务（如 NumerSense、CSQA2）上难以适用，论文寻求一种无需知识库、无需额外微调、可灵活迁移的知识引入方式。

方法

两阶段方法：(1) 知识生成——用「指令+5 个人工编写的演示（问题-知识对）+新问题占位符」的 few-shot 提示驱动 GPT-3，对每个问题以 nucleus sampling（p=0.5）采样 M=20 条自然语言知识语句（CSQA2 用 M=5）；演示设计准则是知识语句应把常识问题转化为显式推理步骤（如演绎），而非直接给出答案。(2) 知识集成——将每条知识与问题文本拼接构成增强问题，用推理模型（零样本 T5/GPT-3 或微调的 UnifiedQA/Unicorn）对每个选项计算支持分，选择被某条知识最强支持的答案（自适应选择最佳知识）；推理模型可为任意现成或微调模型，无需为知识融合做任何进一步微调。

关键结果

NumerSense：在零样本 T5 上由 66.18 提升至 72.47（+6%），刷新 SOTA

CSQA2：在微调 Unicorn（此前非检索类 SOTA）上由 70.2 提升至 73.03（+2%）

QASC：在微调 UnifiedQA 上由 76.74 提升至 80.33（+3%）

零样本推理模型提升 7%-10%：NumerSense 64.05→72.47、CSQA 39.89→47.26、QASC 44.89→55.00

CSQA dev 上比模板式 self-talk 相对 T5-11b 基线多提升 1.89%

NumerSense 上比检索式知识再高 8.83%（test-core）/7.37%（test-all）；QASC 上因检索知识为数据集构建用的 gold knowledge，生成知识明显逊于检索

性能随知识条数增加而提升，在 M=20 饱和，继续增加因噪声增多开始下降

推理模型越小收益越大：最小 T5 加知识后与 T5-3b 基线相当，T5-large 超过 GPT-3 基线；GPT-3 自身推理也可从自生成知识获得 9.0% 提升

知识生成模型规模：175B 带来 10.5% 提升，6.7B 为 5.0%，1.3B 与 0.4B 无显著提升

人工评测（κ=0.57）：83% 知识事实正确、72% 有帮助、13% 有害；纠正模型预测的知识中 93% 被判有帮助，误导性知识中仅 21% 有帮助、39% 有害

成本：未训练任何新模型，推理约 200 GPU 小时，GPT-3 API 约 $500

创新点

与依赖人工模板的 self-talk、依赖微调知识生成器的 DynaGen 等先前「生成文本增强推理」方法不同，本方法只需少量人工编写的任务风格 few-shot 演示即可灵活生成超出预定义模板范围的知识；无需结构化知识库、无需任务定制监督或联合微调，可直接叠加在零样本或微调的现成推理模型上，更灵活、易迁移、工程效率更高。
