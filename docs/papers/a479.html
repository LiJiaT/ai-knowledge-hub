Successive Prompting for Decomposing Complex Questions

Successive Prompting：用于分解复杂问题的连续提示方法

简介

论文研究少样本设定下的复杂问题问答：单次生成的 CoT 式提示把'问题分解'与'子问题回答'的监督耦合在一起，只能基于原复杂问题选一组 in-context 示例，也无法在 LM 不擅长的步骤换用专用组件。作者提出 Successive Prompting：迭代地把复杂问题拆成下一个简单问题并作答，QD（问题分解）与 QA（问答）两个阶段交替调用 LM，直到输出终止符与最终答案；两个阶段分别维护检索索引、按当前步骤挑选示例，并可分别微调、注入合成数据，或把算术步骤交给确定性符号计算模块执行。为缓解分解标注昂贵的问题，作者从 Wikipedia 半结构化表格合成约 141K 复杂问题（525K QD、257K QA 样本）。在 few-shot DROP 上，in-context 设定比 CoT 高 4.6 F1，微调后最佳模型测试集 50.2 F1、比同等监督 SOTA 高 5.1 F1。其'分步提示+按步检索示例+模块化工具委派'的思路对团队的提示工程与 Agent loop 设计有直接参考价值。

问题

在少样本设定下回答需要潜在多步决策的复杂问题（如 DROP、HotpotQA）时，现有 CoT 式单次生成方法把问题分解的监督与中间步骤回答的监督耦合在一起：模型只暴露于一组基于复杂问题邻近度选出的 in-context 示例，可能不含中间步骤所需的最优监督；模块化程度低，无法在 LM 表现不佳的推理步骤改用符号推理引擎等专用组件；且人工撰写中间分解标注成本高昂。

方法

Successive Prompting：将每个潜在步骤表示为（简单问题 qk, 答案 ak）对而非陈述句；每次 LM 调用只做一件事——QD 阶段生成下一个简单问题，QA 阶段回答它，交替迭代直到模型输出终止符（'There are no more questions left to ask' / 'EOQ'）并给出最终答案。为 QD 与 QA 分别建立检索索引（I_D 存部分分解链，I_A 存所有简单 QA 对），用 QQP 句子嵌入 + faiss 按当前步骤检索 in-context 示例；微调路线使用基于 T5 的 UnifiedQA 多任务训练，配合控制码（'QS:'/'A:'）与对比估计损失；算术类简单问题解析后交给确定性符号计算模块执行，无法解析时才回退到 LM；并从 Wikipedia 表格用模板合成 10 种操作（COUNT、FILTER、SUM、COMPARISON 等）及其高阶组合的分解数据。

关键结果

In-context 设定（GPT-J 6B，DROP）：仅用合成数据时比 CoT 高 3.5%，加 300 条 DROP 分解标注后高 4.3%；结论中给出 in-context 下比 CoT 高 4.6 F1；最佳 in-context 配置（Synthetic + DROP）测试集 30.6% F1

微调设定：最佳模型（SP w/ decomp）测试集 50.2 F1，比同等监督的 SOTA（TASE + Synthetic w/ decomp，45.1 F1）高 5.1 F1；dev 上比该 SOTA 高 5.4 F1

消融：把符号计算器换成 LM 做算术，性能下降 1.5% F1；仅把 in-context QA 换成微调 QA（QD 仍为 in-context）提升 10% F1（结论中表述为 9.5 F1）

合成数据普遍提升所有模型性能，其中 TASE 提升接近 20% 绝对值；合成数据规模约 141K 复杂问题、525K QD 样本、257K QA 样本

分解质量与错误归因：QD 阶段准确率 in-context 88%、微调 96%；错误预测中 QA 答错占 40%（in-context）/22%（微调），分解错误占 30%/30%，推理类型超出合成数据覆盖占 28%（in-context）/46%（微调）

创新点

相对 CoT：把每个潜在步骤表示为 QA 对而非陈述句，将 QD 与 QA 解耦为多次 LM 调用，从而每步可检索更贴合的 in-context 示例、可按步骤独立训练、可注入合成数据填补能力缺口、可在合适步骤替换为确定性符号模块。相对同期 Least-to-Most：分解与执行交错进行，生成下一个问题时能看到已回答的子问题，利于长链引用。相对 TMNs/MRKL：支持高阶推理组合，并用对比估计训练分解器，无需额外的链打分器。
