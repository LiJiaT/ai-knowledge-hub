简介

论文针对 LLM 难以与现有软件（以电子表格为代表）可靠交互、且缺乏标准化交互框架与评测基准的问题，提出 SheetCopilot Agent。方法上，作者将表格软件功能抽象为一组带类型参数、使用文档与示例的原子动作（virtual API），并设计基于状态机的 observe-propose-revise-act 闭环规划框架：每步注入表格状态与执行错误反馈，按需检索动作文档以弥补上下文窗口限制，并用特殊 token 输出格式约束和'远离官方命名'的动作同义词抑制幻觉。作者还从 superuser.com 构建了 221 个任务的基准与全自动执行评测流水线（Exec@1/Pass@1/A50/A90）。关键结论：SheetCopilot 单次生成 Pass@1 达 44.3%、Exec@1 达 87.3%，大幅超过生成 VBA 代码的基线（Pass@1 +28.0%）；消融显示闭环反馈与外部文档注入带来显著提升，且细粒度动作优于集成式高级动作。

问题

LLM 与现有复杂软件的无缝互操作能力不足：缺乏模型-应用交互的标准化框架与全面的性能评测基准。具体挑战包括：1) 将软件复杂内部状态与庞大功能转译为模型可理解的文本；2) 让模型准确且安全地生成软件命令与参数，并具备校验、调试、拒绝或修订机制；3) 在多步任务中监控软件状态变化、异常与错误并据此调整。此外，此前电子表格 NLP 研究局限于公式生成等子集，缺少标准化评测手段。

方法

SheetCopilot 采用 in-context learning 框架，核心包括：1) 原子动作抽象——将表格软件功能建模为带 API 名称、类型化参数、使用文档与示例的 virtual API（共 44 个），可跨表格平台实现，避免依赖 VBA 等嵌入式脚本；2) 基于状态机的任务规划——分为 observing、proposing、revising、acting 四阶段闭环：注入表格状态描述、拼接系统提示/任务指令/状态/规划历史生成下一步动作，对校验错误与运行时错误进行反馈式修正，并按需检索该动作的详细文档与示例注入提示（retrieval-based revision）；3) 幻觉缓解——要求模型用特殊 token（如 @）包裹动作以校验输出格式，并将动作名替换为在 embedding 空间中远离官方名称的同义词以避免与模型内化知识冲突；4) 数据集与评测——从 superuser.com 抓取约 16k 问答对，经关键词/LLM 过滤、embedding 聚类选种、GPT-4 改写适配、GPT-3.5 简化与校验，构建 221 任务核心集与 28 个工作簿，通过执行后最终表格状态的必要属性与 ground truth 比对自动判定正确性。

关键结果

SheetCopilot 单次生成正确完成 44.3% 的任务（Pass@1），为 87.3% 的问题生成完全可执行的命令序列（Exec@1）

以 GPT-3.5-Turbo 为后端时，相比生成并运行 VBA 代码的方法，Exec@1 提升 9.5%、Pass@1 提升 28.0%

消融实验：闭环控制（表格状态+错误反馈）与外部动作文档及示例结合，使 Exec@1 较基线提升 30.7%；仅插入外部动作文档即带来 Exec@1 +17.2%、Pass@1 +10.0%

使用远离官方名称的同义词动作名提升 Pass@1 并降低 A50/A90；将图表属性并入集成式 CreateChart 使 Exec@1 下降 12.6%、Pass@1 下降 6.1%，而将 SetFormat 拆分为更细粒度动作带来 Exec@1 与 Pass@1 的显著提升

在 10% 子集对比中，GPT-4 取得最佳 Pass@1 与 A50/A90，GPT-3.5-Turbo Exec@1 最高；GPT-4 在困难任务上因超出 4096 token 上限产生不完整解

GPT-3.5-Turbo 在全量核心集的失败案例中，错误公式与错误范围合计超过 50%，Wrong action 与 Incomplete solution 合计占 33.7%

温度从 0.0 到 1.0 变化时各指标保持稳定；任务指令简化使平均 token 长度从 47.1 降至 33.8

创新点

相对已有工作的区别：1) 此前表格 NLP 研究（Flash Fill、NLyze、基于 LLM 的公式生成）集中于公式生成等有限子集，本文首次面向通用表格控制任务构建基准与全自动执行评测；2) 相比直接生成 VBA 代码的路线，提出软件无关的原子动作抽象作为 LLM 与软件之间的桥梁；3) 提出基于状态机的 observe-propose-revise-act 闭环规划，结合表格状态反馈、错误反馈与按需检索外部动作文档；4) 通过动作同义词替换与输出格式约束缓解幻觉，并给出动作粒度选择（细粒度优于集成式）与动作命名的设计结论。
