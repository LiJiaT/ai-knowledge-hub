GenoMAS: A Multi-Agent Framework for Scientific Discovery via Code-Driven Gene Expression Analysis

简介

论文针对基因表达分析自动化中"固定工作流在边缘案例上失效、全自主 Agent 缺乏科学精度"的两难问题，提出 GenoMAS 多智能体框架。系统由六个专职 LLM Agent（PI 编排、GEO/TCGA 两个 Data Engineer、Statistician、Code Reviewer、Domain Expert）通过类型化消息协议协作，核心 guided-planning 框架将任务指南展开为 Action Unit，编程 Agent 在每一步自主选择推进、修订、跳过或回溯。在 GenoTEX 基准上，数据预处理 CSC 达 89.13%、基因识别 F1 达 60.48%，较此前最优分别提升 10.61% 与 16.85%，API 成本降低 44.7%，代码执行成功率 98.78%。关键结论包括：异构 LLM 分工（Claude Sonnet 4 写码、OpenAI o3 推理审查、Gemini 2.5 Pro 领域知识）较同构配置 F1 再提升 7.5%；按 Action Unit 类型索引的代码记忆复用率稳定在约 65%，显著节省执行时间。

问题

科学计算工作流（以基因表达分析为例）的自动化存在根本矛盾：基于固定工作流的方法缺乏处理边缘案例与持续异常的灵活性，而全自主 LLM Agent 又缺乏严格科学分析所需的精度与过程控制，早期错误会级联传播导致结果整体失效。论文要解决如何构建同时具备结构化工作流可靠性与自主 Agent 适应性的系统，从原始数据可靠地完成多步代码分析。

方法

GenoMAS 融合结构化工作流与自主 Agent：(1) 六个专职 Agent 分三类（PI 编排、编程类 Data Engineer/Statistician、顾问类 Code Reviewer/Domain Expert），经类型化消息传递协议与基于拓扑的消息路由协作，环境用 FIFO 消息队列异步调度并防止循环依赖；(2) guided-planning：任务指南编码为 DAG 并分解为 Action Unit，Agent 基于任务历史在每步选择推进/修订/跳过/回溯（retraction 带预算限制）；(3) 代码写作-审查-修订三阶段循环，Code Reviewer 审查时做上下文隔离（不看同步骤前几轮反馈）以避免级联偏差，需生物医学知识的步骤改询 Domain Expert；(4) 异构 LLM 骨干：Claude Sonnet 4 编程、OpenAI o3 规划与审查、Gemini 2.5 Pro 领域知识；(5) 按 Action Unit 类型索引的代码记忆存储已验证片段供复用；(6) 系统级优化：异步 LLM 调用、流式处理、断点恢复、超时控制、结果缓存。

关键结果

GenoTEX 端到端评测：数据预处理 Composite Similarity Correlation 89.13%，基因识别 F1 60.48%，较此前最优 GenoAgent（F1 43.63%）分别提升 10.61% 与 16.85%；AUROC 提升 0.17，API 成本降低 44.7%

异构 LLM 配置较纯 Claude 同构配置 F1 额外提升 7.5%、成本降低 48.9%

代码执行成功率 98.78%；zero-shot OpenAI o3 基线仅 0.56 AUROC，通用 Agent 中最好的 Biomni 仅 14.82% F1，Claude Code/Cursor/Manus/AutoGen/MetaGPT 未产出完整有效分析

代码记忆复用率在初始学习后稳定在约 65%，追踪 50 个 cohort 会话节省 57.8 分钟（平均每次复用节省 20.3 秒）

分任务看：基因表达数据预处理 CSC 91.15%，临床特征预处理仅 32.61%（主要瓶颈）；使用专家预处理数据时，含 batch effect 校正的统计分析 F1 达 95.26%，远超 Lasso 固定脚本的 14.03%

定性结果：识别基因与 Open Targets 已知关联的 GSEA 富集分数 0.53（FDR q 值 0.16），为中等程度吻合；PI Agent 仅占 2.3% 消息量，97.7% 交互为自协调

创新点

区别于既有工作：(1) 现有科学发现 Agent 多停留在任务规划、文档检索或工具编排层面，GenoMAS 把科学自动化当作"代码问题"而非检索或协调问题，Agent 直接生成、修订、验证可执行代码；(2) 不同于固定架构模板的多 Agent 框架，guided-planning 在 DAG 指南的结构约束与推进/修订/跳过/回溯的自主决策之间取得平衡；(3) 采用异构 LLM 骨干实现认知分工，而非同构配置；(4) 引入上下文隔离的代码审查与按 Action Unit 类型索引的代码记忆；(5) 附录系统测试了 Biomni、AutoGen、MetaGPT、Claude Code、Cursor、Manus 六个通用 Agent 的失败模式，论证通用自主 Agent 缺乏过程控制机制。
