MultiTool-CoT: GPT-3 Can Use Multiple External Tools with Chain of Thought Prompting

MultiTool-CoT：GPT-3 能通过 Chain of Thought 提示使用多个外部工具

简介

LLM 在推理任务中受限于参数与训练数据规模带来的知识不足（稀疏领域知识下更严重），且基于连续 token 表示的计算无法保证算术精确，而已有工具增强研究只针对单一问题使用单一工具。论文提出 MultiTool-CoT：用 few-shot CoT 提示让 GPT-3 在推理过程中生成形如 << External tool name >> 的工具触发符，框架检测到触发符即暂停生成、执行外部工具（calculator、chemical reaction predictor、molar mass list）、把结果拼回推理链后继续生成，工具执行失败时回退由 GPT-3 自行生成输出。few-shot 示例采用两步构建：先让 GPT-3 zero-shot CoT 生成推理过程，再人工插入工具触发符及输入输出。在 NumGLUE Task 2（需数值推理+化学领域知识，325 题）上取得 85.85 准确率的 state-of-the-art，且多工具的增益大于各单工具增益之和；错误分析显示 39% 源于错误推理过程、35% 源于无效工具输入。

问题

LLM 的现实世界知识受模型参数与训练数据规模限制，在稀疏领域知识场景下问题更严重；同时 LLM 基于连续 token 表示的计算无法保证算术计算准确。已有工具增强研究只针对单一缺陷（算术易错或知识不全）调用单一外部工具，未解决需要多种能力组合的问题。

方法

提出 MultiTool-CoT 交互式框架：提示由可用工具说明、人工标注的 few-shot CoT 示例（推理过程中按特定格式嵌入 << External tool name >> 触发符及对应输入）和待解问题组成。生成中一旦出现工具触发符即停止文本生成，解析工具名与输入、执行工具、将结果追加到推理过程末尾后重启生成；若工具因故无法执行（如生成了无效输入），回退由 GPT-3 生成工具输出。最后用额外的 GPT-3 few-shot 过程把推理链最后一句映射为答案值。实验使用 calculator、chemical reaction predictor、molar mass list 三种外部工具；few-shot 示例通过'GPT-3 zero-shot CoT 生成 + 人工标注触发符'两步流程构建（20 个训练问题），temperature 设为 0。

关键结果

在 NumGLUE Task 2 测试集（325 题）上，MultiTool-CoT 达到 85.85 准确率，为 state-of-the-art

显著优于不使用外部工具的方法和仅使用单一外部工具的方法；且多工具带来的性能提升大于各工具单独使用时提升之和

46 个失败案例的人工归因：错误推理过程 39%、无效工具输入 35%、gold answer 本身错误 15%、答案格式差异 11%

减少 few-shot 示例数量会降低准确率但降幅不大；20 个 few-shot 示例约 3000 tokens，接近 GPT-3 可处理的 4000 tokens 上限

创新点

与以往需 fine-tuning 才能调用单一工具的工作（Cobbe et al. 的计算器、Nakano et al. 的浏览器）以及 few-shot 单工具方法（Yao et al. 的 Wikipedia API）不同，本文不依赖 fine-tuning，首次通过 few-shot CoT 提示让 LLM 在推理中组合调用多个外部工具；论文还指出 LangChain 虽实现了类似的多工具框架，但截至投稿时未在任何基准数据集上验证其有效性。
