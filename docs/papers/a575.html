SQL-PaLM: Improved Large Language Model Adaptation for Text-to-SQL (extended)

简介

论文研究如何让超大规模 LLM（PaLM-2 Unicorn）更好地适配 Text-to-SQL 任务，回答'仅靠 prompting 是否足够'与'如何 tuning'两个问题。方法上，few-shot prompting 结合执行反馈的 consistency decoding 与 error filtering；instruction tuning 则系统考察训练数据覆盖与多样性、LLM 生成合成 SQL、注入问题相关数据库内容等因素，并提出检索式与程序辅助两种列选择方法应对超大 schema，以及基于执行反馈的 test-time selection 整合多种训练范式。关键结论：在更难的 BIRD 上 tuning 比 prompting 高约 8.5%，数据库内容注入带来约 3% 提升，test-time selection 再加 2.9%，最终在 Spider dev 达 87.3%、BIRD dev 达 61.7% 执行准确率；硬列选择可将输入 token 压缩至 26%-42% 而仅损失 1-3% 准确率。错误分析还发现 BIRD 基准约 31% 的'错误'实为数据集标注问题，性能上限约 70%。

问题

真实场景的 Text-to-SQL 面临多重挑战：自然语言问题歧义且依赖领域知识、真实数据库表/列数量巨大导致 schema 超出 LLM 上下文限制、SQL 本身复杂（嵌套子查询、多表 JOIN、格式化数据提取）、配对 (问题, SQL) 标注数据稀缺且质量参差。同时尚不清楚仅靠 few-shot prompting 是否足以应对这些挑战，以及如何让大模型通过 tuning 有效适配该任务。

方法

SQL-PaLM 框架基于 PaLM-2 Unicorn，覆盖两条学习路线：(1) few-shot prompting：采样多个 SQL 输出，用执行器验证并按执行结果聚合排序（execution-based consistency decoding），过滤执行报错的候选；(2) instruction tuning：混合 Spider+BIRD 等多数据集扩充覆盖与多样性；用另一个 LLM（GPT-4）生成多样化合成 SQL 并以执行校验+相似度阈值过滤保证正确性与多样性；通过最长连续子串匹配抽取与问题相关的数据库内容注入输入；(3) 表/列选择：retrieval-based（对列名/类型/描述/示例值构建 embedding，按余弦相似度取 top-K）与 program-aided（先让 LLM 生成 preliminary SQL，再解析 FROM/JOIN 与列名得到相关列），并以 soft（附加选中列描述、保留全 schema）或 hard（删除未选列）方式集成到 prompting 与 tuning 流程；(4) test-time refinement：跨多个训练范式的候选 SQL 中，选择执行有效且执行结果获多数范式支持的输出。

关键结果

Few-shot SQL-PaLM 在 Spider dev 上最终达到 87.3% 执行准确率；消融显示去掉 execution-based consistency decoding 或 error filtering 分别导致 4.9% 和 3.5% 的性能下降

Tuning 相比 few-shot prompting 在 BIRD dev 提升约 8.5%，在 Spider dev 提升约 1%，说明任务越复杂 tuning 收益越大；全参数 SFT 优于 LoRA，LLaMA 系列微调结果比 PaLM-2 低约 10%

注入与问题相关的数据库内容在 BIRD dev 带来超过 3% 的准确率提升；混合 Spider+BIRD 训练数据带来约 2% 提升，加入 LLM 合成 SQL 数据再带来 1.3% 提升

合成数据中 81.4% 的生成 SQL 经官方评测验证正确，经相似度过滤（剔除相似度>0.9）后 78.8% 保留用于训练

列选择：retrieval-based 方法 top-10/top-25 召回率分别为 81.52%/92.93% 但精确率较低；program-aided 方法 recall/precision/F1 均超过 90%，平均仅选 5.24 列

硬列选择将输入 token 压缩至完整 prompt 的 26%（program-aided）或 42%（retrieval top-25），代价为 1-3% 准确率损失；ground-truth 列选择上限为 62.06%（比推断列选择高约 3%）；全量列描述反而使性能下降 4.11%

Test-time refinement via execution-based selection 相比单一训练范式提升 2.9%；最终在 BIRD dev 达 61.7% EX、Spider dev 达 87.3% EX

错误分析：随机抽取的 100 个 BIRD '错误'样本中 31 个实为数据集相关问题，推算 BIRD dev 性能上限约 70%；按难度划分准确率为 easy 68.92%、moderate 52.07%、challenging 47.89%

创新点

与已有工作多聚焦 few-shot prompting 策略或微调较小开源模型不同，本文系统研究超大规模 LLM（PaLM-2 Unicorn）的 instruction tuning 适配 Text-to-SQL；提出 program-aided 列选择（利用 LLM 生成 preliminary SQL 再解析出相关列，区别于以往 pattern matching 或端到端训练的 schema linking，且作为可解耦的独立预处理模块）与检索式列选择，并给出 soft/hard 两种集成方式及成本-精度权衡分析；提出基于执行反馈的 test-time selection 跨训练范式整合（区别于同范式内采样的 consistency decoding）；并对训练数据多样性、合成数据、数据库内容注入等关键因素给出系统消融，以及对基准数据集质量的上限分析。
