StreamingRAG: Real-time Contextual Retrieval and Generation Framework

StreamingRAG：实时上下文检索与生成框架

简介

传统 RAG 依赖耗时的抓取、索引与结构化预处理，难以支撑实时分析；重量级 MM-LLM 处理多模态流延迟与算力成本过高（GPT-4V 每帧可达 3-5 秒），会漏掉正在演化的关键事件。StreamingRAG 用轻量 VQA 模型（BLIP、BLIP-2）在实时约束下从视频帧抽取场景-对象-实体关系，构建随时间演化的时序知识图谱作为上下文表示与检索基础。调度器按用户约束、演化事件与当前上下文动态分配抽取优先级，Visual Query Generator 结合知识库生成并精化下一轮问题（每轮最多五个）回传抽取管线形成闭环；系统托管在 DataX 流处理平台，lambda 引擎同时支持持续运行的 standing queries 与交互式查询。在智能交通异常检测评测中，吞吐量提升 5-6 倍、资源消耗降低 2-3 倍，8 个事件检出 7 个（baseline 仅 1 个）。对团队而言，其动态优先级上下文管理与轻量模型分层降本的思路可借鉴，但场景为实时视频流，与团队文本类工程自动化场景差异较大。

问题

如何对多模态数据流（视频、图像、传感器流）做实时的上下文检索与生成：传统 RAG 的抓取-索引-结构化预处理流程太慢，不适合实时场景；重量级 MM-LLM 延迟与算力成本过高（GPT-4V 每帧 3-5 秒），会漏掉正在演化的关键事件，也难以支撑数百路传感流的并发实时处理。

方法

提出 StreamingRAG 框架，含四个组件：(a) 抽取管线——用轻量推理引擎（VQA 模型 BLIP、BLIP-2）在实时约束下从视频帧抽取空间元数据；(b) 知识管线——将元数据转为可执行知识，用 NetworkX 维护时序知识图谱（KG），并结合人工构建的知识库（KB，实体-属性-关系映射）由 Visual Query Generator (VQG) 生成/精化下一轮问题（每轮最多五个）嵌入 prompt 回传抽取管线，形成'提问-抽取-更新'闭环，事件结束后重置 KG；(c) DataX 流处理平台承载组件并提供动态扩缩；(d) lambda 引擎以 batch/serving/speed 三层同时支持持续运行的 standing queries 与按需的 interactive queries。核心手段是基于动态优先级的知识抽取：按用户约束、演化事件与当前上下文决定优先处理哪些实体与关系，并用轻量模型与较小的输出 token 规模满足实时延迟约束。

关键结果

实时分析吞吐量提升 5-6 倍（5-6x faster throughput）

使用轻量模型使资源消耗降低 2-3 倍（以 GPU 内存占用衡量）

StreamingRAG 以约 8 fps（约为视频帧率的 1/3）运行，可有效抽取上下文空间信息

事件检测（共 8 个事件）：StreamingRAG 检出 7 个（87.5%），baseline 检出 1 个（12.5%）

响应准确性通过人工检查评估：baseline 在碰撞案例中漏检或误判（如把车-人碰撞误判为游戏），StreamingRAG 通过多帧时序分析能推断出事故发生，但在 hit-and-run 案例中遗漏了事故发生的确切瞬间

创新点

与传统面向静态数据、需离线预处理的 RAG 不同，StreamingRAG 直接对流式数据实时构建演化知识图谱；以动态优先级调度替代'处理每一数据块/全部实体'的做法；通过 VQG 在知识管线与抽取管线之间形成反馈闭环；并用轻量 VQA 模型替代重量级 MM-LLM，通过控制输出 token 规模满足实时延迟约束。
