MathPrompter: Mathematical Reasoning using Large Language Models

MathPrompter：利用大语言模型（LLM）进行数学推理

简介

LLM 在算术推理这类有唯一正确答案的任务上常给出错误结果，且不提供置信度，造成信任赤字、阻碍实际采用。MathPrompter 提出一种 Zero-shot-CoT 提示技术：先将题目中的数值替换为变量生成代数模板，再用不同提示（推导代数表达式、编写 Python 函数）让 LLM 生成同一问题的多条解析解，然后用 Python 的 eval() 在多组随机变量赋值上执行这些表达式并检查是否达成共识，重复约 N~5 次后取最频繁的答案，再代入原始数值得到最终结果。在 MultiArith 数据集上，该方法用 175B 参数的 GPT-3 将准确率从 Zero-shot-CoT 的 78.7% 提升到 92.5%，性能可与 540B 参数模型及 SOTA Few-shot-CoT 方法相当。对团队而言，其“多路径生成 + 程序化执行验证 + 共识统计”是提升 LLM 输出可靠性的可直接复用提示模式。

问题

LLM 在算术推理任务上表现有限、常给出错误答案；已有 CoT 提示方法对中间推理步骤的正确性没有任何校验，且模型不提供预测置信度，形成信任赤字，阻碍 LLM 的落地采用。

方法

MathPrompter 分四步：(I) 生成代数模板：将题目数值替换为变量得到 Qt 及 key-value 映射；(II) Math-prompts：用不同提示（如 'Write a mathematical equation'、'Write a Python function'）让 LLM 生成多条关于变量的解析解；(III) 计算验证：用 Python 的 eval() 对多组随机变量赋值执行这些表达式，比较输出是否一致；(IV) 统计显著性：重复 (II)(III) 约 N~5 次，取最频繁的答案作为共识结果，无共识则重试，最后将原始数值代入得到最终答案。整个过程基于 Zero-shot-CoT，无需 few-shot 示例。

关键结果

在 MultiArith 数据集上，使用 175B 参数的 GPT-3 (DaVinci) 将准确率从 SOTA Zero-shot-CoT 的 78.7% 提升至 92.5%

同规模基线对比：Zero-shot (175B) 准确率 17.7%，Zero-shot-CoT (175B) 为 78.7%，MathPrompter 达 92.5%

论文强调其性能可与 540B 参数模型以及 SOTA Few-shot-CoT 方法相当（Table 1）

共识机制要求多条解析解在 N~5 次随机变量取值上一致才输出最终答案，无共识时重复生成步骤

创新点

与已有 CoT 提示方法（尤其是 Kojima et al. 的 'Let's think step-by-step' Zero-shot-CoT）的关键区别：(1) 不让 LLM 直接逐步做算术，而是生成代数表达式/Python 函数等解析解，把计算交给确定性执行（eval()），从而对中间步骤形成校验；(2) 用多条不同路径的解在随机变量赋值上做共识，作为输出可靠性的代理信号；(3) 明确针对“LLM 不报告置信度”的信任问题设计。
