BeSafe-Bench: Unveiling Behavioral Safety Risks of Situated Agents in Functional Environments

BeSafe-Bench：揭示功能环境中情境化 Agent 的行为安全风险

下载原文 PDF

简介

现有 Agent 安全评测多局限于文本内容安全或单一领域，且常依赖 LLM 模拟的简化静态 API，与真实动态交互存在显著保真度差距。论文提出 BeSafe-Bench（BSB），在 Web、Mobile、Embodied VLM、Embodied VLA 四类功能环境（基于 WebArena、AndroidLab、OmniGibson、LIBERO 等真实模拟器）中构建 1312 个可执行任务，用 GPT-5 做安全导向指令增强、注入 9 类无意安全风险，并以规则校验 + LLM-as-a-judge 混合框架同时度量任务成功率 SR 与安全率 SafetyR。对 13 个主流 Agent 的评测显示：最好的 Agent 也仅 35.19% 的任务在完全遵守安全约束下完成，最高 41% 的案例是'完成任务但行为不安全'，且过程安全与终止安全常不一致。对团队而言，其风险分类体系、混合评测方法与'任务成功不等于安全'的结论可直接借鉴用于内部 Agent 的上线评测与把关。

问题

Agent 被赋予工具自主执行多步任务后，会产生大量无意的行为安全风险（如敏感数据泄露、数据丢失损坏、财产损失、恶意代码执行），其后果直接作用于数字与物理世界。但现有评测要么只评估生成内容安全，要么局限于单一领域（仅 Web 或仅具身），要么依赖 LLM 模拟的过于简化、静态的 API，与真实环境中 Agent 的动态多样交互存在显著保真度差距，导致评测结果与真实安全表现脱节；缺乏一个在功能环境中统一评测 Situated Agent 行为安全的综合基准。

方法

以 POMDP 形式化 Agent 与环境的交互；在四类功能环境中部署具备真实功能效果的工具与接口（Web 用 WebArena、Mobile 用 AndroidLab/Android 模拟器、具身规划用 IS-Bench+OmniGibson、具身操作用 VLA-Arena/LIBERO），每个模拟器封装在容器化环境中并为每次评测初始化新系统快照，任务与环境严格隔离。任务构造上，从环境原始可行任务出发，用 GPT-5 进行安全导向指令改写（GUI 场景）或风险因子注入（具身场景），围绕 9 类安全风险生成可执行的安全关键任务，并要求 LLM 合成作为评测 ground truth 的风险触发机制。评测采用混合框架：规则校验（精确/包含匹配、对象状态与空间条件）+ GPT-5 作为 LLM-as-a-judge 做语义模糊匹配，同时报告 SR（Success Rate）与 SafetyR（Safety Rate）及其联合分布（S-S 成功且安全 / F-U 失败且不安全），且只统计已执行动作造成的可观察环境影响。

关键结果

构建了跨 Web、Mobile、Embodied VLM、Embodied VLA 四域的 1312 个可执行任务，评测 13 个主流 LLM 驱动 Agent

表现最好的 Agent 也仅有 35.19% 的任务在未违反安全协议下完成；除 Mobile 外其他域的 Agent 安全覆盖率均低于 60%

最高 41% 的案例中 Agent 完成了分配任务但同时做出不安全行为

BSB-Mobile 上 GPT-4-1106-Preview 仅 25.58% SR，9B AutoGLM 仅 2.63% SR；因高风险动作很少被触发，安全覆盖率被人为抬高至 42.11%–79.17%

BSB-EmbodiedVLM 上 GPT-5 的 SR 最高但安全率相对较低，40.99% 的执行为'成功但不安全'；RoboBrain2.0 安全率更高且分布更均衡

具身规划中多个模型终止安全率高但过程安全率低，说明中间执行步骤频繁违反安全约束；引入安全约束后各模型任务完成率普遍下降，复合风险设置下所有模型安全率都很低

Web 环境中 Agent 在在线商店 CMS（涉及内部机密信息）上表现最差，在 Reddit 等社交论坛上易生成虚假或未授权内容

创新点

相对已有工作的区别：(1) 首次在统一基准中覆盖 Web、Mobile、Embodied VLM、Embodied VLA 四类情境，且全部使用具备真实功能效果的功能环境（WebArena、AndroidLab、OmniGibson、LIBERO 等），而非 Agent-SafetyBench、ToolEmu 等依赖 LLM 生成或预定义工具调用结果的方式；(2) 同时评测任务完成与行为安全并报告二者联合分布，而非只看其一；(3) 要求 Agent 与环境多轮动态交互，任务容器化隔离避免交叉干扰；(4) 提出规则校验 + LLM-as-a-judge 的混合评测方案与 9 类风险分类体系，并用 LLM 自动化增强出带风险触发机制标注的安全任务。
