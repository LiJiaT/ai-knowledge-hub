Let's Ask GNN: Empowering Large Language Model for Graph In-Context Learning

Let's Ask GNN：赋能 LLM 的图上 In-Context Learning

简介

论文解决 LLM 难以利用文本属性图（TAG）结构信息的问题：现有 k-hop 邻居文本序列化会遗漏远距离信号并引入噪声，而 GNN 编码为图 token 又存在与文本空间的模态错位。AskGNN 的做法是把图结构与监督信号转化为少量带标签的节点-文本对，由 GNN 驱动的 Structure-Enhanced Retriever 从全图检索 top-K 示例注入 few-shot 提示，并用 learning-to-retrieve 算法优化检索器——以逆困惑度定义 utility score 作为 LLM 反馈，与节点分类损失联合训练。在 ogbn-arxiv、ogbn-products、arxiv2023 三个数据集与七种 LLM 上，AskGNN 一致优于 Zero-shot、随机/kNN few-shot、文本序列化与指令微调基线；链接预测准确率 89.06%，条件文本生成 Rouge-L 22.15。论文还报告了逆缩放现象（7B→72B 性能先升后降）与示例净化带来的约 1% 提升。对团队的核心价值在于'用 LLM 反馈训练检索器来优化 ICL 上下文示例选择'这一可迁移的上下文工程方法。

问题

LLM 主要在非结构化文本上训练，缺乏解读文本属性图（TAG）中结构信息的能力。已有两条路线各有缺陷：k-hop 邻居文本序列化忽略 k-hop 之外的节点、引入噪声，在节点分类上不如 GNN；用 GNN 把图编码为紧凑图 token 则存在图结构与文本空间的模态错位。论文目标是把图结构信息与任务监督信号转化为少量文档节点-标签对作为 ICL 示例，在不微调 LLM 的前提下提升图任务表现。

方法

提出 AskGNN 框架：(1) Structure-Enhanced Retriever（SE-Retriever）以 GraphSAGE 为骨干，基于余弦相似度从全图标注节点中检索 top-K 个节点-标签对作为 ICL 示例，同时利用语义与结构信息；(2) Learning-to-Retrieve（L2R）：把示例组合评估分解为逐示例评估，用小模型（如 Qwen1.5-7B）计算基于逆困惑度的 utility score 对示例排序，作为训练信号优化 GNN 检索器，并缓存反馈以降低成本；(3) 联合损失 L_feedback 与加权 β 的节点分类损失 L_clf，兼顾示例选择与图结构学习；(4) 推理时用优化后的检索器选示例，套入提示模板让 LLM 完成节点分类、链接预测（重构为二分类问答）与条件文本生成等任务。

关键结果

在 ogbn-arxiv、ogbn-products、arxiv2023 上（低标注场景：1%、5%、10% 标注节点），AskGNN 在所有数据集与基线上一致取得最优节点分类准确率，覆盖七种 LLM

链接预测任务（重构为二分类问答）准确率 89.06%，超过 GCN 与指令微调模型

条件文本生成任务（给定节点文本前 10% 生成其余 90%）Rouge-L 达 22.15，超过 few-shot 与指令微调基线

ICL 示例净化：LLM-Selection 使 ogbn-arxiv 准确率从 69.02% 提升至 71.10%（约 +1%）；Minority-Class-Removal 影响在 ±0.1% 内

反馈超参 K 的权衡：K=2/20/200 准确率分别为 79.08%/82.54%/83.09%，K=200 成本约为 K=20 的 10 倍，故默认取 K=20

发现逆缩放现象：Qwen1.5 从 7B 到 72B 性能先升后降，ogbn-product 上 72B 低于 32B

损失权重 β 分析：ogbn-arxiv 在 β≈0.2、ogbn-products 在 β=0.3 达到峰值

Majority Voting 一致低于 LLM 预测，说明 LLM 并非简单复制示例中的多数类

创新点

与 k-hop 文本序列化（只覆盖局部邻域、有噪声）和 GNN-to-token 图投影（模态错位）不同，AskGNN 用 GNN 检索器在全图范围挑选 ICL 示例，把结构信息转化为纯文本的节点-标签对，绕开非文本 token 的语义鸿沟；并引入基于 LLM 反馈（逆困惑度 utility score）的 learning-to-retrieve 优化检索器，区别于此前仅按文本相似度（k-NN）或随机采样选示例的方式。
