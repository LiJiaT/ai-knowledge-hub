When Users Change Their Mind: Evaluating Interruptible Agents in Long-Horizon Web Navigation

当用户改变主意：评测长程 Web 导航中的可打断 Agent

下载原文 PDF

简介

论文针对现有 Agent 基准普遍假设任务执行不被打断、而真实用户常在任务中途追加、修改或撤回需求的问题，首次系统研究长程、有环境状态约束的 Web 导航中的可打断 Agent。作者形式化 Addition/Revision/Retraction 三类打断，基于 WebArena-Lite 构建 InterruptBench，用强 LLM 在语义一致、必要性与真实性约束下合成打断消息，并通过轨迹回放把打断注入到基线轨迹的固定相对进度处，形成可配对比较的无打断基线。在 WebAgent-R1 框架下评测 6 个主流模型发现：强模型也常沿用过期假设、未能把环境状态与新意图对齐；适应成本主要由 token 而非动作数驱动；多次打断总体提升成功率但增益不均且偶有回退。其评测方法学对团队构建人机协作 Agent 的可靠性评测有直接借鉴价值。

问题

现有基准大多假设 Agent 执行不被打断，或仅在短程、无环境约束的纯语言任务中研究打断；论文要解决如何系统评测 LLM Agent 在长程、动作会产生持久状态变化的 Web 导航任务中，处理任务中途用户意图变更（追加、修改、撤回需求）的有效性与效率。

方法

提出 InterruptBench：基于 WebArena-Lite 的 165 个人工验证任务（覆盖 Reddit、GitLab、CMS、Map、OneStopShop 五个域），用 Claude-Opus-4.5 在三条严格约束（合成查询加打断消息与原意图语义一致且 ground truth 不变、每条打断消息必不可少、语气自然真实）下合成三类打断场景并经作者人工审核；设计轨迹回放式打断模拟（先生成完整轨迹，再按相对进度默认 60% 处注入打断并继续执行），支持单轮与多轮（n=1,2,3，类型随机组合）打断；在 WebAgent-R1 框架下统一评测 6 个 LLM backbone，指标包括 Success Rate（String Match/URL Match/Program Execution）、打断后预算受限成功率曲线 SR(k)、相对无打断基线的 token/动作开销差，以及配对结果四象限（S/S、S/F、F/S、F/F）分析。

关键结果

打断后成功率随动作预算 k 快速上升并在 k≈10 后趋于平台；Addition 场景 k=30 时 Opus 约 55%、Sonnet 约 44%、Haiku 约 38%，开源权重模型更低（Qwen 约 26%、DeepSeek 30%、Mistral 23%）

Revision 场景中多数模型的无打断基线成功率接近 0，成功几乎完全依赖正确整合修改信息；Opus 在 k≈15 时超过 50%

适应成本主要由 token 而非动作数驱动：Addition 场景平均动作开销仅 -0.99（Opus）到 +0.82（Sonnet），而平均 token 开销从 +37.6（Qwen）、+88.5（Mistral）到 +670.9（Sonnet）、+1699.1（Haiku）

双失败（F/F）象限开销最高：Haiku +2624 tokens、Sonnet +1128 tokens、Opus +351 tokens；打断导致原本成功任务失败（S/F）的情况罕见（各模型 1-5 例）但代价高（如 Sonnet +21.75 动作、+8584 tokens）

F/S（基线失败、打断后成功）恢复能力差异明显：Opus 70 例、Sonnet 55 例，DeepSeek 35、Qwen 32、Mistral 27；Opus 恢复时开销近零或为负（-2.21 动作、-92.7 tokens），Haiku 则需 +6.67 动作、+1808 tokens

多次打断总体提升成功率：Opus 在 n=3 时达 41.82%，Sonnet 在 n=1 到 n=2 的边际增益超 18 个百分点，三个 Claude 模型从 n=1 到 n=3 成功率约翻倍；DeepSeek-V3.1 在 n=3 出现回退

打断位置影响呈规模相关：Claude-Opus-4.5 在较晚打断位置表现最佳，而 Haiku、DeepSeek-V3.1 在早期打断时最佳、打断延迟后退化

Retraction 场景所有模型平均动作数下降（-1.72 到 -8.13），多数模型 token 也下降（Opus 约 -1061、DeepSeek 约 -330），仅 Haiku 略增（+8.8）

创新点

首个在长程、环境有持久状态变化的 Web 导航任务中系统研究可打断 Agent 的工作：区别于假设无打断执行的长程基准，以及仅覆盖短程、纯语言、单轮打断的已有打断研究，本文形式化三类打断、以严格语义约束合成数据、用轨迹回放实现进度感知的打断注入，并提出 SR(k) 曲线与配对四象限方法，把成功率与适应成本解耦分析。
