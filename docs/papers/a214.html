Granite-Function Calling Model: Introducing Function Calling Abilities via Multi-task Learning of Granular Tasks

Granite-Function Calling Model：通过细粒度任务的多任务学习引入函数调用能力

简介

论文针对开源 LLM 在函数调用能力上落后于 GPT、Claude、Gemini 等专有模型的问题，指出已有微调模型在域外泛化、细粒度子任务处理和开放性三方面不足。方法上，IBM 以 GRANITE-20B-CODE-INSTRUCT 为基座，把函数调用拆解为嵌套调用、函数链、并行调用、函数名检测、参数-值对检测、Next-Best Function 与 Response Generation 七个细粒度任务，将 API-BLEND 与 Glaive-V2 数据统一为 JSON 格式，按加权配比构造 142K 样本做 QLoRA 多任务指令微调。结果显示，GRANITE-20B-FUNCTIONCALLING 在 BFCL 总体准确率排名第四、为开源许可模型中最佳，域外函数名检测 F1 比次优模型高 8%，幻觉率低于 0.1，以 20B 参数比肩 70B 模型。对团队而言，其价值主要在函数调用任务分类学、评测方法与一个 Apache 2.0 可自托管的工具调用模型选项，而非训练方法本身。

问题

开源 LLM 缺乏与 GPT、Claude、Gemini 等专有模型相当的函数调用能力；且现有函数调用微调模型（如 ToolLLM、ToolAlpaca、Gorilla）存在三方面不足：对域外数据集泛化差、无法独立处理函数名检测/槽位填充/调用序列等细粒度子任务、最佳模型闭源或依赖 OpenAI 模型生成训练数据。

方法

以 GRANITE-20B-CODE-INSTRUCT 为基座做指令微调：将函数调用拆为高难度任务（Nested Function Calling、Function Chaining、Parallel Functions）与低难度任务（Function Name Detection、Parameter-Value Pair Detection、Next-Best Function）两类共六个子任务，外加 Response Generation 共七个任务；把 API-BLEND（SeqSGD/SeqSNIPS/SeqTopV2/SeqATIS/SeqMultiWOZ）与 Glaive-V2 统一为 JSON 函数/调用表示，同一份数据配不同任务指令复用于多个任务，按加权配置生成 142K 训练混合；采用 QLoRA（rank 8、alpha 32、dropout 0.1、lr 5e-5）在单节点 8 张 A100_80GB 上训练 3 个 epoch。

关键结果

BFCL 总体准确率在 Top 15 模型中排名第四（截至 2024/06/25），为开源许可模型中最佳

函数名检测：在 ToolLLM（G1/G2/G3）与 RestGPT 上 F1 比次优函数调用模型高 8%，LCS 高 7%，Exact Match 高 11%

全函数调用（API-Bank、ToolBench、ToolAlpaca 域外零样本）：平均函数名 F1 为 0.87，以 0.01 之差次于 Cohere Command-R（35B）的 0.88；参数预测平均 F1 论文称落后最佳模型 0.03

在域外函数名检测的平均 F1 与幻觉率对比中性能最高，且幻觉率低于 0.1

Response Generation（API-Bank）：BertScore/Rouge-L/BLEU 三项均仅次于 Meta-Llama-3-70B-Instruct，差距在 1-5% 之间

以 20B 参数在多项任务上与 70B 的 Meta-Llama-3-70B-Instruct 相当或更好

创新点

与以往把函数调用当作单一任务微调的工作不同，本文将函数调用显式拆解为高低两层共七个细粒度子任务并做多任务学习，同一份数据以不同指令复用于多个任务；训练数据不依赖 GPT 等专有模型生成（基于许可合规的 API-BLEND/Glaive-V2），以 Apache 2.0 开源，并重点论证域外泛化能力与低幻觉率。
