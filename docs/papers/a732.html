ICL-D3IE: In-Context Learning with Diverse Demonstrations Updating for Document Information Extraction

ICL-D3IE：基于多样化示例更新的 In-Context Learning 文档信息抽取框架

简介

论文研究如何让 GPT-3/ChatGPT 在不做任何微调的情况下，通过 in-context learning 完成视觉富文档（表单、收据等）的信息抽取（DIE），需克服 LLM 无法直接处理图像、缺乏版面知识的模态鸿沟与任务鸿沟。方法上提出 ICL-D3IE 框架：先用 SentenceBERT 检索与测试文档最相似的训练文档，再从中构建三类示例——由预测 F1 最低困难片段构成并迭代更新的 hard demonstrations、描述文本位置关系的 layout-aware demonstrations、规范输出格式的 formatting demonstrations，并辅以 label mapping 将非自然标签转为自然语言描述。推理时用更新后的多样化示例指导 LLM 输出实体标注。关键结论：在 FUNSD/SROIE 上免训练即超过全量微调的 LayoutLMv3 等 VDU 模型（SROIE 97.88%），OOD 场景鲁棒性显著更强，且性能对示例数量与排列顺序高度敏感。

问题

如何让 GPT-3/ChatGPT 这类 LLM 在不做任何微调的前提下，通过 in-context learning 完成视觉富文档（表单、收据等）的信息抽取（实体标注）。核心难点有二：模态鸿沟（LLM 无法直接处理文档图像）与任务鸿沟（LLM 缺乏对版面 layout 信息的训练）；同时标准 ICL 直接拼接 OCR 文本作示例的做法忽略了文本间位置关系，且对示例选择非常敏感。

方法

提出 ICL-D3IE 框架，按三条准则构建多样化示例：(i) 示例应惠及所有测试文档、 包含版面信息、 输出格式易于抽取。流程分四步：1) 用 OCR 将文档转为文本+边界框，用 XYCut 算法确定阅读顺序，用 SentenceBERT 编码并按余弦相似度为每个测试文档检索最相似的训练文档；2) 构建三类示例：对检索文档做 zero-shot 推理、取 entity-level F1 最低的困难片段作为 hard demonstrations；用提示词让 GPT-3 生成区域文本位置关系描述作为 layout-aware demonstrations；随机选片段配标准答案作为 formatting demonstrations；并在上下文前部加入 label mapping，把非自然标签（如 'total. cash price'）映射为自然语言描述；3) 用当前多样化示例在训练文档上迭代推理，按 F1 挑最低分片段追加进 hard demonstrations（约 20 轮迭代更优）；4) 用更新后的示例对测试文档推理并抽取答案。实验用 text-davinci-003 与 gpt-3.5-turbo，temperature 设为 0，每类示例各 4 条。

关键结果

ID 设定下，ICL-D3IE (Davinci-003) 仅用少量示例、无需任何训练，在 FUNSD 达 90.32%、SROIE 达 97.88%，创造新 SOTA，超过全量微调的 LayoutLMv3 base（SROIE 上 96.89%）；在 CORD 上与 SOTA 差距在 3% 以内

相比 Standard ICL，ICL-D3IE (Davinci-003) 在 FUNSD 上提升 18.8 F1；CORD few-shot 设定下 VDU 平均性能翻倍以上

OOD 设定（用 TextAttack 生成形近替换/删字符的 OCR 错误样本）下，ICL-D3IE 在全部三个数据集上显著优于之前的预训练微调方法

消融实验：移除任一组件均降低性能，移除 hard demonstrations 影响最大；移除 layout-aware demonstrations 在 CORD 上掉约 10 F1；移除 label mapping 在 CORD 上显著下降

示例顺序高度敏感：M-H-L-F 排序在三个数据集上一致优于 M-L-H-F

示例数量从 1 增至 12 性能持续提升，ICL-D3IE (Davinci-003/ChatGPT) 在所有数量下均大幅超过 few-shot 微调的 LayoutLMv3

hard demonstrations 迭代更新 20 次后性能更佳；ChatGPT 版本因生成灵活、答案难抽取而弱于 Davinci-003（CORD 上 87.13 vs 94.12 F1，SROIE 上 92.63 vs 97.88 F1）

创新点

据作者所述，这是首个探索用 LLM in-context learning 解决 VRD 文档信息抽取的工作。区别于标准 ICL 只拼接任务示例，它按三条准则组合多类示例（hard/layout-aware/formatting + label mapping），用 SentenceBERT 最近邻检索选取示例文档，并通过'在训练数据上推理—按 F1 挑最难片段—迭代追加'的反馈闭环自动更新 hard demonstrations，使示例惠及所有测试样本。
