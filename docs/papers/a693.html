Think Outside the Code: Brainstorming Boosts Large Language Models in Code Generation

Think Outside the Code：Brainstorming 提升 LLM 的代码生成能力

简介

LLM 在简单编程任务上表现出色，但面对竞赛级复杂问题直接生成代码通过率很低，而 AlphaCode 等依赖 RL 微调加大规模采样过滤的方案成本过高、且缺乏高层思考。论文提出 BRAINSTORM 框架，把代码生成拆成三步：先用 4 类指令让 LLM 零样本发散生成多样化的解题思路，再用基于 XLNet 微调的 thoughts ranker 选出最可能导向正确解的思路，最后把问题与选中思路拼进零样本 prompt 让 LLM 实现代码。在 CodeContests 上 ChatGPT 的 pass@1 从 4.52% 升至 7.01%（相对提升超 50%），APPS 竞赛级任务相对提升超 30%，LeetCode 真实比赛达到接近人类程序员水平。对团队的核心价值在于'先发散思路、再择优实现'的提示模式，以及'简单任务过度思考反而有害'这一边界结论。

问题

LLM 在简单编程任务上表现好，但在竞赛级等复杂任务上直接生成代码通过率急剧下降；现有最强方案（AlphaCode、CodeRL）依赖 RL 微调与大规模采样、过滤、聚类，真实场景中成本不可承受，且把生成拆成 token 级动作序列、缺少高层思考，限制了 LLM 的推理能力发挥。

方法

BRAINSTORM 三步框架，全程 zero-shot、无需 few-shot 示例：(1) Brainstorming：设计 m=4 类指令（要求只给思路不给代码、分析输入范围与时间复杂度等），让 LLM 对同一问题发散生成多样化的'解题蓝图'式 thoughts，提高采样到正确思路的概率；(2) Thoughts Selection：训练基于 XLNet（利用其 segment recurrence 机制处理长序列）的 thoughts ranker，以代码执行测试用例得到的正/负标签做加权交叉熵训练，推理时选正概率最高的思路；(3) Code Generation：将问题描述与选中思路放入零样本 prompt 让 LLM 生成 Python 代码，在沙箱中编译执行判题。

关键结果

CodeContests 测试集（165 题）：ChatGPT 的 pass@1 从 4.52% 提升到 7.01%，相对提升超过 50%，pass@k 与 pass@any 均取得当时 SOTA

CodeContests 验证集（117 题）：pass@1 相对提升约 30%

APPS 基准（5000 题）：竞赛级任务在 k=1 和 k=100 时相对最优基线取得超过 30% 的相对提升

LeetCode Contests（100 题，官方在线判题）：BRAINSTORM 使 ChatGPT 达到与人类程序员相当的水平

Ranker 训练数据规模：CodeContests 构造 8k 正例/33k 负例，APPS 构造 17k 正例/64k 负例；训练在 8 张 A100-80GB 上 50 小时内完成

负面结果：对 introductory/interview 级简单任务，BRAINSTORM 反而降低 pass@1 与 pass@5

创新点

与 AlphaCode/CodeRL 等依赖 RL 微调+大规模采样过滤的路线不同，BRAINSTORM 用零样本提示先在抽象层面头脑风暴多样化解题思路、再逐步实现代码，无需 few-shot 示例与海量采样；与 CoT 单链推理相比，通过多套指令发散生成 thoughts 提高命中正确思路的概率；与 CodeT/CodeRanker 对代码候选做排序不同，本文排序对象是解题思路本身，且用训练的神经 ranker 而非 LLM 自评完成选择。
