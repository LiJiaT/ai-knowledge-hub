Are Large Language Models In-Context Graph Learners?

大语言模型是 In-Context 图学习器吗？

higharXivRAG与检索提示技术上下文窗口其他基于arXiv版本
下载原文 PDF

简介

论文研究 LLM 能否在不微调的前提下，仅凭 in-context 能力完成图结构数据学习（以 text-attributed graph 上的节点分类为代表）。实证发现 LLAMA-3.1-8B-INSTRUCT 与 DEEPSEEK-V3 的 zero-shot 表现显著落后于监督 GNN，且加入 few-shot 示例反而可能进一步降低性能；作者提出 GNN 的 message-passing 可视为对每个节点递归执行的 RAG 过程，据此设计 QUERYRAG、LABELRAG、FEWSHOTRAG 三个框架，把节点一跳邻域的文本属性与/或标签作为'天然检索到的上下文'注入提示，无需外部语料与任何参数更新。在 8 个数据集上，所提框架显著优于 zero-shot、few-shot 与标准 RAG，LABELRAG/FEWSHOTRAG 超过监督 MLP，部分场景接近 GNN 或匹配专用 graph LLM；消融显示图结构检索优于文本相似度检索，检索邻居超过约 3 个后收益递减。对团队的核心价值在于为'检索什么、检索多少、如何组织上下文'提供了可迁移的实证依据。

问题

LLM 在语言、图像等非结构化输入上展现出强大的 in-context 推理能力，但对图等结构化数据缺乏对非欧几里得结构的理解，不微调时性能显著落后于 GNN。论文要回答：LLM 究竟是不是有效的 in-context graph learner？并进一步探究：能否通过更合理的上下文组织（而非微调），让不可修改或只能通过 API 访问的预训练 LLM 在图任务上逼近专门模型。

方法

关键洞察是把图学习概念化为 RAG 过程：节点/边作为 query，图本身即被检索的上下文；GNN 的 message-passing 等价于对每个节点沿图上下文递归执行 RAG 步骤，且 RAG 与 GNN 在 retrieval、augmentation、generation 三步上形式同构。据此提出三个 graph-guided RAG 框架：QUERYRAG 用一跳邻居节点的文本属性作为检索上下文；LABELRAG 借鉴 label propagation，把邻居节点的标签一并纳入提示；FEWSHOTRAG 将邻居的 (query, label) 对组合成 few-shot 示例。三者直接以图拓扑为检索源，不依赖外部语料库与相似度检索管线，且完全不对 LLM 做微调。

关键结果

zero-shot 下 LLAMA-3.1-8B-INSTRUCT 与 DEEPSEEK-V3 在 Cora/Pubmed 节点分类上显著差于监督 GCN/MLP；one-shot 与 few-shot 下性能进一步下降（Cora 上最明显），即 few-shot 示例可能带来负收益

标准 RAG 使两个 LLM 准确率提升并超过监督 MLP，但仍显著落后于监督 GNN

在 8 个 text-attributed graph 数据集上，LABELRAG 与 FEWSHOTRAG 显著优于 zero-shot/few-shot/标准 RAG，超过监督 MLP，部分情况下匹配甚至超过监督式 graph LLM，与 GNN 差距很小（如 History 数据集上 GNN 仅略优）

检索器消融：graph-based 检索在三个框架上一致优于 text-based（BERT 稠密检索）与 random-based 检索

检索邻居数 K 增加时性能先升，超过约 3 个邻居后趋于平台甚至略降

跨 backbone 实验（QWEN2.5-7B-INSTRUCT、GEMMA-2-9B、PHI-3.5-MINI-INSTRUCT、MISTRAL-7B-INSTRUCT-V0.3）中 FEWSHOTRAG 在全部模型上取得最高准确率

创新点

相对已有工作的区别：(1) 系统建立 message-passing GNN 与 RAG 的形式化对应，论文指出此前'little work has explored the fundamental connections between them'；(2) 与标准 RAG 依赖外部语料和相似度检索不同，三个框架把图拓扑本身当作天然检索源，无需额外检索工程；(3) 与需要微调的 graph LLM（GLEM、TAPE、LLaGA 等）不同，方法纯靠提示内上下文组织，适用于只能 API 访问的冻结模型。
