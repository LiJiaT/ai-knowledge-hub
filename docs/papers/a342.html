SWE-CI: Evaluating Agent Capabilities in Maintaining Codebases via Continuous Integration

SWE-CI：基于 Continuous Integration 评测 Agent 维护代码库的能力

简介

现有代码基准（HumanEval、SWE-bench、Terminal-bench 等）普遍采用一次性快照协议，只测功能正确性，无法区分'脆弱的硬编码修复'与'干净可扩展的实现'。SWE-CI 提出首个基于 Continuous Integration 循环的仓库级基准：从真实 GitHub 仓库构建 100 个 base/oracle commit 对（平均间隔 233 天、71 次连续提交），采用 Architect-Programmer 双 Agent 协议，在最多 20 轮'生成增量需求文档-改码-跑测试'的循环中演进代码库，并以未来加权的 EvoScore 与零回归率量化可维护性。对 8 家厂商 20 个模型、超 100 亿 token 的评测发现：多数模型零回归率低于 0.25，仅两个 Claude Opus 模型超过 0.5；15/20 模型的 Pylint 分数胜过人类代码，但 20/20 的 MI 分数全部落后，即 LLM 代码'表面整洁但内在复杂'。对团队而言，它提供了评测代码 Agent 长期可靠性的方法模板，其双 Agent 分工、XML 需求契约与提示约束设计均可直接借鉴。

问题

现有代码评测基准几乎都采用快照式（snapshot-style）一次性协议：Agent 接收单个完整需求并一次性给出解法，只衡量功能正确性。在此范式下，硬编码脆弱修复的 Agent 与写出干净可扩展代码的 Agent 可能通过同一测试套件，可维护性差异不可见；而真实软件的成功依赖长期维护（维护占软件生命周期成本的 60%-80%）。论文要解决的问题是：如何评测 Agent 在长期代码演进中持续维持代码质量（可维护性与回归控制）的能力。

方法

提出演进式（evolution-based）评测范式：从 GitHub Python 仓库中筛选 base/oracle commit 对（4,923 个仓库 → 8,311 候选对 → 环境构建与自修复后 1,458 对 → 过滤后 137 → 最终 100 个任务），每个任务要求 Agent 从 base commit 出发迭代演进，最终通过 oracle commit 关联的全部测试。采用 Architect-Programmer 双 Agent 协议复现 CI 循环：Architect 基于测试差距按 Summarize-Locate-Design 三步生成不超过 5 条的高层增量需求文档（XML 格式，含 location/description/contract/acceptance 字段），Programmer 按 Comprehend-Plan-Code 三步实现，测试由外部系统执行，最多 20 轮迭代。提出归一化变化量（normalized change，a(c)∈[-1,1]，非对称归一化统一表达进步与回归）与未来加权平均的 EvoScore（γ≥1，越靠后的迭代权重越大）作为可维护性代理指标。harness 使用 iFlow CLI，测试框架为 pytest 与 pytest-json-report。

关键结果

构建 100 个任务（来自 68 个仓库），每个 base/oracle 对平均间隔 233 天、71 次连续提交，且至少 500 行源代码改动（不含测试文件）

共评测 8 家厂商的 20 个模型，总 token 消耗超过 100 亿；Claude Opus 系列全程领先，GLM-5 表现突出

多数模型零回归率（zero-regression rate）低于 0.25，仅两个 Claude-opus 模型超过 0.5

15/20 个模型在 Pylint 分数上胜过人类 oracle 代码，但 20/20 在 MI（可维护性指数）分数上全部落后于人类代码

所有 20 个模型生成的补丁改动行数均少于人类，但以更低的可维护性为代价

多数模型 solved rate 低于 50%；12/20 模型的回归率与迭代轮数呈正相关，11/20 的回归幅度与迭代轮数呈负相关

所有厂商模型的最大相对提升集中在第 1-4 轮迭代，之后收益明显递减；弱模型耗尽 20 轮预算仍无法完成剩余需求

创新点

首个基于 Continuous Integration 循环的仓库级基准，将代码生成评测范式从静态、短期功能正确性转向动态、长期可维护性：以'未来修改上的功能正确性'操作化定义可维护性（依据 ISO/IEC 25010），提出归一化变化量与未来加权的 EvoScore 指标，并设计 Architect-Programmer 双 Agent 协议。与 InterCode、Commit0、SWEBench-CL、SWE-EVO 等长程/演进感知基准不同，SWE-CI 显式建模迭代开发周期中代码质量的累积退化——这是其设计的核心关切。
