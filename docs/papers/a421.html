Efficient Prompting via Dynamic In-Context Learning

基于动态 In-Context Learning 的高效提示方法（DYNAICL）

简介

论文针对 in-context learning 的普遍做法——给所有输入统一添加固定数量的示例——导致的 token 浪费与性能次优问题，提出 DYNAICL 框架。方法上训练一个小型 meta controller（用 FLAN-T5 实例化，小于 1B 参数）：第一阶段通过数据合成算法在 FLAN 指令数据集上找到每个输入所需的最少示例数并用监督学习训练，第二阶段用基于性能-效率权衡奖励的强化学习微调；推理时按 controller 预测与 token 预算动态分配示例数量。实验以 ChatGPT 为通用模型，在 8 个任务上相比均匀分配基线，固定预算下平均绝对性能提升 2.6%，达到同等性能最多节省 46% token（平均 108 token 即可匹敌基线 200 token 的效果）。meta controller 还能泛化到未见任务（含生成式 QA）与未见模型（LLAMA-65B），且自身计算与延迟开销可忽略。对团队而言，这是“按输入难度动态组织上下文与示例”的直接参考，可同时降低 API 成本并提升产出质量。

问题

In-context learning 虽能帮助通用模型更好地理解任务，但会把 prompt 显著拉长，占用宝贵的上下文窗口空间并推高计算成本。现有做法对所有输入统一分配固定数量的示例，既浪费 token，论文的初步研究还发现给简单样本添加过多示例偶尔会“混淆”模型、把原本正确的预测变错。论文要解决的问题是：在无法访问模型参数的黑盒（闭源）通用模型上，如何根据输入复杂度与计算预算动态分配 in-context 示例数量，以获得更好的性能-效率权衡。

方法

提出 DYNAICL：训练一个 meta controller（可用 FLAN-T5-base/large 等小型指令微调模型实例化），输入任务指令与输入，输出适合该输入的示例数量 k。训练分两阶段：第一阶段提出数据合成算法，对每个 prompt 枚举不同示例数量，找到使通用模型期望准确率超过手工阈值 t 的最小示例数 k*，在 FLAN 指令数据集混合上用最大似然估计训练；第二阶段用强化学习（policy gradient）微调，奖励定义为期望性能与效率（示例数 k）的线性插值，权重 α 控制偏向性能或效率。推理时按给定 token 预算对预测值做归一化调整（引入 token 节省比例 β）后动态分配示例。方法只操作输入侧，与模型架构/参数解耦，因此适用于 ChatGPT 等闭源模型。

关键结果

相比均匀分配基线，在每样本预算为 5/10 个示例时，8 个 seen 任务上平均绝对性能分别提升 2.6% 和 1.4%

达到固定目标性能时最多节省 46% token；平均只需 108 token 即可匹敌均匀基线平均 200 token 的性能

meta controller 泛化到 6 个未见任务（包括生成式 QA 数据集 Natural Questions、Web Questions），在所有任务上持续优于基线

用 ChatGPT 训练的 meta controller 迁移到未见模型 LLAMA-65B 上仍能节省大量 token

meta controller 开销可忽略：T5-large 级别 controller 对 50 token 样本的计算成本低于输入从 200 token 减到 199 token 所增加计算量的 0.1%；延迟开销仅占 GPT-3.5-turbo API 调用延迟的 0.1%-0.2%，而减少一个示例约带来 10% 提速

消融实验：两个训练阶段均有贡献且第一阶段更重要；更小的 meta controller 或更少训练任务仍具竞争力

创新点

与以往需要访问模型参数的效率优化手段（知识蒸馏、剪枝、量化、动态输入缩减、gist token 压缩等）不同，DYNAICL 只操作输入侧，面向黑盒闭源通用模型；与 input-adaptive computation 类工作调整模型复杂度不同，它动态调整的是输入（示例数量）的大小。论文称这是首批无需访问模型参数即可加速黑盒通用模型的方法之一，并指出该方向此前没有先验工作，因此只与均匀分配和随机分配两个朴素基线比较。
