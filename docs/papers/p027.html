简介

论文针对现有异构加速器（HA）设计框架普遍以吞吐率或 QoS 为优化目标、缺乏安全关键实时系统所需的可预测执行硬件支持、实时感知 DSE 与严格可调度性分析的问题，提出实时优先的设计框架 PHAROS。方法上，PHAROS 采用多加速器流水线拓扑，片上 scheduler 支持 FIFO 与 EDF 调度及基于 tiling 的层内抢占，并将抢占开销以保守上界并入 WCET；依据实时理论以每个加速器利用率 ≤1 作为 SRT 可调度判据，以最大利用率为目标构建三阶段 DSE，并用 beam search 启发式控制搜索复杂度。实验基于 Versal VCK5000 平台与 PointNet、Point Transformer 等负载：PHAROS 找到 49 个可调度 taskset，较吞吐率导向 DSE 提升 3.76×，可行解多 1.44×–2.28×，最大利用率最多降低 6.2%。该工作属于实时 DNN 加速器设计领域，与团队内存/互连 IP 的架构、RTL 与验证技术栈基本无交集，仅 DSE 建模方法论有微弱参考价值。

问题

现有空间分区异构加速器（HA）设计框架主要优化吞吐率或 QoS 指标，忽视安全关键实时系统需求：可预测执行的硬件支持、实时感知的设计空间探索（DSE）与严格可调度性分析；错过 deadline 会直接违反系统级安全保证（HRT）或造成严重退化（SRT）。现有 QoS 导向框架（如 DREAM、CDMSA 通过丢任务换 QoS）不满足 SRT 对每个作业响应时间有界的要求，而 MESC、ART、DERCA 等实时框架受限于单加速器架构、硬件定制不足，无法覆盖周期更小的 taskset。

方法

提出 PHAROS 框架：由多个独立 dataflow 加速器组成流水线拓扑（任务须在一个加速器上完成所有 segment 后才进入下一个，不允许回溯），每个加速器采用 output-stationary 数据流、tiling、double buffering 与专用 DMA 引擎经 AXI 访问片外 DDR；片上 scheduler 含静态配置表、动态进度表与 job pool，FIFO 用队列实现、EDF 用按 deadline 排序数组实现并支持抢占；利用 tiling 实现层内抢占（存回部分结果、记录循环迭代状态、恢复时重载 buffer），并将抢占开销以各环节取最大值的保守方式并入 WCET。基于实时理论 [5]，以每个加速器利用率 ≤1 作为 SRT 可调度充要判据，以 max(util) 为 DSE 目标，分三阶段搜索（片上资源划分、层到加速器的连续映射、A/B/C/X/Y/Z 参数），并提出引入 remain_acc 合成加速器评估剩余负载的 beam search 启发式以降低指数级搜索复杂度。

创新点

区别于三类已有工作：吞吐率/QoS 导向的 HA 框架（如 CHARM，不感知实时）、通过丢任务换 QoS 的框架（DREAM、CDMSA，直接违反 SRT 要求）、以及受限于单加速器架构的实时框架（MESC、ART、DERCA）。PHAROS 的主要区别在于将基于流水线拓扑约束的 SRT 可调度性理论嵌入多加速器 DSE：以 max(util) 取代吞吐率/延迟作为优化目标，硬件上同时支持 FIFO/EDF 双调度策略与层内抢占，并把抢占开销显式并入 WCET 与响应时间分析，从而对满足利用率约束的设计给出数学上的 deadline compliance 保证。

Abstract

空间分区的异构加速器（heterogeneous accelerators, HAs）凭借其性能与灵活性，在嵌入式系统中得到日益广泛的应用。然而，现有的大多数 HA 设计框架主要针对吞吐量或服务质量（quality-of-service, QoS）指标进行优化，往往忽视了安全关键实时需求，包括对可预测执行的硬件支持、实时感知的设计空间探索（design space exploration, DSE）以及严格的可调度性分析。在智能交通等安全关键应用中，这些需求至关重要，因为可调度性保证直接影响系统安全。为弥补这一空白，我们提出了 PHAROS，一个以实时为中心的 HA 设计框架。PHAROS 针对空间分区的 HA，在先入先出（first-in-first-out, FIFO）和最早截止期限优先（earliest-deadline-first, EDF）调度策略下引入了抢占机制与调度器设计。借助现代实时理论，我们进一步开发了一种面向软实时（soft real-time, SRT）可调度性的 DSE，其优化目标与约束条件均针对 SRT 可调度性量身定制。通过在多种应用上开展全面的建模、分析与评估，我们表明，与面向吞吐量的 DSE 基线相比，PHAROS 面向可调度性的 DSE 能够为更广泛的任务集发现更多可行配置，同时带来更优的实时性能。我们还为所支持的调度算法提供了响应时间分析。

1 Introduction

异构加速器（Heterogeneous Accelerators, HAs）因能够为不同工作负载在空间上划分计算资源，从而实现更高的性能与更优的能效，在嵌入式系统中日益流行 [1-4]。然而，现有大多数 HA 设计聚焦于吞吐量或 QoS 指标，忽视了实时安全关键系统的需求，而这类系统要求硬件行为可预测、面向实时的设计空间探索（Design Space Exploration, DSE）以及严格的可调度性分析。一旦错过截止期限，便可能直接违反系统级安全保证（硬实时，Hard Real-Time, HRT），或导致严重的性能退化（软实时，Soft Real-Time, SRT）。

2 Related Works

面向实时安全关键系统的硬件加速器：多项研究工作已在不同平台上对硬件加速器（HA）设计进行了探索[1, 3, 6-13]。然而，现有框架的加速器设计仍主要面向吞吐量或延迟，并且通常依赖缺乏抢占机制的静态或先进先出（FIFO）调度策略。因此，它们无法直接部署到软实时（SRT）安全关键系统中，因为在这类系统中，异构工作负载必须根据不同的重要性级别（即任务优先级）进行调度。

还有一些框架实现了抢占、截止期感知调度等与实时系统相关的特性[4, 1420]。这些框架主要针对 99% 延迟等服务质量（QoS）指标进行优化，这允许某些作业不产生响应。与这些指标不同，SRT 截止期合规要求每个作业都具有有限的响应时间。因此，这些框架同样无法部署到 SRT 安全关键系统上。DREAM [14] 和 CDMSA [16] 选择丢弃作业来为其他作业腾出空间。尽管 QoS 指标可能因此得到改善，但这直接违反了 SRT 要求。此外，这些框架并未从数学上检验系统能否确保截止期合规。

针对实时系统，已有一些框架被提出以满足截止期合规要求，并提供可调度性或响应时间分析。[21] 基于 Vitis-AI [22] 框架实现了一个非抢占的基于深度神经网络（DNN）的驾驶辅助系统。MESC [23]、ART [24, 25] 和 DERCA [26] 实现了抢占机制和最早截止期优先（EDF）调度。这些工作专为实时安全关键系统量身定制；然而，其性能受限于单加速器架构，因此硬件定制能力受限。因此，PHAROS 能够为周期更小的任务集确保 Shixin Ji, Jinming Zhuang, Sarah Schultz, Zhuoping Yang, Xingzhen Chen, Zheng Dong, Alex K. Jones, Yihui Ren, and Peipei Zhou 截止期合规，而这些框架则因硬件效率低下而无法做到。

用于指导加速器设计的实时理论：为确保满足截止时间，加速器设计必须与实时理论相结合，以分析可调度性或响应时间。对于单个加速器，[27] 在硬实时（HRT）场景下给出了最早的形式化表述，其中每个作业都被要求在其截止时间之前完成。[28] 分析了软实时（SRT）场景，其中作业仅被要求具有有限的响应时间。对于多个异构加速器系统，[29] 和 [30] 分别在 HRT 和 SRT 场景下提供了分析，且未对系统施加任何约束。然而，由于考虑了许多极端情况，这两项工作过于悲观，使得通过可调度性测试的候选设计在硬件上效率低下。[5] 通过约束加速器的拓扑结构，为 SRT 调度给出了更紧的界，即一个作业必须在一个加速器上完成其全部执行后才能转移到另一个加速器，且不允许回溯。

我们选择利用 [5] 来指导 PHAROS。我们将硬件抢占操作并入最坏情况执行时间（WCET）中，从而在全抢占场景下对系统建模，并围绕这些约束设计我们的设计空间探索（DSE）。我们承认这一现有理论限制了设计空间；尽管如此，它仍能覆盖空间加速器设计的很大一部分。我们将对更先进的实时理论和拓扑结构的探索留作未来工作。

3 PHAROS Hardware Architecture Design and Task Modeling

在本节中，我们介绍所提出的 PHAROS 硬件架构，包括数据流与控制流。随后，我们在全抢占场景下对整个系统进行形式化建模，并阐述我们针对抢占与任务模型的方法。

3.1 PHAROS Accelerator Design

PHAROS 采用了一种广泛使用的加速器模型，如图 2 所示，该模型由多个独立的数据流加速器组成。在每个加速器中，每个深度神经网络（DNN）层的执行都从片外 DDR 存储器加载数据开始，并以将结果存储到 DDR 结束。我们为每个加速器采用带分块（tiling）的输出固定（output-stationary）数据流，以减少片外存储器访问。我们对输入与输出片上缓冲器集合应用双缓冲（double buffering），使加载和存储与计算相重叠。

为了在单个加速器中处理具有各种形状的层，我们将每一层的配置存储在相应的片上调度器中，其中包括形状（例如矩阵乘法中的 M、K、N）和 DDR 基地址。DDR 存储器空间的划分在编译前确定。我们为不同的张量分配各自独立的存储器空间，以避免冲突。对于由相邻层产生并消费的中间数据，我们自动维护一个统一的缓冲空间，以避免重复的存储器消耗。我们设计了专用的直接存储器访问（DMA）引擎，用于向片外 DDR 存储器发出 AXI 事务，从而实现交错访问，使多个加速器能够共享可用带宽。

3.2 Control Flow and Scheduling Methods

为确保正确且高效的执行，调度机制对于确定每一层在每个加速器上的执行顺序以及跨加速器的数据同步至关重要。在 PHAROS 中，我们采用分散式控制流，由每个加速器独立进行调度。如图 2 所示，每个片上调度器拥有一个静态配置表、一个用于存储执行状态的动态进度表，以及一个用于存储可被调度的就绪作业的作业池。当采用先进先出（FIFO）调度时，作业池以队列形式实现。当采用最早截止期限优先（EDF）时，作业池以数组形式实现，并在调度前按截止期限排序。如果新作业的截止期限小于正在执行的作业，则会发生抢占。

调度器各表的最大容量在编译时固定。我们将进度表和作业池的最大条目数设置为任务集中的任务数量，因为当系统是软实时（SRT）可调度的且加速器处于链式拓扑时，每个任务在任一加速器上最多存在一个就绪作业。调度器的时间和资源开销很小，每个条目占用 < 25 字节的数据，数组的排序时间 < 1 µs。

PHAROS 通过由高层次综合（HLS）流实现的 FIFO 队列将不同加速器之间的作业池连接起来。对于第一个加速器，作业由外部设备释放，例如连接传感器的中央处理器（CPU）或输入/输出（IO）。每个加速器在完成某一作业上的段之后，会将该作业释放给后继加速器。这意味着对于一个作业，其在某个加速器上的段只有在以下情况下才会就绪：（1）该加速器是第一个加速器，或（2）所有前驱加速器均已完成执行，这与 guideline 理论 [5] 相兼容。

3.3 Task and Performance Modeling

3.4 Preemption Support & Overhead

The original real-time theory assumes a fully preemptive scenario with zero overhead, which is unrealistic due to the latency incurred by preemption. We explain the preemption mechanism in PHAROS and the corresponding modeling as follows.

As shown in Figure 3, PHAROS supports preemption within the execution of one layer by leveraging the tiled output-stationary dataflow. When a high-priority job arrives at the scheduler, the accelerator cannot run it immediately. Instead, the accelerator first completes the current tile of the low-priority job. Then it stores the partial results in the output buffer into the corresponding DDR address. The current execution status in terms of loop iteration numbers is recorded to the on-chip progress table within the scheduler. The accelerator then runs the high-priority job. When the low-priority job resumes, the scheduler reloads the input and output buffers according to the loop iteration and recovers execution.

4.2 Beam Search Heuristics

PHAROS 面临的一个重要挑战是求解庞大的设计空间：当向任务集（taskset）中添加更多任务，或使用包含更多层的更大规模应用时，设计空间会呈指数级增长。为了解决这些问题，我们提出了一种束搜索（beam search）启发式方法。

算法 1 和图 5 展示了束搜索的过程。其核心思想是：我们迭代地利用一部分资源和工作负载创建新的加速器，与此同时，未被分配的工作负载和资源构成一个合成加速器（记为 remain_acc），用于评估仍未被分配的工作负载的利用率。如算法 1 所示，每次迭代都从一个父设计点开始，该设计点已将部分资源（r）和层（l）分配给一系列加速器（accs）（第 5-6 行）。随后，我们搜索所有可能的资源和工作负载来创建一个新的加速器，并构建一个新的 remain_acc（第 7-10 行）。在搜索过程中，我们按比例分配各类资源。create_acc 步骤采用与图 4 中所讨论的相同的暴力搜索方法。只有在创建加速器之后才能获得其利用率，若其利用率 > 1，我们便对该子节点进行剪枝（第 11 行）。由于在创建新加速器时已遵循利用率和流水线约束，一旦 remain_acc 的利用率 ≤ 1，我们就可以将这个合成加速器转化为真实的加速器，从而得到一个可行解（第 13-14 行）。如果利用率超过 1，这并不表示失败；相反，该设计点同样会保留在子节点中，算法将在后续迭代中继续进行更进一步的划分（第 12 行）。

Across a broad range of experiments, we observe that most of the feasible design points and the design with the best maximum utilization are found when M ≤ 4. We use CHARM DSE as the throughput-guided baseline. To generate different tasksets with the same application combination, we set the period of each task via switching the P' / 𝑃 1 and P' / 𝑃 2 ratio; a larger ratio means a smaller period and heavier workload. For each DSE result, FIFO and EDF scheduling are used. (2) FIFO w/t polling, where for job segment 𝜏 𝑠 𝑖,𝑗 on 𝑎𝑐𝑐 𝑘 , it can be ready as long as its corresponding segment in the previous job, 𝜏 𝑠 𝑖,𝑗 - 1 , is finished.
