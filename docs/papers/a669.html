PiVe: Prompting with Iterative Verification Improving Graph-based Generative Capability of LLMs

PiVe：基于迭代验证的提示方法提升 LLM 的图结构生成能力

简介

LLM 因预训练语料以非结构化文本为主，在文本到图（T2G）等结构化生成任务上即使配合 few-shot 示例仍会漏三元组、产出错误。PiVe 框架训练一个小型 LM 充当验证器模块：对种子图做删三元组扰动自监督构造训练数据，使验证器能判断输出是否 Correct 并给出缺失三元组；随后将纠正指令拼回 prompt 迭代调用 LLM（Iterative Prompting），或只调用一次 LLM 后由验证器离线逐步修正（Iterative Offline Correction，每实例仅一次 API 调用、更省成本）。在 KELM-sub、WebNLG、GenWiki 三个数据集上平均提升 26%，人工评测中带 PiVe 的 ChatGPT 在 105 个样本中胜出 85 个（胜率超 80%），并明显优于依赖 LLM 自我反馈的 Self-Refine。验证器还可复用为数据增强工具，构建出 11 万对高质量平行文本-图数据集 GenWiki-HIQ。

问题

LLM 的预训练数据以非结构化文本为主，导致其在将文本组织成结构化机器可读格式（语义图/三元组）的任务上表现不佳；即使增加 few-shot 示例数量或更换提示风格，GPT-3.5 等模型生成的图仍含错误（尤其是三元组缺失），需要修正机制。论文聚焦如何提升黑盒 LLM 的 text-to-graph 生成质量。

方法

提出 PiVe 框架：从种子文本-图对出发，对图中三元组做删除扰动，自监督构造（文本, 扰动图, 纠正描述 IP）训练数据，训练小型 LM 验证器——用 T5-Large 按数据集分别全参微调（single verifier），或用 Flan-T5-XXL + LoRA + 8-bit 量化指令微调出跨数据集 unified verifier。推理时有两种模式：(1) Iterative Prompting——LLM 生成图后交给验证器检查，将预测的缺失三元组以纠正指令拼入新 prompt 再次调用 LLM，迭代至验证器输出 Correct 或达到最大 3 次迭代；(2) Iterative Offline Correction——只调用一次 LLM 获得初始图，后续验证与修正全部由小验证器离线逐步完成，成本更低但效果略弱。验证器还可作为数据增强工具迭代补全自动构造数据集中的图，生成 GenWiki-HIQ。

关键结果

在 KELM-sub、WebNLG、GenWiki 三个数据集上，PiVe 通过迭代纠正指导使 LLM 输出质量平均提升 26%

人工评测（105 个样本、3 名标注者、多数投票）：带 PiVe 的 ChatGPT 胜出 85 个样本，总胜率超过 80%

验证器训练成本：single verifier 约 6 小时、unified verifier 约 40 小时（单张 A40 48GB GPU）；推理时单实例验证耗时 single verifier 0.15s、unified verifier 3.5s

Self-Refine 在 KELM-sub 上无法提供有效反馈，随迭代性能下降，与 PiVe 差距明显

GPT-4 在 T2G 任务上远好于 ChatGPT；PiVe 在两种模型、不同 prompt 策略与 shot 数（k=6/8/10）下均带来一致提升，且 shot 越多提升越大

Iterative Prompting 效果优于 Iterative Offline Correction，但后者每实例只需一次 API 调用，更具成本效益

用 WebNLG 验证器对 GenWikiFINE-f 的约 11 万文本-图对做迭代增强构建 GenWiki-HIQ；在其上训练的 G2T 模型在 GenWiki 人工标注测试集上全面优于用 GenWikiFINE-f 训练的模型

创新点

与让 LLM 自我反思的 Self-Refine 不同，论文发现 LLM 在结构化数据上无法给出有效自我反馈，因此引入外部小型验证器提供细粒度纠正指令；与 Welleck 等的自纠错语言模型相比，PiVe 的验证器设计更简单，仅需'删除三元组'这一简单扰动策略即可自监督构造任意大的训练数据。此外验证器可复用为数据增强工具，并提出在线迭代提示与离线修正两种成本-效果权衡模式。
