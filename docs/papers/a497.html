Making Large Language Models Better Reasoners with Step-Aware Verifier

用步骤感知验证器（Step-Aware Verifier）让大语言模型成为更好的推理器

简介

论文解决 LLM 在 GSM8K 等推理任务上即使使用 chain-of-thought 提示仍频繁出错的问题：已有 self-consistency 依赖固定 prompt 采样加多数投票，路径多样性受限且多数路径被误导时会失效。方法 DIVERSE 包含三个组件：为同一题随机构造 5 组不同 exemplar 的 prompt、各采样 20 条推理路径以扩大多样性；微调 deberta-v3-large 作为 verifier，与投票结合做加权筛选；再通过比较正/负路径中间结果的语义等价性自动生成步骤级标签，训练 step-aware verifier 对每步单独打分。在 code-davinci-002 上于 8 个基准中的 6 个刷新 SOTA（GSM8K 74.4%→83.2%，CLUTRR 67.0%→95.9%），且步骤级分数能指示推理从哪一步开始出错，带来可解释性。对团队而言，'多样采样+验证器加权投票'与'步骤级失败定位'是提升 LLM 应用输出可靠性的通用模式。

问题

LLM 在 GSM8K 等算术/常识/归纳推理任务上即使配合 chain-of-thought 提示仍会生成错误推理路径；已有 self-consistency 方法使用固定 exemplar 的 prompt 采样多条路径后做多数投票，存在三方面不足：prompt 固定导致路径多样性受限、多数路径被误导时投票失效、以及无法定位推理链中具体哪一步出错。

方法

DIVERSE 三组件：(1) Diverse Prompts：每题随机选取 M1=5 组不同 exemplar 组成的 prompt，各自采样解码 M2=20 条推理路径，共 100 条候选；(2) Voting Verifier：用 1000 条 ⟨question, answer⟩ 训练对微调 deberta-v3-large 作为 verifier 输出每条路径的正确概率，将 verifier 概率与投票指示函数结合做加权聚合，避免纯多数投票被误导；(3) Step-aware Voting Verifier：设计算法比较负路径与正路径的中间结果（用 roberta-large-mnli 判断语义等价），自动提取步骤级正/负标签，在损失函数中加入步骤级辅助损失（超参 α 平衡），对每个推理步骤单独验证。exemplar 不足时用 self-teaching 自举伪 exemplar。

关键结果

在 code-davinci-002 上于 8 个推理基准中的 6 个取得新 SOTA：GSM8K 74.4%→83.2%、AsDiv 81.9%→88.7%、MultiArith 99.3%→99.8%、SVAMP 86.6%→87.0%、SingleEq 79.5%→94.9%、CLUTRR 67.0%→95.9%

GSM8K 上相比 Greedy Decode/Self-Consistency 的提升：davinci 22.2%/12.0%，text-davinci-002 33.1%/12.0%，code-davinci-002 27.0%/5.6%；相比 Self-Consistency 在三类推理技能上平均提升 5.6%/5.1%/54.3%

verifier 训练数据从 1000 条削减 75% 到 250 条，性能仅下降约 2%；每题使用推理路径数 M≥50 后准确率提升趋于边际

每个 prompt 使用 8 个 exemplar 可将 GSM8K 准确率进一步提升到 83.2%

错误推理步骤中 95% 由错误公式（用错中间结果或算子）导致；随机路径 40% 含冗余步骤，verifier 降至 31%，step-aware verifier 进一步降至 20%；对 33% 的失败用例 step-aware verifier 产生更多正确步骤

常识推理任务上比 PaLM-based self-consistency 低 1.9%（StrategyQA 低 3.0%，归因于伪 exemplar 噪声）

创新点

相对 self-consistency（固定 prompt 采样+多数投票），DIVERSE 的区别在于：通过变换 prompt 本身（而非仅靠采样解码）增加推理路径多样性；用可训练的 verifier 与投票结合替代纯多数投票，避免多数被误导时失效；首次把验证粒度从整条推理链细化到单个推理步骤，并自动构造步骤级标签，同时带来性能提升与'哪一步开始出错'的可解释性。
