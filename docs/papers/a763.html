AgentVerse: Facilitating Multi-Agent Collaboration and Exploring Emergent Behaviors

AgentVerse：促进多智能体协作并探索涌现行为

简介

该论文针对单 Agent 难以胜任复杂真实任务、且已有多 Agent 研究局限于窄任务和静态角色分工的问题，提出通用多 Agent 框架 AgentVerse。框架模拟人类群体解题过程，包含 Expert Recruitment、Collaborative Decision-Making、Action Execution、Evaluation 四个循环阶段：由 recruiter Agent 根据目标自动生成专家角色描述，支持水平（民主讨论后聚合）与垂直（solver+reviewer 迭代至共识）两种通信结构，并依据评估反馈动态调整团队组成。实验显示 GPT-4 驱动的 Group 设置在 Humaneval 上 pass@1 从 83.5 提升到 89.0，10 个多工具任务完成 9 个（单 ReAct Agent 仅 3 个）；但 GPT-3.5-Turbo 的 Group 设置在部分任务上因易被错误反馈带偏反而劣于单 Agent。研究还在 Minecraft 中归纳出 volunteer、conformity、destructive 三类涌现行为，为多 Agent 系统的效率增益与安全风险提供了系统的观察框架。

问题

复杂真实任务往往需要多个体协作，但已有多 Agent 协作研究局限于特定窄任务、泛化性不确定，且采用静态协作方式，Agent 的角色与能力固定僵化，缺乏可随任务进展动态调整的通用协作框架。

方法

将人类群体解题过程建模为 MDP，提出 AgentVerse 四阶段循环框架：(1) Expert Recruitment——由 recruiter Agent 根据目标动态生成专家角色描述组成团队，并依据评估反馈调整组成；(2) Collaborative Decision-Making——水平结构中各 Agent 独立决策后经 summarization/ensemble 聚合，垂直结构中 solver 提案、reviewer 反馈迭代至共识；(3) Action Execution——Agent 以 ReAct 方式调用工具（用 OpenAI function call 实现）执行集体决策；(4) Evaluation——由人或 Agent 给出 verbal 反馈，未达标则回到招募阶段重新配置团队。

关键结果

Humaneval 上 GPT-4 的 pass@1 从 CoT 的 83.5 提升到 Group 设置的 89.0

10 个需至少两种工具的任务中，AgentVerse 编排的 Agent 组完成 9 个，单 ReAct Agent 仅完成 3 个

GPT-3.5-Turbo 的 Group 设置在 3 个通用任务中的 2 个上劣于 Solo 设置，MGSM 数据集约 10% 的错误可归因于 Agent 被他人错误反馈带偏；该现象在 GPT-4 上未出现

数学推理任务中 reviewer 数量增多与更高概率的错误批评相关，故将数学推理任务的 Agent 数限制为 2 个

在 Minecraft 具身实验中归纳出三类涌现行为：volunteer（时间/资源/协助贡献）、conformity、destructive（如伤害其他 Agent 或破坏村庄图书馆以获取材料）

创新点

区别于已有静态角色、窄任务的多 Agent 工作，AgentVerse 的主要区别在于：由 recruiter Agent 自动生成并依据评估反馈动态调整专家团队组成（而非人工预分配角色）；系统化采用并对比水平/垂直两种通信结构；并跨文本理解、推理、编码、工具使用与具身 AI 多类任务系统观察并分类多 Agent 涌现行为（volunteer/conformity/destructive）。
