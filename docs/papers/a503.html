PromptChainer: Chaining Large Language Model Prompts through Visual Programming

PromptChainer：通过可视化编程将 LLM 提示串联成链

简介

论文研究非 AI 专家如何编写由多次 LLM 调用组成的提示链，以完成单次调用无法处理的复杂多步任务。通过三个月的形成性研究，作者提炼出三大挑战：充分利用 LLM 能力的开销、提示编写时无意引入错误、以及黑盒不稳定生成导致的级联错误，并据此设计 PromptChainer——一个可视化链编程界面，提供 Chain View/Node View 双视图、数据转换与评估 helper 节点、自定义 JavaScript 与外部 API 节点、提示模板占位符与输入句柄自动同步，以及节点单测、端到端运行、断点调试三级排错机制。4 名设计师与开发者的案例研究显示，所有人成功搭建平均 5.5±0.9 个节点的链，预定义 helper 覆盖了大多数链式需求；用户不仅用链弥补单提示的局限，也借链提升原型可扩展性并获得中间控制。论文同时指出并行子任务间的一致性保持与复杂链的追踪仍是开放问题。

问题

单次 LLM 运行难以完成真实应用中的复杂多步任务；已有工作表明将多次 LLM 运行串联成链（上一步输出作为下一步输入）能以更透明、可控的方式完成复杂任务，但用户在编写自己的 LLM 链时需要何种支持仍是开放问题。形成性研究归纳出三大编写挑战：(1) 充分利用 LLM 能力的开销，(2) 提示编写时容易无意引入错误，(3) 黑盒且不稳定的 LLM 生成造成的级联错误；具体表现为需要在链的步骤间转换数据格式，并在多个粒度上调试链。

方法

PromptChainer 可视化链编写界面：Chain View 以节点-边图编辑链结构，Node View 用于实现、改进与测试单个节点。节点类型包括 Generic LLM 节点、LLM Classifier 节点、面向数据转换与评估的 helper 节点、自定义 JavaScript 节点，以及与外部服务交换数据的 communication 节点。系统依据提示模板中的占位符（如 [[user]]）自动解析并同步节点的命名输入/输出句柄，使局部编辑与全局链保持一致；示例库提供常用子链模板，引导用户形成对 LLM 能力的心智模型并趋向可解析的提示模式。调试支持三个粒度：独立测试块做节点级单测、端到端运行并按节点记录输出、断点调试且允许直接修改中间节点输出后再继续执行下游节点。底层模型为 137B 参数的 LaMDA。

关键结果

4 名参与者（3 名设计师、1 名开发者）全部在研究 session 中成功搭建出目标链，链平均包含 5.5±0.9 个节点

预定义 helper 节点覆盖了大多数链式需求：用户共使用 13 个预定义 helper，是自定义 JavaScript 节点（4 个）的三倍

对用户研究与试点用户共 8 条链中 27 个 LLM 节点的编码：7 个用于输入分类（categorizing inputs）、13 个用于从 LLM 获取信息（sourcing information）、7 个用于重组输入（re-organizing input）

创新点

区别于作者团队先前仅提出并验证 chaining 概念的工作，本文首次系统研究'用户如何编写自己的 LLM 链'这一开放问题：通过形成性研究提炼出 LLM 高度通用性带来的三大编写挑战，并给出对应的界面设计——处理任意 LLM 数据格式的 helper 节点、为每个 LLM 步骤定义'函数签名'的模板-句柄同步机制、以及节点单测/端到端/断点三级级联错误调试。案例研究还首次刻画了用户的链构建策略差异（自顶向下先搭占位节点 vs 逐节点构建）与链式动机（不仅为弥补 LLM 局限，也为可扩展性与中间控制），并指出并行子任务一致性与复杂链追踪等未解问题。
