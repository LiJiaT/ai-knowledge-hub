Zep: A Temporal Knowledge Graph Architecture for Agent Memory

Zep：一种面向 Agent 记忆的时序知识图谱架构

简介

论文针对现有 RAG 框架只能做静态文档检索、无法支撑 Agent 持续演化的对话与业务数据记忆的问题，提出 Zep——一个基于 Graphiti 时序知识图谱引擎的 Agent 记忆层服务。Graphiti 用 episode/语义实体/社区三层子图组织非结构化对话与结构化业务数据，采用双时间线模型记录事实的有效期与摄入顺序，并通过 LLM 驱动的实体消歧、事实抽取与边失效机制实现知识的动态更新与非有损存储。检索侧融合余弦相似度、Okapi BM25 全文与图上广度优先搜索，再用 RRF/MMR、提及频率、节点距离与 cross-encoder 等重排器提精度。实验上，Zep 在 DMR 基准以 94.8%（gpt-4-turbo）超过 MemGPT 的 93.4%，在更贴近企业场景的 LongMemEval s 上较全上下文基线准确率最高提升 18.5%，同时响应延迟降低约 90%。结论表明时序知识图谱是构建 Agent 长期记忆、降低 token 成本与延迟的有效工程路径。

问题

现有 RAG 方法面向静态文档语料，无法满足企业级 Agent 对持续演化的对话历史与业务数据进行动态知识整合的需求；由于完整对话历史与业务数据无法有效放入 LLM 上下文窗口，需要新的 Agent 记忆机制，能动态更新知识并保留事实的时间演化关系。

方法

核心是 Graphiti 时序知识图谱引擎：图由 episode 子图、语义实体子图、社区子图三层构成，非有损存储原始对话并保留双向索引。采用双时间线模型（事件时间线 T 与摄入事务时间线 T'），为每条事实记录 t_valid/t_invalid 与 t'_created/t'_expired；新边与既有边语义矛盾时由 LLM 判定并使旧边失效。实体抽取结合最近 n=4 条消息上下文与 reflexion 启发的反思技术减少幻觉，实体消歧通过 1024 维向量余弦检索+全文检索+LLM 判重完成，图写入使用预定义 Cypher 查询而非 LLM 生成查询以保证 schema 一致性。社区检测用 label propagation 及其动态扩展替代 GraphRAG 的 Leiden 算法，降低全量刷新的延迟与 LLM 成本。检索时混合余弦语义相似、Okapi BM25 全文与图上广度优先搜索三种方式，再经 RRF、MMR、episode-mentions、node distance 及 cross-encoder 重排，输出格式化上下文字符串供 Agent 使用。

关键结果

DMR 基准（500 组多会话对话）：Zep 用 gpt-4-turbo 达到 94.8% 准确率，超过 MemGPT 报告的 93.4%；用 gpt-4o-mini 达到 98.2%。对照基线：全对话上下文 94.4%（gpt-4-turbo）/98.0%（gpt-4o-mini），会话摘要 78.6%/88.0%，递归摘要基线仅 35.3%。

LongMemEval s（对话平均约 115,000 tokens）：gpt-4o-mini + Zep 较基线准确率提升 15.2%，gpt-4o + Zep 提升 18.5%，同时响应延迟较基线降低约 90%。

按题型分解：gpt-4o-mini + Zep 在六类问题中的四类有提升，增益最大的是 single-session-preference、multi-session 与 temporal-reasoning；gpt-4o + Zep 在 knowledge-update 类亦有提升。

single-session-assistant 类问题出现性能下降：gpt-4o 下降 17.7%，gpt-4o-mini 下降 9.06%。

创新点

相比 MemGPT 等基于递归摘要/归档的记忆方案与 GraphRAG 等静态图 RAG，Zep 的主要区别在于：(1) 双时间线模型，同时建模事实的事件时间与系统摄入时间，支持基于新信息的边失效与历史关系演化记录，作者称这是 LLM 知识图谱构建上的新进展；(2) episode/语义实体/社区三层子图的非有损存储与双向索引，可从语义产物回溯引用来源；(3) 用 label propagation 的动态扩展维护社区，延迟全量刷新以降低延迟与 LLM 推理成本；(4) 检索侧将余弦、BM25 与图上 BFS 混合并配合图感知重排器，而非 GraphRAG 的 map-reduce 检索。

ZEP: A TEMPORAL KNOWLEDGE GRAPH ARCHITECTURE FOR AGENT MEMORY

Preston Rasmussen Zep AI preston@getzep.com Pavlo Paliychuk Zep AI paul@getzep.com Travis Beauvais Zep AI travis@getzep.com Jack Ryan Zep AI jack@getzep.com Daniel Chalef Zep AI daniel@getzep.com

ABSTRACT

我们提出 Zep，一种面向 AI 智能体的新型记忆层服务，它在深度记忆检索（Deep Memory Retrieval, DMR）基准测试（benchmark）中超越了当前最先进的系统 MemGPT。此外，在比 DMR 更全面、更具挑战性且更能反映真实企业用例的评估中，Zep 同样表现卓越。现有面向大语言模型（Large Language Model, LLM）智能体的检索增强生成（Retrieval-Augmented Generation, RAG）框架仅限于静态文档检索，而企业应用需要从持续对话和业务数据等多种来源动态整合知识。Zep 通过其核心组件 Graphiti 解决了这一根本性局限——Graphiti 是一个具备时间感知能力的知识图谱引擎，能够动态融合非结构化的对话数据与结构化的业务数据，同时维护历史关系。在 MemGPT 团队将其确立为主要评估指标的 DMR 基准测试中，Zep 展现出更优的性能（94.8% vs 93.4%）。除 DMR 之外，Zep 的能力还通过更具挑战性的 LongMemEval 基准测试得到进一步验证，该基准通过复杂的时间推理任务更好地反映了企业用例。在这一评估中，Zep 取得了显著成果：与基线实现相比，准确率提升最高达 18.5%，同时响应延迟降低 90%。这些结果在跨会话信息综合与长期上下文维护等企业关键任务中尤为突出，证明了 Zep 在真实应用中部署的有效性。

1 Introduction

基于 Transformer 的大语言模型（LLM）对产业界和研究界的影响近年来备受关注[1]。LLM 的一个主要应用是开发基于聊天的 Agent。然而，这些 Agent 的能力受限于 LLM 的上下文窗口、上下文的有效利用以及预训练期间获得的知识。因此，需要额外的上下文来提供域外（OOD）知识并减少幻觉。

检索增强生成（RAG）已成为基于 LLM 的应用中一个关键的关注领域。RAG 利用过去五十年间开创的信息检索（IR）技术[2]，为 LLM 提供必要的领域知识。

当前使用 RAG 的方法主要聚焦于宽泛的领域知识和大体静态的语料库——也就是说，添加到语料库中的文档内容很少发生变化。要让 Agent 在我们的日常生活中无处不在，自主解决从琐碎到高度复杂的问题，它们将需要访问一个持续演化的大型语料库，其中包含用户与 Agent 交互产生的数据，以及相关的业务数据和世界数据。我们认为，赋予 Agent 这种广泛而动态的“记忆”是实现这一愿景的关键构建模块，并且我们主张，当前的 RAG 方法并不适用于这样的未来。由于完整的对话历史、业务数据集以及其他领域特定内容无法有效地容纳在 LLM 的上下文窗口内，因此需要为 Agent 记忆开发新的方法。为 LLM 驱动的 Agent 添加记忆并非新想法——这一概念此前已在 MemGPT[3] 中得到探索。

近来，知识图谱（KG）已被用于增强 RAG 架构，以解决传统 IR 技术的诸多不足[4]。在本文中，我们介绍 Zep[5]，一个由 Graphiti[6] 驱动的记忆层服务，Graphiti 是一个动态的、具备时间感知能力的知识图谱引擎。Zep 摄取并综合非结构化的消息数据和结构化的业务数据。Graphiti KG 引擎以无损的方式利用新信息动态更新知识图谱，维护事实与关系的时间线，包括其有效期。这种方法使知识图谱能够表示一个复杂且不断演化的世界。

由于 Zep 是一个生产系统，我们重点关注了其记忆检索机制的准确性、延迟和可扩展性。我们使用两个现有的基准测试（benchmark）来评估这些机制的有效性：一个是来自 MemGPT[3] 的深度记忆检索（DMR）任务，另一个是 LongMemEval 基准测试[7]。

2 Knowledge Graph Construction

在 Zep 中，记忆由一个具有时间感知能力的动态知识图谱 G = ( N , E , φ ) 驱动，其中 N 表示节点，E 表示边，φ : E → N × N 表示一个形式化的关联函数。该图谱由三个层级的子图构成：情节子图、语义实体子图和社区子图。

对原始情节数据与派生语义实体信息的双重存储，呼应了人类记忆的心理学模型。这些模型区分了表示不同事件的情节记忆与捕捉概念及其含义之间关联的语义记忆 [8]。这种方法使采用 Zep 的大语言模型（LLM）Agent 能够发展出更复杂、更精细的记忆结构，从而更好地契合我们对人类记忆系统的理解。知识图谱为表示这些记忆结构提供了一种有效的媒介，而我们实现的相互独立的情节子图与语义子图则借鉴了 AriGraph [9] 中的类似方法。

我们使用社区节点来表示高层结构与领域概念，这一做法建立在 GraphRAG [4] 工作的基础上，从而能够对该领域形成更全面的全局理解。由此形成的层级化组织结构——从情节到事实、再到实体、再到社区——扩展了现有的层级化检索增强生成（RAG）策略 [10][11]。

2.1 Episodes

Zep 的图构建始于对称为情节（Episode）的原始数据单元的摄取。情节可以是三种核心类型之一：消息、文本或 JSON。尽管每种类型在图构建过程中都需要特定的处理方式，但本文聚焦于消息类型，因为我们的实验以对话记忆为中心。在我们的场景中，一条消息由相对较短的文本（多条消息可以容纳于一个 LLM 上下文窗口之内）以及产生该话语的相关行为者（actor）组成。

每条消息都包含一个参考时间戳 t ref，用于标明消息发送的时间。这一时间信息使 Zep 能够准确识别并提取消息内容中提及的相对日期或部分日期（例如“下周四”、“两周后”或“去年夏天”）。Zep 实现了一种双时态（bi-temporal）模型，其中时间线 T 表示事件的时间先后顺序，而时间线 T ′ 表示 Zep 数据摄取的事务顺序。T ′ 时间线发挥着数据库审计这一传统用途，而 T 时间线则为建模对话数据与记忆的动态特性提供了一个额外的维度。这种双时态方法代表了基于 LLM 的知识图谱构建领域的一项新颖进展，并且构成了 Zep 相较于以往基于图的 RAG 方案的诸多独特能力的基础。

2.2.1 Entities

实体提取是情节处理的初始阶段。在摄取过程中，系统会同时处理当前消息内容和最近 n 条消息，为命名实体识别提供上下文。在本文以及 Zep 的通用实现中，n = 4，即提供两轮完整的对话用于上下文评估。鉴于我们关注的是消息处理，说话者会被自动提取为一个实体。在完成初始实体提取后，我们采用一种受 reflexion[12] 启发的反思技术，以最大限度地减少幻觉并提高提取覆盖率。系统还会从情节中提取实体摘要，以便于后续的实体消解和检索操作。

提取完成后，系统将每个实体名称嵌入到 1024 维向量空间中。这种嵌入使得系统能够通过在现有图实体节点上进行余弦相似度搜索来检索相似节点。系统还会对现有的实体名称和摘要执行单独的全文搜索，以识别更多候选节点。随后，这些候选节点与情节上下文一起，通过大语言模型（LLM）使用我们的实体消解提示词进行处理。当系统识别出重复实体时，会生成更新后的名称和摘要。

在实体提取与消解完成之后，系统使用预定义的 Cypher 查询将这些数据并入知识图谱。我们选择这种方式而非由 LLM 生成的数据库查询，以确保 schema 格式的一致性，并降低产生幻觉的可能性。

2.2.3 Temporal Extraction and Edge Invalidation

与其他知识图谱引擎相比，Graphiti 的一个关键差异化特性在于其能够通过时序提取（temporal extraction）和边失效（edge invalidation）过程来管理动态信息更新。

系统使用 t ref 从情节（episode）上下文中提取与事实相关的时序信息。这使得系统能够对绝对时间戳（例如，“艾伦·图灵出生于 1912 年 6 月 23 日”）和相对时间戳（例如，“我两周前开始了新工作”）进行准确提取并以日期时间形式表示。与我们的双时态（bi-temporal）建模方法一致，系统跟踪四个时间戳：t ′ created 和 t ′ expired ∈ T ′ 监控事实在系统中何时被创建或失效，而 t valid 和 t invalid ∈ T 则跟踪事实成立的时间范围。这些时序数据点与其他事实信息一同存储在边上。

新边的引入可能使数据库中已有的边失效。系统采用大语言模型（LLM）将新边与语义相关的既有边进行比较，以识别潜在的矛盾。当系统识别出时间上重叠的矛盾时，会将受影响边的 t invalid 设置为使其失效的边的 t valid，从而使这些边失效。遵循事务时间线 T ′，Graphiti 在确定边失效时始终优先考虑新信息。

这种全面的方法使得 Graphiti 能够随着对话的演进动态添加数据，同时既维护当前的关系状态，又保留关系随时间演变的历史记录。

2.3 Communities

在建立情景子图和语义子图之后，系统通过社区检测构建社区子图。虽然我们的社区检测方法建立在 GraphRAG[4] 所述技术的基础上，但我们采用标签传播算法 [13] 而非 Leiden 算法 [14]。这一选择受到标签传播算法易于动态扩展这一特点的影响，该特性使系统能够在新数据进入图时更长时间地保持准确的社区表示，从而推迟对完整社区刷新的需求。

该动态扩展实现了标签传播中单个递归步骤的逻辑。当系统向图中添加新的实体节点 n i ∈ N s 时，它会考察相邻节点所属的社区。系统将新节点分配给其多数邻居所在的社区，然后相应地更新社区摘要和图。虽然这种动态更新使得数据流入系统时能够高效地扩展社区，但由此产生的社区会逐渐偏离完整运行一次标签传播所生成的社区。因此，定期的社区刷新仍然是必要的。不过，这种动态更新策略提供了一种实用的启发式方法，可显著降低延迟和 LLM 推理成本。

遵循 [4]，我们的社区节点包含通过对成员节点进行迭代式 map-reduce 风格摘要而得到的摘要。然而，我们的检索方法与 GraphRAG 的 map-reduce 方法 [4] 有很大不同。为支持我们的检索方法，我们根据社区摘要生成包含关键术语和相关主题的社区名称。这些名称经过嵌入处理并存储，以支持余弦相似度搜索。

3.1 Search

Zep 实现了三种搜索函数：余弦语义相似度搜索（ϕ cos）、Okapi BM25 全文搜索（ϕ bm25）以及广度优先搜索（ϕ bfs）。前两种函数利用了 Neo4j 对 Lucene [15][16] 的实现。每种搜索函数在识别相关文档方面各具独特能力，三者结合可在重排序之前对候选结果提供全面覆盖。搜索字段因三种对象类型而异：对于 E s，我们搜索 fact 字段；对于 N s，搜索实体名称；对于 N c，则搜索社区名称，该名称由该社区所涵盖的相关关键词和短语组成。尽管为独立开发，我们的社区搜索方法与 LightRAG [17] 中的高层关键词搜索方法相类似。将 LightRAG 的方法与 Graphiti 这类基于图的系统相融合，为未来研究展现了一个有前景的方向。

4

尽管余弦相似度和全文搜索方法在检索增强生成（RAG）[18] 中已十分成熟，但知识图谱上的广度优先搜索在 RAG 领域受到的关注有限，值得注意的例外是 AriGraph [9] 与 Distill-SynthKG [19] 等基于图的 RAG 系统。在 Graphiti 中，广度优先搜索通过识别 n 跳范围内的额外节点和边来增强初始搜索结果。此外，ϕ bfs 可以接受节点作为搜索的参数，从而对搜索函数实现更强的控制。当使用最近的情节作为广度优先搜索的种子时，这一功能尤为有价值，它使系统能够将最近提及的实体和关系纳入检索到的上下文中。

这三种搜索方法各自针对相似性的不同方面：全文搜索识别词汇相似性，余弦相似度捕捉语义相似性，而广度优先搜索则揭示上下文相似性——即在图中距离更近的节点和边会出现在更为相似的对话上下文中。这种多层面的候选结果识别方法最大限度地提高了发现最优上下文的可能性。

3.2 Reranker

虽然初始搜索方法旨在实现高召回率，但重排序器（reranker）的作用在于通过对最相关的结果进行优先排序来提高精确率。Zep 支持现有的重排序方法，例如倒数排序融合（Reciprocal Rank Fusion, RRF）[20] 和最大边际相关性（Maximal Marginal Relevance, MMR）[21]。此外，Zep 实现了一种基于图的情节提及（episode-mentions）重排序器，该重排序器根据对话中实体或事实被提及的频率对结果进行优先排序，从而使被频繁引用的信息变得更容易获取。该系统还包含一个节点距离重排序器，它根据结果与指定质心节点之间的图距离对结果进行重新排序，从而提供局限于知识图谱特定区域的上下文。该系统最复杂的重排序能力采用了交叉编码器（cross-encoder）——这类大语言模型（LLM）通过使用交叉注意力（cross-attention）针对查询对节点和边进行评估来生成相关性得分，不过这种方法会带来最高的计算成本。

4 Experiments

本节分析了基于 LLM 记忆的基准测试（benchmark）所开展的两项实验。第一项评估采用 [3] 中提出的深度记忆检索（Deep Memory Retrieval, DMR）任务，该任务使用了 "Beyond Goldfish Memory: Long-Term Open-Domain Conversation" [22] 中介绍的 Multi-Session Chat 数据集的一个包含 500 段对话的子集。第二项评估使用了 "LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory" [7] 中的 LongMemEval 基准测试。具体而言，我们使用 LongMemEval s 数据集，该数据集提供了平均 115,000 个 token 的长篇对话上下文。

在两项实验中，我们都通过 Zep 的 API 将对话历史整合到 Zep 知识图谱中。随后，我们使用第 3 节所述的技术检索出最相关的 20 条边（事实）和实体节点（实体摘要）。系统将这些数据重新格式化为上下文字符串，其功能与 Zep 的记忆 API 所提供的功能一致。

尽管这些实验展示了 Graphiti 的关键检索能力，但它们只是该系统完整搜索功能的一个子集。这种聚焦的范围使我们能够与现有基准测试进行清晰的比较，同时将对其他知识图谱能力的探索留待未来工作。

4.2 Deep Memory Retrieval (DMR)

深度记忆检索（Deep Memory Retrieval, DMR）评估由 [3] 提出，包含 500 段多会话对话，每段对话包含 5 个聊天会话，每个会话最多 12 条消息。每段对话包含一个用于记忆评估的问答对。MemGPT 框架 [3] 目前在使用 gpt-4-turbo 的情况下以 93.4% 的准确率领先各项性能指标，相比通过递归摘要实现的 35.3% 基线有显著提升。

为建立对比基线，我们实现了两种常见的大语言模型（LLM）记忆方法：完整对话上下文和会话摘要。使用 gpt-4-turbo 时，完整对话基线取得了 94.4% 的准确率，略超 MemGPT 报告的结果，而会话摘要基线取得了 78.6%。在使用 gpt-4o-mini 时，两种方法的性能均有所提升：完整对话为 98.0%，会话摘要为 88.0%。由于其已发表工作中方法学细节不足，我们无法使用 gpt-4o-mini 复现 MemGPT 的结果。

随后，我们通过摄取这些对话并使用 Zep 的搜索功能检索最相关的前 10 个节点和边，来评估 Zep 的性能。由 LLM 评判（LLM judge）将 Agent 的响应与所提供的标准答案（golden answers）进行比较。Zep 使用 gpt-4-turbo 取得了 94.8% 的准确率，使用 gpt-4o-mini 取得了 98.2%，相比 MemGPT 和各自的完整对话基线均仅有小幅提升。然而，这些结果必须结合具体情境来看待：每段对话仅包含 60 条消息，很容易容纳于当前 LLM 的上下文窗口之内。

DMR 评估的局限性不止于其较小的规模。我们的分析揭示了该基准测试（benchmark）设计中的重大缺陷。该评估完全依赖单轮的事实检索类问题，无法评估复杂的记忆理解能力。许多问题措辞含糊，提及了诸如“放松时最喜欢的饮品”或“怪异爱好”之类的概念，而这些概念在对话中并未被明确地如此刻画。最为关键的是，该数据集对 LLM Agent 真实企业用例的代表性很差。使用现代 LLM 的简单全上下文方法所取得的高性能，进一步凸显了该 benchmark 在评估记忆系统方面的不足。

[7] 中的发现进一步强调了这一不足：这些发现表明，随着对话长度的增加，LLM 在 LongMemEval benchmark 上的性能迅速下降。LongMemEval 数据集 [7] 通过呈现更长、更连贯、能更好反映企业场景的对话，以及更加多样化的评估问题，解决了上述许多缺陷。

4.3 LongMemEval (LME)

我们使用 LongMemEval s 数据集对 Zep 进行了评估，该数据集提供了能代表 LLM Agent 真实商业应用的对话和问题。LongMemEval s 数据集对现有 LLM 和商业记忆解决方案构成了重大挑战 [7]，其对话平均长度约为 115,000 个 token。这一长度虽然相当可观，但仍处于当前前沿模型的上下文窗口之内，使我们能够为评估 Zep 的性能建立有意义的基线。

该数据集包含六种不同的问题类型：single-session-user、single-session-assistant、single-session-preference、multi-session、knowledge-update 和 temporal-reasoning。这些类别在整个数据集中并非均匀分布；有关详细的分布信息，我们建议读者参阅 [7]。

我们在 2024 年 12 月至 2025 年 1 月期间进行了所有实验。我们使用一台消费级笔记本电脑，从马萨诸塞州波士顿的一处住宅位置进行测试，连接到托管于 AWS us-west-2 的 Zep 服务。这种分布式架构在评估 Zep 的性能时引入了额外的网络延迟，而这一延迟在我们的基线评估中并不存在。

5 Conclusion

我们介绍了 Zep，这是一种基于图的 LLM 记忆方法，它将语义记忆和情景记忆与实体摘要和社区摘要相结合。我们的评估表明，Zep 在现有记忆基准测试上达到了最先进的性能水平，同时降低了 token 成本，并以显著更低的延迟运行。

Graphiti 和 Zep 所取得的成果虽然令人瞩目，但很可能仅代表了基于图的记忆系统的初步进展。多条研究路径可以在这些框架的基础上继续拓展，包括将其他 GraphRAG 方法整合进 Zep 范式，以及对我们的工作进行新颖的扩展。

研究已经证明了在 GraphRAG 范式中，经过微调的模型在基于 LLM 的实体和边抽取中的价值，其在提升准确率的同时降低了成本和延迟 [19][25]。针对 Graphiti 提示进行微调的类似模型或可增强知识抽取效果，尤其是对于复杂对话。此外，尽管当前关于 LLM 生成知识图谱的研究大多在没有形式化本体的情况下开展 [9][4][17][19][26]，但领域特定本体展现出巨大的潜力。图本体在 LLM 出现之前的知识图谱研究中曾处于基础性地位，值得在 Graphiti 框架内得到进一步探索。

我们在寻找合适的记忆基准测试时发现可选方案十分有限，现有基准测试往往缺乏鲁棒性和复杂度，常常沦为简单的“大海捞针”式事实检索问题 [3]。该领域需要更多的记忆基准测试，尤其是那些能够反映客户体验任务等业务应用的基准测试，以便有效评估并区分各种记忆方法。值得注意的是，目前尚无任何现有基准测试能够充分评估 Zep 处理并综合对话历史与结构化业务数据的能力。尽管 Zep 专注于 LLM 记忆，其传统的检索增强生成（RAG）能力
