Do Mixed-Vendor Multi-Agent LLMs Improve Clinical Diagnosis?

混合厂商 Multi-Agent LLM 能否改进临床诊断？

简介

论文研究多 Agent LLM 诊断系统中'厂商多样性'的价值：现有临床多 Agent 框架多用同一模型家族组队，存在相关失败模式（correlated failure modes），会在讨论中强化共享偏见而非纠错。作者在 MAC（Multi-Agent Conversation）框架上系统比较 SingleLLM、Single-Vendor 与 Mixed-Vendor 三种配置，用 o4-mini、Gemini-2.5-Pro、Claude-4.5-Sonnet 各实例化一个 doctor agent，在 RareBench 与 DiagnosisArena 上评测，并刻意去掉角色特化 prompt 以隔离模型多样性这一变量。结果显示 Mixed-Vendor 配置在两个基准上均取得最优 recall 与 accuracy（RareBench Recall@1 39.31%、DiagnosisArena Top-1 36.36%），且部分 Single-Vendor MAC 反而低于单模型基线。Overlap/Jaccard 分析揭示机制：混合团队汇聚互补归纳偏置，'拯救'被单个模型或同质团队集体漏掉的诊断，但存在 consensus trap 风险。对团队而言，这是'多 Agent 组队应混用不同厂商模型'的直接实证依据，其双 judge 评测与 overlap 分析方法也可直接借鉴。

问题

现有临床诊断多 Agent LLM 框架大多由同一厂商/同一模型家族的多个 Agent 组队，同质团队存在相关失败模式，会在对话中强化共享偏见而非纠正错误；而医学领域已有的跨厂商组合多为独立运行加投票/简单聚合，缺乏在共享对话式架构内对 single-vendor 与 mixed-vendor 的系统比较。论文要回答：在相同 MAC 架构下，混用不同厂商的前沿模型能否、以及通过何种机制提升诊断性能。

方法

基于 Multi-Agent Conversation（MAC）框架：3 个 'doctor' Agent 加 1 个 supervisor Agent，按固定 round-robin 顺序发言；每轮 doctor 阅读完整对话历史与 supervisor 最新反馈后，提交带简要理由的 Top-10（RareBench）/Top-5（DiagnosisArena）排序诊断列表；supervisor 监控讨论、给出反馈，在差异诊断稳定或达到 13 轮硬上限时终止，用规则解析器从其结论消息中提取最终列表。关键实验设计：不用角色特化 prompt，所有 doctor 使用相同的通用临床指令，使性能差异严格来自 vendor 多样性；三个 doctor 分别由 o4-mini、Gemini-2.5-Pro、Claude-4.5-Sonnet 实例化，o4-mini 默认固定为 supervisor。评测采用 o4-mini 作 LLM judge，并用 BioLORD 检索式 judge 做厂商中立的二次评测；通过 solution set overlap、Jaccard 相似度与 ∆Coverage 分析收益机制。

关键结果

RareBench 合并集上，Mixed-Vendor MAC 取得 Recall@1 39.31%、Recall@10 61.35%，在所有检索深度指标上均为最高，并超过所有 Single-Vendor MAC 基线

最难的 MME 子集（n=40）上，Mixed-Vendor MAC Recall@1 达 40.00%，比最佳 Single-LLM（Gemini-2.5-Pro）高 10 个百分点，比最佳 Single-Vendor MAC（Claude-4.5-Sonnet）高 5 个百分点

LIRICAL 子集上 Mixed-Vendor MAC Recall@1 为 35.69%，与最佳 Single-LLM Gemini-2.5-Pro（36.24%）相当，但在 Recall@3/5/10 上超过所有基线；HMS 子集上所有指标均为最高

DiagnosisArena（n=165，2024 年案例）上 Mixed-Vendor MAC Top-1 准确率 36.36%、Top-5 49.09%，超过 o4-mini Single-Vendor MAC 的 35.76%；而 Gemini-2.5-Pro 与 Claude-4.5-Sonnet 单模型 Top-1 仅 20.00% 与 19.39%

Overlap 分析：MME 上 Mixed-Vendor 相对最强 Single-LLM 挽回 22.50% 的案例（Mixed Rescue）且零回归（Baseline Unique 0.00%）；其他数据集 Baseline Unique 为 6.82%-14.1%

部分 Single-Vendor MAC 反而低于其单模型基线（Gemini 在 LIRICAL 与 HMS、Claude 在 HMS），归因于相关失败模式

Supervisor 消融（MME）：换用 Gemini 或 Claude 做 supervisor，Mixed-Vendor Recall@1 仍达 40.00%-42.50%，领先最佳同质基线 +7.5% 至 +15.0%

多样性-收益关联：MME 上 ∆Coverage 峰值 32.97% 恰好出现在跨厂商 Jaccard 相似度最低处（J_AB=0.269、J_AC=0.233、J_BC=0.750）

创新点

相对已有工作的区别：(1) 此前医学 mixed-vendor 系统多为 panel 式独立运行加多数投票/聚合，Agent 之间无实时交叉质询；本文首次在共享的对话式 MAC 架构内系统对比 single-vendor 与 mixed-vendor 配置。(2) 通过去掉角色特化 prompt 的对称设置，把收益严格归因到 vendor 多样性而非角色分工。(3) 用 overlap/Jaccard/∆Coverage 定量揭示机制——混合团队汇聚互补归纳偏置、'拯救'被漏诊案例，而同质团队受相关失败模式与 consensus trap 困扰；并发现同厂商扩容（多实例同款模型）不保证提升、甚至可能退化。
