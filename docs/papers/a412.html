Can We Edit Factual Knowledge by In-Context Learning?

我们能用 In-Context Learning 编辑事实知识吗？

简介

该论文研究能否在不更新任何参数的前提下，用 in-context learning（ICL）编辑 LLM 中错误或过时的事实知识，以规避梯度式知识编辑的高计算开销、副作用以及黑盒 API 模式下无法修改参数的问题。作者提出 IKE（In-Context Knowledge Editing），设计 copy、update、retain 三类演示模板，并用 sentence encoder 做 k-NN 检索与余弦相似度排序来组织演示上下文。实验显示 IKE 在 GPT-J 上取得与 ROME 相当的总分（89.6 vs 91.5）但过度编辑与知识遗忘更少，且可扩展到 OPT-175B；消融证明演示选择与 retain 演示决定 specificity，update 演示决定 generalization。对团队而言，这是一份关于'如何通过上下文组织可靠改变模型行为'的系统性实证研究，其演示工程方法与副作用评测口径可直接迁移到知识库问答与 RAG 的上下文构建中。

问题

LLM 参数中存储的事实知识可能错误或过时；传统知识编辑依赖梯度/微调（FT、MEND、ROME 等），计算开销大、会引入遗忘旧知识与过度编辑等副作用，且在 model-as-a-service 黑盒模式下无法修改参数。论文探究 ICL 能否在无梯度、无参数更新的情况下完成事实知识编辑，同时满足两个目标：generalization（对同一事实的多种提示表述都能给出新答案）与 specificity（不干扰其他无关知识）。

方法

提出 IKE：将新事实 f=(x*, y*) 与探测提示 x 组织成自然语言演示上下文，模板为 T(f,x,y)=New Fact: f. Prompt: x y；设计三类演示——copy（注入新事实）、update（提升泛化）、retain（保持无关知识），比例设为 1:3:4；用预训练 sentence encoder（all-MiniLM-L6-v2）从训练语料检索 k-NN 演示并按余弦相似度从左到右排序（2048 上下文长度取 k=32）。全程不修改参数，编辑效果通过 P(y|x,f,C) 评估，并讨论了与外部记忆+检索增强结合以支持多条编辑的扩展方向。

关键结果

GPT-J (6B) 上 COUNTERFACT 基准：IKE 总分 89.6，与最优基线 ROME 的 91.5 相当；比 MEND 高 10% 绝对编辑成功率，specificity 比 ROME 高 30 分

OPT-175B 上 IKE 比 PROMPT 基线高 36.0 分，验证方法在更大规模模型上的可扩展性；编辑后近 50% 知识事实仍保持较高概率

消融实验：去掉基于检索的演示选择（Random Selection）使 NS 从 77.0 降至 45.0；去掉 retain 演示使 NM 从 35.2 骤降至 -47.6；去掉 update 演示显著损害 generalization

CKA 对比评估：所有基线在更严格的对比评估下倾向过度泛化，ROME 平均 CKA 最低、false rate 最高，IKE 的过度编辑影响最小

TEMPLAMA 时间感知知识多轮编辑：ROME 的 memorization ratio 极低（几乎遗忘所有已注入旧事实），IKE 在多轮编辑后仍能记住最旧事实

用 Wikipedia 中性长文本替换事实的扩展实验：IKE 达到 75 PS / 73 NS，高于仅检索增强的 PROMPT（65 / 64）

成本：32 个演示的 IKE 实验在单张 40GB NVIDIA A40 上约需 3 GPU 小时

创新点

与 hyper-network（MEND）、MLP 参数定位改写（ROME）等梯度式方法不同，IKE 把知识编辑完全转化为演示构造问题，无需梯度估计、适用于黑盒模型；相比 Si et al. (2022) 仅在 GPT-3 上初步验证 ICL 可提升编辑成功率，本文系统研究了演示格式/选择/排序的影响、过度编辑与知识遗忘等副作用、跨模型规模（1.5B–175B）的可扩展性，并提出外部记忆+检索增强的工程化扩展方向。
