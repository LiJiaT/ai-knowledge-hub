简介

这篇综述面向 LLM 的实践者与最终用户，系统回答“什么任务该用 LLM、什么任务不该用”这一工程选型问题。论文从模型（GPT-style 与 BERT-style 两大谱系）、数据（预训练/微调/测试数据）与下游任务三个视角展开，按标注数据量（zero/few/abundant）给出选型建议，并逐一分析传统 NLU、生成、知识密集、scaling 相关能力等任务的 use case 与 no use case，汇总为决策流程图。关键结论：有充足标注数据的传统 NLU 任务微调小模型仍更优且成本更低；生成类与知识密集型任务 LLM 占优；检索增强可把闭卷任务变为开卷；CoT 提示可显著提升计算能力但无外部工具介入时仍会算错。论文还讨论了成本、延迟、参数高效微调（LoRA/Prefix Tuning/P-Tuning）以及幻觉、偏见、隐私等可信性问题，对团队而言是一份做技术选型与评测体系设计的地图式参考，而非具体方法论文。

问题

实践者和最终用户在下游 NLP 任务中使用 LLM 时缺乏系统性实践指导：面对具体任务应选择 LLM 还是微调小模型、如何依据预训练/微调/测试数据的情况做选型、各类 NLP 任务中 LLM 的适用与不适用场景是什么，以及真实部署时需权衡哪些效率（成本、延迟）与可信性（鲁棒性、公平性、安全性）因素。

方法

综述与经验总结：梳理 GPT-style（decoder-only）与 BERT-style（encoder-only/encoder-decoder）模型演化谱系；按标注数据可得性（zero/few/abundant）分场景给出模型选型建议；按任务类别（传统 NLU、生成任务、知识密集任务、scaling 相关能力、杂项任务、真实世界场景）逐一分析 use case 与 no use case 并形成决策流程图（decision flow）；讨论 in-context learning、CoT 提示、检索增强（闭卷转开卷）等使用手段；最后覆盖效率（训练/推理成本、延迟、参数高效微调）与可信性（鲁棒性与校准、公平性与偏差、虚假偏差、幻觉、有害内容、隐私）。

关键结果

GPT-4 在 MMLU（57 个学科）上取得 86.5% 准确率，大幅超越现有模型；在 ARC-C 上达到 96.3%，接近 100%

GPT-4 可通过 Leetcode 25% 的题目

训练 GPT-3 175B 单次约需 460 万美元，T5 11B 单次超过 130 万美元；GPT-3 175B 需 3.14×10^23 Flops，约为 T5 11B（3.30×10^22）的 10 倍

GPT-3.5-turbo 聊天服务定价 $0.002/1k tokens；自定义模型训练 $0.03/1k tokens、使用 $0.12/1k tokens

GPT-J 6B 在 max token size 为 2/8/32 时推理时间分别为 0.077s/0.203s/0.707s；InstructGPT davinci v2 在 token size 32 时为 1.969s，每请求 0.21s 的理想推理时间对 web 搜索引擎而言过慢

NER 任务 CoNLL03 上微调模型性能约为 LLM 的两倍；毒性检测 CivilComments 上最好的 LLM 也仅略好于随机猜测

GPT-3 的两位数加法能力在参数超过 13B 后才显现（涌现能力）

摘要任务上 LLM 在 ROUGE 等自动指标上不占优，但人类评估更偏好 LLM 生成结果；GPT-4 作为评估器与人类评分的相关性大幅高于其他方法，但 LLM 评估器可能偏向 LLM 生成的文本

创新点

区别于聚焦模型架构或训练技术的综述，本文以实践者视角组织内容：以 LLM 与 fine-tuned 模型的对比为主线，给出可操作的决策流程和系统的 use/non-use case 清单，并将成本、延迟、可信性等部署因素纳入统一讨论框架；同时维护持续更新的实践资源列表（GitHub 仓库）。
