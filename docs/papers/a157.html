PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers

PlanRAG：面向作为决策者的生成式大语言模型的先规划后检索增强生成（Plan-then-Retrieval Augmented Generation）

简介

论文研究如何让 LLM 端到端完成需要复杂数据分析的业务决策：给定决策问题、业务规则和放不进上下文的大型结构化数据库（RDB 或图数据库），回答最优决策，作者将此定义为 Decision QA 任务。由于缺乏可评测该能力的基准，作者从两款模拟真实商业情境的游戏（Europa Universalis IV 与 Victoria 3）构建了 DQA 基准，含 Locating 与 Building 两个场景共 301 个问题，并用自研确定性模拟器自动标注答案。方法上提出 PlanRAG：在 ReAct 提示结构上加入 Plan 与 Re-plan 指令，让单个 LM 先制定数据分析计划，再生成 SQL/Cypher 查询检索数据，并在计划不足时迭代重规划。实验显示 PlanRAG 超越 SOTA 迭代式 RAG：Locating 场景提升 15.8%、Building 场景提升 7.4%，且重规划对精度贡献显著。核心结论是'先规划后检索'能系统性减少候选遗漏与漏检错误，但规划本身仍是主要瓶颈，且方法对模型能力要求较高。

问题

现有 RAG 方法主要面向知识型 QA，只做'检索-作答'式推理，不擅长决策制定中最难的一步——规划需要做哪些数据分析（决策三步骤中的 Step 1）；同时缺乏能考察 LLM 决策能力的基准。论文目标是让 LLM 端到端完成决策制定的全部三步：规划分析、用查询检索数据、基于数据作答，并定义 Decision QA 任务与 DQA 基准来衡量这一能力。

方法

提出 PlanRAG（迭代式 plan-then-retrieval RAG），用单个 LM（GPT-4）实现两种推理。将 ReAct 提示结构扩展为 'Plan'-'Thought'-'Action'-'Observation'-'Re-plan'：(1) Planning：输入 ⟨Q, S, R⟩（问题、数据库 schema、业务规则）生成初始数据分析计划；(2) Retrieving & Answering：结合计划生成数据查询，经 LangChain/LlamaIndex 接口以 SQL/Cypher 执行于 MySQL/Neo4j，用检索结果迭代推理是否继续检索或作答；(3) Re-planning：参考各检索步骤结果评估当前计划，必要时生成新计划或修正分析方向，循环直至作答。同时构建 DQA 基准（Locating/Building 两场景，每个数据库有 RDB 与 GDB 双版本共 602 个），并开发确定性模拟器对最优决策做标注。

关键结果

PlanRAG 相比 SOTA 迭代式 RAG（IterRAG）：Locating 场景准确率提升 15.8%，Building 场景提升 7.4%

去除重规划（PlanRAG w/o RP）导致准确率下降：Locating 降 10.8%，Building 降 0.9%，证明重规划对决策 LM 重要

SingleRAG-LM 在超过 60% 的 Locating 问题和 95% 的 Building 问题上未能从数据库检索到任何结果

关键数据漏检率：PlanRAG-LM 为 1.3%（Locating）与 21.8%（Building），低于 IterRAG-LM 的 3.3% 与 33.2%

重规划频率：Locating 中 6% 的问题（24/400）触发重规划，Building 中 38%（77/202）；且重规划次数越多，带来的准确率提升越低

模型能力门槛：Llama-2（70B/13B）与 Phi-2 无法解出任何 DQA 问题；GPT-3.5 上 IterRAG 反而优于 PlanRAG，原因是 PlanRAG 提示过于复杂

提示结构消融（各场景 10% 抽样）：'Plan'-'Thought'-'Action'-'Observation'-'Re-plan' 结构优于去掉 Thought 的变体与先 Thought 后 Plan 的变体

失败案例分析：PlanRAG-LM 显著减少 CAN（候选考虑不当）与 MIS（漏检）错误，但 DEEP（数据/公式误用）错误略有增加，作者归因于前两类错误减少的副作用

创新点

与已有工作的区别：(1) 现有单轮/迭代式 RAG 面向知识型 QA，PlanRAG 首次在检索前加入显式规划步骤，并支持基于检索结果的重规划，形成'规划-检索-重规划'的双推理类型循环；(2) 首次提出 Decision QA 任务与 DQA 基准，要求 LM 对带业务规则的大型结构化数据库（RDB/GDB）做查询式决策，而现有 Tabular QA/Table NLI 基准不考虑业务规则、且每表行数远小于 DQA。
