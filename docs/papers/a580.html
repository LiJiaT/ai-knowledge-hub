Deliberate then Generate: Enhanced Prompting Framework for Text Generation

先审慎后生成（Deliberate then Generate）：面向文本生成的增强提示框架

higharXiv提示技术思维链与推理基于arXiv版本
下载原文 PDF

简介

论文针对现有提示方法通常只向 LLM 提供正确信息、模型收到指令后直接生成结果的问题，提出 Deliberate then Generate（DTG）提示框架：在提示中加入错误检测指令和一个可能含错误的候选输出，要求模型先检测错误类型、再给出改进后的结果。关键设计发现是候选与参考差异越大越能触发模型的审慎能力，因此直接用空字符串或随机文本作候选即可，无需额外基线系统构造纠错样本。在 GPT3.5（text-davinci-003）与 GPT4 上覆盖 7 个生成任务、20+ 数据集的实验中，DTG 一致优于标准提示，并在机器翻译、文本简化、CommonGen 上取得 SoTA，还能把 MS-Translator 的 COMET 从 80.4 提升到 81.65。对团队而言，这是一种提示改动极小、可跨任务复用的提示模式，适合沉淀进生成类工作流的提示词资产。

问题

现有 prompting 方法通常只基于正确信息运作（LLM only operates on the basis of what is correct），模型直接从输入生成结果；论文探究能否借鉴人类从正负反馈中学习语言的机制，让 LLM 在生成前先对一个可能含错误的候选输出进行错误检测与审慎思考（deliberation），从而提升文本生成质量，且不依赖额外系统来构造纠错样本。

方法

DTG 提示框架由三部分组成：1）简洁明确的任务指令；2）一个可能含错误的候选输出（[SYS]）；3）要求模型先检测错误类型再给出改进结果的指令（'Please detect the error type firstly, and provide the refined results then'）。核心设计在于候选的选择：实验发现候选与参考的相似度（按 edit distance 衡量）越高效果越差，因此用随机采样文本甚至空字符串作为候选即可有效触发 deliberation，摆脱对额外基线系统的依赖，只需对提示做最小修改即可迁移到翻译、摘要、对话摘要、风格迁移、简化、改写、常识生成等任务。论文还验证了 DTG 作为 refiner 改进其他系统输出的用法。

关键结果

在 GPT3.5（text-davinci-003）与 GPT4 上、7 个文本生成任务 20+ 数据集中，DTG 一致优于标准提示，并在机器翻译、文本简化、常识生成等多个任务上取得 SoTA

机器翻译：5-shot 下 DE-EN、ZH-EN、UK-EN 等 to-English 语言对 BLEU 显著提升，DTG 在 COMET-22 上超过 WMT-Best 系统；低资源 IS-EN、HA-EN 亦一致提升

风格迁移：GYAFC 的 EM/FR 任务 BLEU 较标准提示分别提升 8 分和 10.04 分，BLEURT 超过 BART（分别 +0.98 与 +0.32）

文本简化：在 Asset 与 Wiki-auto 上同时提升 BLEU 与 SARI，建立新 SoTA

CommonGen：平均提升 3.50 BLEU 与近 2.00 Rouge，建立新 SoTA

消融实验：去掉错误检测指令导致 BLEU 显著下降；固定错误类型导致 1.1 BLEU 下降；用模型自身生成的正确候选作输入不能超过标准提示

作为 refiner：在 WMT ZH-EN 上将 MS-Translator 的 COMET 从 80.4 提升至 81.65

错误统计分析：DTG 降低了 under translation 与 entity translation 两类错误率

GPT4 上 DTG 仍然有效，但提升幅度略小于 GPT3.5

创新点

与只提供正确信息的传统提示不同，DTG 引入'负证据'——一个可能含错误的候选输出——来触发 LLM 的审慎与纠错能力；关键发现是候选与参考差异越大效果越好，因此用空字符串即可，无需额外系统构造纠错样本。与 CoT 等多步推理提示不同，论文指出 CoT 在机器翻译、摘要等一般生成任务上已被证明无效，而 DTG 无需任务特定设计即可跨任务一致提升。
