How to Prompt LLMs for Text-to-SQL: A Study in Zero-shot, Single-domain, and Cross-domain Settings

如何为 Text-to-SQL 提示 LLM：Zero-shot、Single-domain 与 Cross-domain 设置下的研究

简介

该论文解决以往 text-to-SQL 研究中 prompt 构造方式五花八门、结果无法横向比较的问题，在 zero-shot、single-domain、cross-domain 三种设置下，系统评测了数据库 schema 表示（Table(Columns)、Columns=[]、+ForeignKey、CreateTable）、表内容表示（InsertRow、SelectRow、作者提出的按列去重 SelectCol）以及 cross-domain 示例组织（M 个数据库×每库 K 条）对 Codex 与 ChatGPT 执行准确率的影响。关键结论：外键关系与表内容是有效 prompt 的关键知识；in-domain 示例能让模型快速学到表关系、却学不到表内容，因此表内容需始终显式提供；prompt 长度存在 sweet spot，Codex 超过约 5500 tokens、ChatGPT-16K 超过约 11K tokens（约 70% 最大上下文）后性能显著下降。对团队而言，这是关于'上下文里该放什么、放多少'的一份直接实证参考。

问题

以往基于 LLM 的 text-to-SQL 研究在构造 prompt 时各自采用不同策略（数据库 schema 与内容的表示方式、示例的组织方式），导致研究之间缺乏可比性、难以判断各自的真实贡献，且'如何选择有效的 prompt 构造'成为后续研究的持续难题。本文旨在系统回答在不同设置下应如何构造 text-to-SQL 的 prompt。

方法

在 Spider-dev（20 个数据库、1034 对 NLQ-SQL）上以执行准确率（EX）为指标做控制变量实验：比较 4 种 schema 表示（Table(Columns)、Columns=[]、+ForeignKey、CreateTable）与 3 种表内容表示（InsertRow、SelectRow、作者提出的按列去重 SelectCol）；cross-domain 下将示例组织为 M 个示范数据库×每库 K 条（M×K=N）并扫描组合；对 prompt 与 SQL 做归一化（小写、统一空白）以减少 token；用 McNemar 检验差异显著性；模型为 GPT-3 Codex（code-davinci-002）与 ChatGPT（gpt-3.5-turbo-0301，cross-domain 另测 16k-0613）。

关键结果

Zero-shot 下加入外键关系提升明显：Columns=[]+ForeignKey 相比 Columns=[]，Codex 从 71.8 升至 73.1，ChatGPT 从 69.1 升至 71.2（多数对比 p<0.05）

Zero-shot 下 CreateTable+SelectCol 相比 CreateTable 对 Codex 提升 2.0%、对 ChatGPT 提升 1.7%；SelectCol 3 相比 InsertRow 3 对 Codex 高 3.8、对 ChatGPT 高 1.8

Single-domain 下 in-domain 示例带来显著提升且随示例数（1/4/8/16）持续上升；16 个示例时表关系表示的差距对 Codex 完全消失、对 ChatGPT 仅剩 0.5%，但表内容差距仍保持 1.3（Codex）/1.9（ChatGPT）

仅 4 个 in-domain 示例即可将 SelectCol 3 与 InsertRow 3 的差距缩小到 0.3（Codex）/0.2（ChatGPT），即示例增多后模型对表内容表示方式不再敏感

Cross-domain 下示例数或数据库数超过阈值后性能显著下降；准确率随 prompt 长度呈倒 U 形，Codex 约在 5500 tokens、ChatGPT-16K 约在 11K tokens 后开始下降，约在最大上下文 70% 处出现衰退

归一化在 Codex 全部构造及 ChatGPT 7 种构造中的 6 种上减少 token 并持平或提升准确率，但差异未达统计显著（p>0.05）

Zero-shot 下 Codex 在所有 prompt 构造上一致优于 ChatGPT

创新点

不同于以往提出单一增强手段（相似度示例检索、中间推理步骤、self-debugging）的工作，本文在统一实验协议下把'prompt 构造本身'作为研究对象，覆盖 zero-shot/single-domain/cross-domain 三种设置与更广的数据库范围（相比 Rajkumar et al. 2022 仅在 Spider zero-shot 和两个单域数据库上的分析）；并提出按列去重展示表内容的 SelectCol 表示，同时报告了 prompt 长度 sweet spot 现象。
