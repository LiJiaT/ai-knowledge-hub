简介

这篇综述系统梳理了 In-context Learning（ICL）这一 LLM 核心使用范式：模型通过在上下文中拼接少量示例即可完成预测，无需参数更新。论文给出 ICL 的形式化定义，并从四个维度建立分类体系：模型训练（pretraining 与 warmup，如 instruction tuning）、提示设计（示例选择/重格式化/排序、指令格式化、打分函数）、机理分析（影响因素与贝叶斯/梯度下降等学习机制解释）、应用（数据工程、模型增强、知识更新）。关键结论包括：ICL 性能对示例的选择、顺序与格式高度敏感；论文自做的对比实验表明示例选择方法的有效性依赖具体模型；增加示例数量并不必然提升性能，长上下文场景甚至可能有害。对团队而言，这是一份关于如何组织 few-shot 上下文与设计提示的系统性路线图。

问题

ICL 研究快速增长但缺乏系统性梳理。论文旨在为社区提供 ICL 的正式定义、与相关概念（Prompt Learning、Few-shot Learning）的区分、先进技术（训练策略与提示设计策略）的分类总结、机理分析、应用场景以及挑战与未来方向，帮助研究者理解 ICL 如何工作并改进 ICL。

方法

作为综述，论文建立 ICL 分类体系：1) 模型训练：通过 pretraining/continual pretraining 与 warmup 阶段（多任务微调、symbol tuning、FLAN 式 instruction tuning）增强 ICL 能力；2) 提示设计：示例选择（无监督方法如基于 kNN 的 KATE、互信息、困惑度，监督方法如 EPR、基于 Q-learning 的强化学习选择）、示例重格式化（LLM 生成示例、Structured Prompting、In-Context Vectors）、示例排序（熵度量、由简到繁的 ICCL）、指令格式化（Automatic Prompt Engineer 自动生成与筛选指令、CoT 中间推理步骤）、打分函数（Direct/PPL/Channel 三种）；3) 分析：影响因素（预训练数据多样性、示例构造）与学习机制（induction heads、贝叶斯视角、梯度下降对偶视角）；4) 应用与挑战（效率与可扩展性、泛化、长上下文 ICL）。论文还基于 OpenICL 框架在 4 个模型上公平对比了 topk/votek/mdl 三种示例选择方法。

关键结果

论文自做实验：在 gpt2、gptj、LLaMA3-8B-Instruct、Qwen2-7B-Instruct 上使用 8 个示例对比 topk/votek/mdl，发现示例选择方法的有效性依赖具体模型：GPT-2 上 mdl 最佳，其余三个模型上 topk 最佳

引用结果：通过 ICL，最佳模型已在 BIG-Bench 65% 的任务上超过人类评分者平均报告结果

BBH 包含 23 个 SOTA 模型表现远低于人类的未解决任务；OPT-IML Bench 包含来自 8 个基准的 2000 个 NLP 任务

FLAN 在 137B LaMDA-PT 上用超过 60 个数据集做指令微调，同时提升 zero-shot 与 few-shot ICL 性能；后续工作将指令规模扩展到 1000+ 任务

创新点

据作者所知是首篇专门针对 ICL 的综合性综述（2022 年底首发于 arXiv，经四次大版本持续更新）。区别于后续聚焦示例检索、提示工程实践建议或纯理论解释的相关综述，本文覆盖 ICL 的形式化定义、训练策略、提示设计、机理分析与应用全景，并补充了多种无监督示例选择方法在同一实验设置下的公平对比。

团队参考意义

相关度级别：high

命中能力域：3.1 上下文工程与记忆 | 3.2 提示工程 | 3.5 评测与可靠使用

理由：ICL 是团队 3.1（上下文工程）与 3.2（提示工程）的理论与工程基础：few-shot 示例的选择、排序与格式化本质上就是上下文组织问题，基于 kNN/相似度的示例检索与 RAG 的检索增强思路同源；Automatic Prompt Engineer 等指令自动生成对应自动提示优化；CoT 对应推理提示。在 3.5 方面，综述系统覆盖 ICL 评测基准（BIG-Bench/BBH/MGSM/LongICLBench/OPT-IML Bench）、三种打分函数的效率与稳定性对比、order sensitivity 等可靠性问题，以及 ICL 用于引导更安全输出的讨论。虽然不直接涉及 Agent 架构与多智能体协作，但 ICL 是所有 Agent 提示与上下文设计的底层方法。
