IM-RAG: Multi-Round Retrieval-Augmented Generation Through Learning Inner Monologues

IM-RAG：通过学习内心独白（Inner Monologues）实现多轮检索增强生成

简介

论文针对 RAG 系统在适配能力各异的 IR 系统、多轮检索过程可解释性不足、缺乏端到端优化三方面的问题，提出 LLM 为核心的 IM-RAG 框架。方法上让 LLM 作为 Reasoner 在 Questioner 与 Answerer 两个角色间切换：信息不足时生成检索 query，充分时给出最终答案；引入 Refiner 对 Retriever 输出做重排与格式化以弥合 IR 模块与 LLM 的差距，并用 Progress Tracker 基于余弦相似度提供中间步奖励，通过 RL（PPO）训练 Questioner、SFT 训练 Answerer。在 HotPotQA 上取得 SOTA，F1 达 82.5%，比同结构但不做多轮检索的基线（41.2%）近乎翻倍，去掉 Refiner 会带来 14.2% 的 F1 下降。对团队而言，其"何时继续检索、何时作答"的切换机制与"检索结果精炼后再注入上下文"的做法，可直接借鉴到知识库问答与检索 Agent 的工具调用流程中。

问题

RAG 范式虽能借助外部知识缓解 LLM 的生成幻觉与知识静态问题，但存在三点不足：难以灵活适配能力各异的 IR（信息检索）系统、多轮检索过程可解释性受限、缺乏端到端优化。已有 prompting 方法简单灵活但无法针对具体搜索引擎做端到端优化（改进 query 改写模块未必带来更好检索效果）；基于人工标注多轮检索记录的训练方法需要大量标注数据与训练成本，且对需要多步推理、多轮检索的复杂问题难以收集标注。

方法

提出 LLM-centric 的 IM-RAG 框架，把 Inner Monologue 从 QA 对话推广为 Reasoner 与 Retriever 之间任意形式的通信，含四个组件：(1) Reasoner：同一 base LLM（Vicuna-1.5 7B）上挂 Questioner 与 Answerer 两个 LoRA adapter，前者经 RL（PPO）学习把复杂问题分解为依赖上下文的多轮子查询，后者经 SFT 专责最终作答；(2) Retriever：可插拔（实验用 Sentence-transformer + FAISS 的 DPR）；(3) Refiner：用 RankVicuna 对检索结果重排/改写/过滤，弥合 IR 模块与 LLM 在格式、长度、重要性上的差距；(4) Progress Tracker：基于与 golden 支撑文档的余弦相似度给每轮检索打分，累积分数超过阈值 φ_r=0.3 或达到最大轮数 N_max=3 时由提问切换为作答。整个 IM 过程以中间步距离分数、最终答案 F1 与 KL 惩罚为奖励做端到端优化。

关键结果

在 HotPotQA 上取得 SOTA，F1 达 82.5%，相对此前最佳模型有 1.9% 的相对提升；因未重点微调 IR 模块，Passage EM 等检索指标落后于第二组基线

与同模型、同结构但不做多轮检索的 RAG (no IM) 基线相比，F1 从 41.2% 提升到 82.5%

GPT-3.5（4-shot、未接外部知识）在 EM 与 F1 上分别落后 RAG (no IM) 基线 0.2% 与 4.1%；REACT（PaLM-540B）因缺乏任务特定优化不占优势

消融：去掉 Refiner 导致 F1 下降 14.2%（68.3% vs 82.5%）；去掉 Answerer SFT、仅用 Questioner 作答得 F1 77.9%，下降 4.6%

去掉 Questioner 的 RL、改用 prompting 触发多轮检索时，vicuna-7b 在大量数据点上无法按期望格式输出 query，系统无法工作

McNemar 检验显示 IM-RAG 相对 no-IM、GPT-3、no-SFT、no-Refiner 的提升均统计显著

Retriever 侧 FAISS 相似检索在 GPU 环境下平均每 query 0.061 秒

创新点

相对 IMMO 等仅支持 QA 对话式 Inner Monologue 的工作，IM-RAG 把 IM 推广到 Reasoner 与 Retriever 间任意结构化/非结构化形式（文本块列表、排序结果、标量分数）的通信，并首次在多轮 RAG 中引入 Progress Tracker 提供中间步奖励，以改善 PPO 在多步过程中的优化效率；相比 AISO、CoS 等绑定预定义 IR 系统、换域需重训的方法，通过可学习的 Refiner 适配器实现 IR 模块即插即换，且无需人工标注多轮检索记录即可用 RL 端到端优化，兼顾灵活性、可解释性与性能。
