Signals: Trajectory Sampling and Triage for Agentic Interactions

Signals：面向 Agent 交互的轨迹采样与分诊框架

简介

已部署的 Agentic 应用会产生海量且非确定性的多步交互轨迹，逐条人工审查不可扩展、对每条轨迹调用 LLM-as-a-judge 成本过高，导致上线后的改进主要依赖手工检查轨迹、猜测失败模式。论文提出轻量级的 signal 分诊框架：把轨迹信号按 discourse/execution 数据层与学习/诊断用途组织为 interaction（misalignment、stagnation、disengagement、satisfaction）、execution（failure、loop）、environment（exhaustion）三组，全部用确定性规则计算、无需模型调用，作为结构化属性在不影响线上 Agent 行为的前提下挑出最值得开发者审查的轨迹。在 τ-bench 上的三人盲评实验中，signal 采样的 informativeness rate 达 82%，高于 heuristic 的 74% 与随机采样的 54%，每条有效轨迹的标注成本对应 1.52× 效率提升，且优势在成功/失败 reward 分层与更难的 retail 域中均稳健。对团队而言，这是一种可常驻、近零开销的 Agent 产出质量分诊基础设施，可直接用于上线后轨迹筛选、执行可靠性监控与偏好数据构建的第一级。

问题

生产环境的 Agentic 系统捕获了丰富的行为轨迹（推理步骤、工具调用、执行结果、用户响应），但缺乏把其转化为改进信号的机制：人工审查不可扩展，对每条轨迹运行辅助 LLM（LLM-as-a-judge）成本过高，离线评测基准又覆盖不了真实使用的长尾。结果是已部署 Agent 的改进仍以手工方式进行——开发者逐条看轨迹、假设失败模式、迭代 prompt 或工具定义，没有连接生产数据与偏好学习（RLHF/DPO）的结构化流水线。

方法

提出轻量级、基于信号的轨迹分诊（triage）框架。信号按两个正交轴组织：数据层（discourse 层 vs execution 层）与下游用途（学习导向 vs 诊断导向），得到三组信号：1) Interaction Signals（misalignment、stagnation、disengagement、satisfaction，学习导向，来自用户-助手自然语言）；2) Execution Signals（failure、loop，学习导向，来自工具调用/运行事件等结构化观测，通过非推进性工具结果分类与调用序列模式规则检测）；3) Environment Signals（exhaustion，诊断导向，识别配额、宕机、上下文上限等外部约束，不作训练监督）。所有信号由确定性规则计算（归一化、容错匹配、话语启发式、序列分析），零模型调用，作为结构化元数据附加到轨迹。信号不是质量分数，只标记'可能含信息量'的轨迹（同时覆盖失败与优秀样本），用于在固定标注预算下优先采样供人审查；论文还提出通过 counterfactual continuations 把选中轨迹转化为偏好对路径。

关键结果

在 τ-bench 上（每种方法各采 100 条、三人盲评、多数投票），signal 采样 informativeness rate 为 82.0%（95% CI [.73, .89]），heuristic 为 74.0%，random 为 54.0%；signal vs random 显著（p<0.001），signal vs heuristic 未达显著（p=0.232）

按 reward 分层：失败轨迹上 signal 达 96.2%；成功轨迹上 signal 66.7% vs heuristic 50.0% vs random 41.3%；反事实标准化（对齐 random 的 63%成功/37%失败分布）后 signal 77.6% vs heuristic 62.7% vs random 54.0%，说明优势并非来自过采样失败轨迹

标注效率：每得到一条有效轨迹，signal 需 1.22 次标注，heuristic 1.35，random 1.85，相对 random 为 1.52× 效率提升

域稳健性：retail 域（任务更复杂、基础信息率更低）signal 78% vs heuristic 66% vs random 35%；airline 域三者均在 86%–96%

标注一致性：binary 判定的三人 Gwet's AC1=0.477（中等）；在三人一致认为有信息量的 130 条轨迹上，主原因分类 Fleiss' κ=0.662、Gwet's AC1=0.829

有效轨迹的原因分布在三种策略间稳定：action/tool-use 行为问题占 57–60%，conversation 问题占 38–43%，另有少量 success exemplar

创新点

与 LLM-as-a-judge、Agent-as-a-Judge、process reward models 等需对每条轨迹做模型调用或昂贵标注的方法不同，本文信号全部由确定性规则计算、零模型调用，可常驻部署且不修改线上 Agent 行为；与已有对话质量指标工作不同，本文显式区分 discourse 层与 execution 层（Agent 可能对话流畅但执行上灾难性失败），且信号不产出质量分数、不预设修复方案，只做'信息量'分诊以同时暴露失败与优秀样本。论文定位于可观测性与优化之间的接口（observability–optimization interface），并把执行层信号（工具调用失败、循环）作为此前未被充分利用的训练信号来源，面向偏好数据构建的上游采样环节。

Abstract

基于大语言模型（LLM）的 Agentic 应用日益依赖于涉及规划、动作执行与环境反馈的多步交互循环。尽管此类系统如今已大规模部署，但部署后的改进仍然充满挑战。Agent 轨迹数量庞大且具有非确定性，而要对每条轨迹进行审查——无论是通过人工审查还是借助辅助 LLM——都既缓慢又成本高昂，令人难以承受。我们提出了一种轻量级的基于信号的框架，用于对 Agentic 交互轨迹进行分诊（triage）。我们的方法从实时交互中计算廉价且具有广泛适用性的信号，并将其作为结构化属性附加到轨迹上以支持轨迹分诊，从而在不影响在线 Agent 行为的前提下识别出可能具有信息量的交互。我们将这些信号组织成一个粗粒度的分类体系，涵盖交互类（不对齐、停滞、脱离、满意度）、执行类（失败、循环）与环境类（耗尽），并设计为无需调用模型即可完成计算。在 τ-bench 这一被广泛用于工具增强 Agent 评估的基准测试（benchmark）上开展的一项受控标注研究中，我们表明基于信号的采样达到了 82% 的信息量比率，相比之下启发式过滤为 74%、随机采样为 54%，且每条有信息量的轨迹可获得 1.52× 的效率增益。这一优势在不同奖励层级和任务领域中均保持稳健，证实了信号带来的是真实的逐轨迹信息量增益，而并非仅仅是对明显失败的过度采样。这些结果表明，轻量级信号可以充当 Agentic 系统实用的采样基础设施，并为偏好数据构建与部署后优化指明了一条路径。

1 Introduction

Agentic 应用将 LLM 推理与工具执行结合于多步交互之中 [13, 18]。随着这些系统进入真实世界的部署，改进它们需要将观察到的行为转化为优化信号。已部署的 Agent 会大规模生成详细的行为数据，涵盖推理步骤、工具调用、执行结果和用户响应。与此同时，诸如 RLHF [9] 和 DPO [11] 等基于偏好的训练方法，在给定恰当构建的偏好数据的情况下，为改进 LLM 行为提供了经过充分研究的机制。然而，在 Agent 产生的行为数据与能够消费这些数据的偏好学习方法之间，仍然存在鸿沟。生产系统捕获丰富的轨迹，却没有提供将其转化为训练信号的机制。偏好学习流水线需要经过整理的比较数据，却没有从生产环境中系统化获取这些数据的途径。其结果是，改进已部署的 Agent 在很大程度上仍然以人工为主。开发者手工检查轨迹、对故障模式提出假设，并在提示词或工具定义上进行迭代，而没有将两者连接起来的结构化流水线。

这种脱节之所以持续存在，有以下几个原因。离线评估虽然对测试已知场景很有价值，但它依赖于经过整理的基准测试（benchmark），而这些基准测试遗漏了真实世界使用中的长尾部分 [17, 10]。人工审查无法规模化。Agent 轨迹数量庞大且具有非确定性，并且没有可靠的指标来检测 Agent 何时陷入无效循环或用户何时变得沮丧。一种自然的替代方案是使用辅助 LLM 来评估每条轨迹，正如 LLM-as-a-judge 方法 [20] 所展示的，其在结构化任务上与人类偏好的一致性超过 80%，但将这种评估应用于每条轨迹在大规模场景下成本过高。先前关于对话质量的工作提出了从对话特征中导出的自动质量指标 [5, 14]，但这些方法所做的假设在 Agentic 系统中并不成立。首先，它们将对话视为全部图景，而 Agent 则将话语层（用户意图、澄清、沮丧）与执行层（工具调用、API 响应、状态变更）交织在一起。Agent 可以在执行上遭遇灾难性失败的同时，仍保持流畅而友好的对话。其次，它们假设信号应当产生质量评分或给出修复方案，但质量判断是依赖于上下文的。简洁的回复对专家用户而言可能很理想，但对新手来说却可能令人沮丧，而将此类判断嵌入系统中有可能编码那些无法跨领域泛化的假设。

我们提出使用由轻量级轨迹信号组合而成的分诊（triage）函数来弥合这一脱节。信号是对重复出现的行为模式的描述性标记，涵盖交互（未对齐、停滞、脱离、满意）、执行（失败、循环）与环境（耗尽）三个层面，无需调用模型即可计算，并可作为结构化元数据附加到轨迹上。交互信号与执行信号面向学习，适合用于构建偏好数据，而环境信号则支持系统级诊断，但不作为训练监督。至关重要的是，信号并非质量分数。它们识别的是那些可能对下游分析具有信息量的轨迹，既呈现失败案例，也呈现范例，而不断言正确性，也不指定修复方案。这一设计借鉴了信息检索领域的悠久传统：在该领域中，查询重构、停留时间和会话放弃等隐式行为信号一直被用作用户满意度的代理指标，而无需显式反馈 [2, 6]。我们将这一思想适配到 Agentic 场景中，在该场景下，轨迹不仅包含自然语言，还包含工具调用、执行结果和环境反馈。

2 Related Work

来自行为数据的自动质量信号。当显式用户反馈或真值奖励不可用时，系统必须依赖从轨迹本身导出的信号。在对话系统中，对话崩溃检测挑战赛（Dialogue Breakdown Detection Challenge）[4] 组织了共享任务，利用对话行为类型和连贯性度量等特征来识别不恰当的系统话语。在信息检索领域，查询重构和会话放弃等隐式信号长期以来一直被用作满意度的代理指标。在 Agentic 场景中，Watson [12] 为大语言模型（LLM）驱动的智能体引入了认知可观测性（cognitive observability），通过代理模型恢复隐式推理轨迹，以支持诊断和针对性纠正，但需要对每条轨迹进行模型调用。我们的行为信号（包括重复、修复和挫败模式）将来自对话和检索领域的隐式信号思想适配到 Agentic 场景中，在该场景下，轨迹不仅包含自然语言，还包含工具调用、执行结果和环境反馈。我们的执行层信号，例如工具调用失败和失败模式，可直接从结构化轨迹记录中提取，但作为训练信号仍未得到充分利用。尽管已有工作分别研究了智能体架构、自我改进、偏好优化和可观测性，但对可观测性与优化之间接口的关注却较少。我们的工作正是针对这一空白：我们将轻量级、无模型的轨迹信号组合成一个面向异构智能体轨迹的分诊（triage）函数，筛选出对开发者具有信息量的轨迹，这些轨迹可作为偏好数据构建的基础。

3 Signal Taxonomy

我们提出了一种粗粒度的轨迹信号分类体系，以及一种从可观测轨迹中实例化这些信号的轻量级检测流程。我们将信号定义为反复出现的行为模式的描述性标记，这些模式使轨迹对下游分析和偏好数据构建具有潜在的信息价值。重要的是，它们并非用于衡量正确性、奖励或质量。我们沿两个正交的轴来组织轨迹信号：信号所源自的数据层，以及其下游用途。第一个轴区分从轨迹的话语层（discourse layer，即用户-助手自然语言）导出的信号与从执行层（例如工具调用、运行时事件）导出的信号。第二个轴区分对学习有用的信号（即用于构建偏好数据和改进智能体策略）与主要用于诊断和系统可观测性的信号。由此得到三个顶层信号组：1) Interaction Signals（面向学习）、2) Execution Signals（面向学习）和 3) Environment Signals（面向诊断）。这种分类反映的是信号在计算方式与预期用途上的差异，而非对智能体行为的概念性划分；单条轨迹可能同时表现出来自多个信号组的模式。该分类体系有意采用粗粒度：我们将许多范围狭窄的启发式规则归并为少量反复出现的模式，以便在不同实现之间进行泛化，并支持可扩展的分诊。

3.1 Interaction Signals

定义。交互信号（interaction signals）由用户与助手之间的自然语言计算得出，刻画交互在语篇层面的展开方式。它们反映面向用户的行为与合作动态，而不对智能体的内部状态或语义正确性作出断言。这些信号适用于偏好学习（preference learning），因为它们揭示了用户能够直接辨识的成功与失败模式。

3.3 Environment Signals

定义。环境信号捕获源自周围系统而非 Agent 内部策略或推理的故障与约束。其中包括基础设施、API 和资源边界条件。我们将这些信号单独分离出来，是因为它们虽然对可观测性和诊断至关重要，却并不适合用作训练监督：它们并不反映 Agent 决策的质量，若用于学习还可能引入虚假相关性。需要注意的是，如果事件主要由系统约束或服务健康状况（配额、服务中断、上下文上限）来解释，我们将其归类为 Environment；否则归类为 Execution。

4 Experiment

我们将所提出的信号框架作为一种数据选择机制进行评估，该机制可置于偏好构建与训练的上游。我们并非将信号作为分类器或质量评分器加以评估，而是探究它们能否充当实用的采样基础设施：识别哪些轨迹值得人工审查，而无需语义理解或显式奖励建模。具体而言，我们旨在验证如下论断：在固定标注预算下，信号采样相比基线策略能够呈现出更高比例的对开发者具有信息价值的轨迹，从而揭示出那些否则会被稀释或完全遗漏的有意义的成功或失败模式。

4.1 Experiment Setup

Trajectory Pool. We use τ -bench [17] as our testbed, a benchmark that emulates multi-turn conversations between a simulated user and a tool-equipped agent across two domains (i.e., airline and retail). Its trajectories contain both discourse-level interaction (user-agent dialogue) and structured execution events (tool calls, API responses, database mutations), exercising all signal categories in the proposed framework. We construct the trajectory pool from τ -bench's publicly available historical trajectories, generated by multiple agent configurations (varying model backbones and prompting strategies) across all benchmark tasks. The resulting pool naturally includes both successes and failures. We denote the total pool size as N and draw fixed-size samples of n = 100 trajectories per method. We note that τ -bench uses LLM-simulated users rather than real ones; certain interaction signals, particularly disengagement and satisfaction, may therefore be under-represented relative to real-world traffic.

Sampling Strategies. We compare three sampling methods, each drawing 100 trajectories:

All three sampling strategies draw the same number of trajectories ( n = 100 ), ensuring that any difference in annotation yield is attributable to the sampling strategy rather than annotation volume.

Annotation Protocol. Three expert annotators, each familiar with agentic systems and tool-use patterns, independently label all 300 trajectories. Trajectories from all conditions are shuffled into a single queue and annotators are blinded to which sampling strategy produced each trajectory. 4.2 Results and Analysis

标注者间一致性。在报告结果之前，我们评估了标注的可靠性。各标注者判为YES的比率介于0.57至0.74之间，由此得到流行度指数（prevalence index）为0.34、偏倚指数（bias index）为0.17。已知这两个因素即使在原始一致性充分的情况下也会压低κ族统计量[1]；因此，我们采用能够校正这些效应的Gwet's AC1[3]作为主要一致性系数。对于二元的“对开发者有信息量”这一问题，三位评分者的Gwet's AC1为0.477，表明一致性处于中等水平。由于该问题需要对一个分级的主观属性进行二元切分，分歧集中在那些证据存在但可操作性模糊的边界轨迹上；因此，该中等数值反映的是阈值上的分歧，而非缺乏共同理解。这一解释得到了主要原因类别的证实：在三位标注者一致认为某条轨迹具有信息量的条件下（N = 130），Fleiss' κ = 0.662，Gwet's AC1 = 0.829，表明一旦标注者一致认为某条轨迹值得考察，他们便能可靠地识别出相同的潜在问题。我们在所有后续分析中均采用多数投票聚合。

主要结果。表1报告了三种采样策略各自的信息量率，每种策略均在100条轨迹的固定预算下进行评估。信息量率是指被标注者判定为包含对开发者可操作信息的采样轨迹所占的百分比。所有置信区间均为Clopper-Pearson 95%区间，该区间对二元结果保证精确的覆盖率；所有成对比较均使用Fisher精确检验（双侧），以确保在不依赖渐近近似的前提下保证有效性。

信号采样取得了最高的总体信息量率（82.0%，95% CI [.73, .89]），这意味着它所选出的轨迹中大约每五条就有四条能提供有用的诊断或行为证据。相比之下，启发式采样达到74.0%，而随机采样仅为54.0%。信号采样与随机采样之间的差异高度显著（p < 0.001），证实在固定标注预算下，信号采样能挖掘出明显更多对开发者有信息量的轨迹。信号采样与启发式采样之间的差异未达到显著性水平（p = 0.232）；然而，正如我们接下来将要展示的，一旦按任务奖励进行分层，这两种策略在实现其信息量率的方式上便截然不同。

奖励分层分析。τ-bench 中的每条轨迹都带有一个二元奖励：只有当最终数据库状态与真实结果完全一致、且 Agent 的回复包含所有必需信息时，该轨迹才被视为成功。按此奖励进行分层，揭示了三种采样器之间的一个关键构成差异。如表 1 所示，启发式采样主要选中失败的轨迹（70% 的轨迹 reward = 0），而随机采样则反映了轨迹池的基础比率（37% 失败）。Signal 采样则抽取到更为均衡的混合样本（52% 失败）。这一构成差异具有重要意义。

在失败的轨迹中，所有策略都达到了较高的信息价值率（75.7% - 96.2%），其中 Signal 采样高达 96.2%。而在成功的轨迹中，实际差距更为明显，三种策略在此分化最大：Signal 采样在 66.7% 的成功轨迹中识别出具有信息价值的模式，相比之下启发式采样为 50.0%，随机采样仅为 41.3%。这些正是那些微妙的行为问题，例如策略违规和低效的工具调用，它们虽不妨碍任务完成，但对改进仍然至关重要。

为了将各策略寻找有信息价值轨迹的能力与其过采样失败轨迹的倾向分离开来，我们进行了一次反事实标准化，将各策略的分层特定比率重新加权到随机采样的奖励分布上（63% 成功、37% 失败）。在这一调整下，Signal 采样取得了 77.6% 的标准化比率，相比之下启发式采样为 62.7%，随机采样为 54.0%。一旦剔除启发式采样中失败轨迹占比过高的构成，其相对随机采样的优势便下降 11.3 个百分点，而 Signal 采样的优势则更为稳健（仅下降 4.4 个百分点）。这证实了 Signal 采样带来的是真实的单条轨迹信息价值提升，而并非仅仅是对失败轨迹的过采样。

标注效率。上述结果可直接转化为实际节省。在 100 条标注的固定预算下，Signal 采样可获得 82 条有信息价值的轨迹，而启发式采样为 74 条，随机采样为 54 条。等价地说，在 Signal 采样下每条有信息价值的轨迹耗费 1.22 个标签，而启发式采样为 1.35 个，随机采样为 1.85 个，相当于相对无偏基线获得了 1.52× 的效率提升。此外，正如奖励分层分析所示，这一提升并非过采样明显失败轨迹所带来的假象：Signal 采样在失败层和成功层内部均保持了更高的信息价值率，这意味着即使样本构成保持不变，其效率优势依然存在。

类别分布。表 2 展示了开发者信息性轨迹中标注原因类别的分布。在信息性轨迹中，标注原因的分布在所有三种策略下均保持稳定：动作/工具调用行为问题占 57-60%，对话问题占 38-43%，另有少量成功示例。这种一致性表明，信号框架并不会偏向于呈现某一类型的问题，而只是呈现出更多的问题。

领域鲁棒性。我们进一步检验信号采样的优势是否在 τ-bench 的不同领域中同样成立。在航空（airline）领域中，所有策略均达到较高的信息性比率（86% - 96%），区分空间有限。而零售（retail）领域具有更复杂的多步骤任务和更低的基础信息性比率，呈现出最清晰的区分：信号采样达到 78% 的信息性比率，而启发式采样为 66%，随机采样为 35%。因此，信号采样恰恰在轨迹最为异质、无信息性轨迹最为普遍的地方提供了最大的边际价值。

5 Limitations

我们的实验在 τ-bench 上进行，该基准测试涵盖两个领域（航空与零售），并使用由大语言模型（LLM）模拟的用户。虽然这些领域覆盖了分类体系中的所有信号类别，但所观察到的优势能否推广到更广泛的领域以及真实用户群体，仍是一个悬而未决的问题。特别是，模拟用户可能未能充分体现真实用户脱离参与和满意度模式的多样性，如第 4 节所述。

此外，信号分类体系在设计上是有意采用粗粒度且面向行为的方式。它捕捉的是反复出现的话语与执行模式，但并不评估语义正确性或特定领域的策略违规。那些语言流畅、行为上并无异常但事实上错误的轨迹，不会被当前框架呈现出来，这表明信号最好与互补机制（例如特定领域的验证器或结果验证）配合使用。

最后，我们的信号检测器依赖于确定性规则和词汇启发式方法。基于模型的检测器可以提供更高的召回率，尤其是对于缺乏显式词汇标记的细微未对齐或隐性挫败模式，但其代价是失去了使常驻部署成为可行的轻量级计算。探索将基于规则的信号与选择性的基于模型的检测相结合的混合架构，是一个有前景的方向。

6 Conclusion

我们提出了一个轻量级的、基于信号的框架，用于对智能体交互轨迹进行分诊。该框架的贡献包括：1）一个涵盖交互、执行与环境模式的粗粒度信号分类体系；2）一种无需计算质量分数即可对轨迹进行优先级排序以供人工审查的采样机制；3）在 τ-bench 基准测试上的实证验证，表明基于信号的采样实现了 82% 的信息量比率，相比随机采样获得了 1.52× 的效率提升。该优势在不同奖励层级和任务领域中均保持稳健，证实了信号提供的是真正的逐轨迹信息量增益，而不仅仅是对明显失败的过度采样。

该框架不仅有效，而且适合真实场景部署。由于所有信号均通过确定性规则而非模型调用计算得出，该方法带来的开销可以忽略不计，并且能够轻松扩展到大规模的交互记录集合。这种效用与效率的结合，使基于信号的采样成为更广泛的偏好数据构建流程中极具吸引力的第一阶段：被选中的轨迹（包括失败案例和成功范例）可以与反事实续写配对，从而为基于偏好的优化产生监督信号。我们将这一端到端流程的设计与评估留待未来工作。
