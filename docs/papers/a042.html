KG-Agent: An Efficient Autonomous Agent Framework for Complex Reasoning over Knowledge Graph

KG-Agent：一个面向知识图谱上复杂推理的高效自主 Agent 框架

简介

论文针对现有 LLM 与知识图谱（KG）协同推理方法的两大局限——交互机制靠人工预定义、无法灵活适应复杂任务，以及依赖 ChatGPT/GPT-4 等闭源 API——提出自主 Agent 框架 KG-Agent。方法上，它为 KG 构建了抽取、语义、逻辑三类工具组成的多功能工具箱，从现有 KGQA 数据集的 SQL 标注合成代码形式的指令微调数据（而非从闭源模型蒸馏），仅用 10K 样本微调 LLaMA2-7B；运行时由 LLM-based planner 选择工具生成函数调用，KG-based executor 执行并更新 knowledge memory（问题、工具箱定义、当前 KG 信息、历史推理程序），自主迭代直至得出答案。关键结论：10K 样本微调的 7B 模型在 WebQSP、CWQ、GrailQA 等 in-domain 数据集上超过使用更大模型或更多数据的 SOTA，out-domain 零样本也优于全量微调模型，并可迁移到电影领域 KG（MetaQA）。其 planner-工具箱-executor-记忆 的 Agent loop 设计与'从可执行轨迹合成 SFT 数据'的做法，对团队构建 Agent 系统有直接借鉴价值。

问题

现有 LLM+KG 的 synergy-augmented 方法存在两个主要问题：一是 LLM 与 KG 的信息交互机制多为人工预定义的多轮计划，无法灵活适应推理过程中多变的难度与约束；二是依赖 ChatGPT、GPT-4 等闭源大模型 API，其蒸馏出的计划未必适合较弱的模型。此外，KG 数据量大且结构化，LLM 难以直接准确操作。论文目标是让较小的开源 LLM（7B）在无人工辅助下自主完成 KG 上的多跳复杂推理。

方法

KG-Agent 包含四个组件：指令微调后的 LLM-based planner、多功能工具箱、KG-based executor 和 knowledge memory。工具箱按抽取、语义、逻辑三类设计（如 get_relation、get_tail_entity、get_entity_by_constraint、count、intersect、end 等），格式统一、可按需扩展。训练数据构造不依赖闭源模型蒸馏：利用 KGQA 数据集的 SQL 标注，先在 KG 上落地为 query graph，用 BFS 抽取推理链与约束条件，再转成函数调用序列形式的推理程序，逐步构造输入-输出对并用统一 prompt 模板格式化，最终以 1:5:5:10 比例采样 10K 样本 SFT LLaMA2-7B。推理时 planner 基于当前记忆选择工具并生成函数调用，executor 用程序编译器执行并更新记忆（追加历史推理程序、写入新获取的 KG 信息），自主迭代直到得到答案；整个过程对任务类型和具体 KG 不可知，具有通用性。

关键结果

仅用 10K 样本微调 LLaMA-7B，在 in-domain 与 out-domain 数据集上均超过使用更大 LLM 或更多数据的 SOTA 方法

in-domain：仅用约 36% 和 23% 的原始训练集数据量，在 CWQ 和 GrailQA 上分别取得 7.5% 和 2.7% 的相对 F1 提升；混合多数据集微调后在 WebQSP、CWQ、GrailQA 上 F1 分别提升 1.7%、7.5%、2.7%

out-domain 零样本：在 WQ-Freebase 和 TQ-Wiki 上分别取得 9.7% 和 8.5% 的相对准确率提升，优于全量数据监督微调的小模型

MetaQA（电影领域 KG）one-shot 迁移：在所有子集上稳定超过有竞争力的监督微调基线；对比之下 ChatGPT 在 MQA-3hop 上比 TransferNet 绝对下降 45%，StructGPT 比 ChatGPT 高约 37%

指令数据量从 2k 增至 64k 性能持续上升，但 16k 到 64k 之间无显著提升，作者归因于指令数据多样性不足

创新点

与 KB-BINDER、Pangu、StructGPT、RoG 等预定义 LLM-KG 交互流程的方法不同，KG-Agent 让 LLM 在推理过程中自主决策、无需人工辅助；与 ChatDB 等自主方法依赖闭源 API 且无法用工具实现专门操作（如 count）不同，KG-Agent 是首个仅靠 7B 开源 LLM、以工具+记忆增强方式支持 LLM 与 KG 复杂交互的自主 Agent 框架。此外，指令数据从 KGQA 数据集的 SQL 标注合成而非从 GPT-4 蒸馏，并混合多个 KG（Freebase、Wikidata）的数据以学习跨 KG 的通用自主决策能力。
