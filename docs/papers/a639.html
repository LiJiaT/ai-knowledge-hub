Exploring Chain-of-Thought Style Prompting for Text-to-SQL

探索 Chain-of-Thought 风格提示在 Text-to-SQL 中的应用

简介

该论文研究如何用 Chain-of-Thought（CoT）风格提示提升 LLM 在 Text-to-SQL 解析上的多步推理能力。作者先将 chain-of-thought 提示与 least-to-most 提示适配到该任务，再提出 question decomposition prompting（QDecomp）及其变体 QDecomp+InterCOL：让模型在单次生成中先分解子问题、并在每个子问题旁标注涉及的表/列名，最后一次性输出 SQL。在 Spider 开发集与 Spider Realistic 上，QDecomp+InterCOL 相比无推理步骤的标准提示分别取得 5.2 与 6.5 点绝对提升，相比 least-to-most 取得 2.4 与 1.5 点提升；使用 extra-hard 示例时执行准确率达 78.2%，接近微调模型 RASAT+PICARD。关键结论是：迭代式提示并非必要，过细的推理步骤反而会加剧 error propagation。这些发现对团队的提示设计、few-shot 示例工程与评测方法选择有直接参考价值。

问题

LLM 的 in-context learning 在 Text-to-SQL 解析任务上性能仍有较大提升空间。作者假设多步推理能力是关键短板，并系统研究两个问题：(RQ1) 一次性生成全部推理步骤与迭代式提示求解哪种更好；(RQ2) 更详细的推理步骤是否带来更好的 Text-to-SQL 结果。

方法

将 chain-of-thought 提示适配到 Text-to-SQL（参照 SQL 子句的逻辑执行顺序，用自然语言模板把每个子句构造成推理步骤）；将 least-to-most 提示适配为两阶段（问题分解 problem reduction + 逐个子问题迭代求解 problem solving）。在此基础上提出 QDecomp：像 CoT 一样单次生成，但把推理步骤改为对原问题的子问题分解；其变体 QDecomp+InterCOL 在每个子问题处增量标注涉及的表/列名，以缓解 schema grounding（table/column linking）问题。实验使用 Codex（code-davinci-002）、8-shot、API Docs 提示格式与 test-suite execution accuracy 评测，并系统考察 in-context 示例选择（随机 vs 按难度 G1/G2/G3）、示例数量与提示格式（API Docs vs Create Table + Select 3）的影响。

关键结果

QDecomp+InterCOL 在 Spider 开发集和 Spider Realistic 上分别取得 68.4% 和 56.5% 的 test-suite 准确率，比标准提示高 5.2 和 6.5 个绝对点，比 least-to-most 高 2.4 和 1.5 个绝对点

使用 extra-hard（G3）示例时，QDecomp+InterCOL 执行准确率达 78.2%，与微调的 RASAT+PICARD 相当；least-to-most 仅 73.8%，且 test-suite 准确率反而降至 63.3%

chain-of-thought 提示（Spider 开发集 56.8%）甚至低于标准提示，least-to-most 为 66.0%

组件匹配分析显示 QDecomp 与 QDecomp+InterCOL 在全部五个 SQL 组件（SELECT、WHERE、GROUP BY、ORDER BY、KEYWORDS）上优于其他 CoT 风格方法

API Docs 格式与 Create Table + Select 3 格式性能相当（4-shot）：后者对标准提示仅带来可忽略提升，对 QDecomp 与 QDecomp+InterCOL 甚至略有下降

示例数量增至 8 个后继续增加仅带来微小收益；QDecomp(+InterCOL) 在 GeoQuery、IMDB、Yelp 三个单域数据集上均取得最佳结果

创新点

据论文所述，这是对 CoT 风格提示在 Text-to-SQL 上应用的首次系统探索。核心区别在于提出 QDecomp，将 least-to-most 的问题分解与 CoT 的单次生成结合，用实验证明迭代提示不必要、过细推理步骤会加剧 error propagation；QDecomp+InterCOL 进一步通过在子问题中增量标注表/列名缓解 schema linking。与 DIN-SQL（需迭代提示）和 LEVER（需在完整训练集上微调 verifier）不同，该方法无需迭代调用或额外训练即可取得可比或更优的结果。
