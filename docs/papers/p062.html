Remote and Probeless Debug Methodology for Data Center Silicon Debugs

面向数据中心 Silicon Debug 的远程 Probeless（无探针）调试方法学

简介

该论文针对数据中心 RMA 流程中带 CPU failure signature 的硬件单元做 Failure Analysis 时，传统依赖物理接触与侵入式 JTAG 探针导致物流成本高、停机时间长的问题，提出一种无需物理探针的远程 Silicon Debug 方法。方法核心是复用服务器 BMC 内集成的 JTAG（IEEE Std 1149.1）controller 作为调试访问通道：初始架构将 RDDI server 与 Probe API 置于 host 侧，每条低层 JTAG Shift-IR/Shift-DR 操作都承受一次网络往返，实测比物理探针调试慢约 30 倍；优化架构将二者下沉到 BMC 本地执行，高频 JTAG 事务不再穿越网络，仅高层命令与结果走网络。结果显示优化后命令执行速度接近传统探针调试水平，恢复了远程无探针 FA 的实用性。对团队而言，其"协议智能下沉到靠近被测件的边缘设备"的架构原则与 IEEE 1149.1 JTAG 访问实践，对 IP 在系统端的远程调试访问设计有借鉴价值。

问题

数据中心规模庞大、uptime 压力高，RMA（Return Material Authorization）流程中对筛出 CPU failure signature 的单元需进行 Failure Analysis（FA）；传统调试依赖物理系统接触和侵入式 JTAG 探针，需要大量技术工时、专用设备并造成系统停机，在数据中心场景下物流与经济成本高、难以规模化。论文要解决的是：在不依赖物理探针和直接物理接触的前提下，对数据中心/RMA 系统中的 SoC 完成深度 Silicon Debug 与根因分析。

方法

利用服务器主板上 BMC 内集成的 JTAG（IEEE Std 1149.1）controller 作为远程调试访问通道，经 BMC firmware/software stack 访问。初始架构：host 上的调试工具（ARM-DS、scandump/memdump/jtag application）经 RDDI server 与 Probe API 转成 RPC 发往 BMC 的 RPC server，再由 BMC JTAG driver 驱动目标 SoC；由于每条低层 JTAG 操作都产生一次 Host->BMC->Host 网络往返，性能慢约 30 倍。优化架构：将 RDDI server 与 Probe API 迁移到 BMC 上驻留执行，高层调试命令（如读某内存地址）在 BMC 本地翻译为 Shift-IR/Shift-DR 序列，经本地 IPC/函数调用直接驱动 JTAG driver，仅将最终结果回传 host，从而消除高频 JTAG 事务的网络延迟。论文进一步给出可推广原则：BMC 作为具备本地 JTAG 控制能力的"智能调试代理"，可适配不同协议/中间件，例如开发相应 server 组件后可能集成 Lauterbach TRACE32。

关键结果

初始远程调试架构（RDDI server/Probe API 位于 host 侧）的命令执行速度比使用物理探针直连 host 的传统 JTAG 调试慢约 30 倍（approximately 30 times slower），根因是每条低层 JTAG 操作都引入一次网络往返延迟。

优化架构（RDDI server 与 Probe API 迁移至 BMC 本地）实测命令执行速度接近（nearly equivalent）传统基于探针的调试水平，关键因素是绝大多数 JTAG 事务不再经历网络往返。

创新点

相对依赖物理 JTAG 探针的传统调试方式，主要区别在于：1) 完全复用服务器 BMC 中已有的 JTAG controller，实现 probeless、非侵入的远程 Silicon Debug，免去现场插拔探针与系统停机；2) 关键创新是将调试协议智能（RDDI server 与 Probe API）从 host 迁移到 BMC 本地执行，使高频 Shift-IR/Shift-DR 事务局限在 BMC 内部，仅高层命令与结果走网络，消除网络往返延迟瓶颈；3) 将 BMC 重新定位为具备本地 JTAG 控制能力的 intelligent debug agent 而非被动物理接口代理，并抽象出可推广的四步架构原则（远程下发高层请求、BMC 本地翻译为 JTAG 交互、驱动目标 SoC、回传结果）。

摘要 - 鉴于现代数据中心的规模，维持硬件可靠性和性能面临重大挑战。数据中心运营的特点是高复杂性、大规模以及维持正常运行时间的持续压力。退货授权（RMA）流程涉及对故障硬件组件的诊断和更换。我们每月与供应商处理大量的RMA。其中少量单元在筛选时呈现CPU故障特征，从而触发故障分析（FA）流程。维护这些系统的一个重大挑战是硬件故障的调试。依赖物理访问和侵入式探针的传统调试方法加剧了这些挑战。本方法论引入了一种新颖的远程调试方法，消除了对物理硬件访问的需求。在本方法论的背景下，成功实施的前提条件是所有涉及的基础板管理控制器（BMC）均配备有可正常工作的JTAG控制器。本方法论利用BMC现有的JTAG控制器，该控制器提供了深度硅故障分析所需的行业标准访问能力。虽然高层BMC通道对于初步分诊有效，但JTAG仍然是深度硅故障分析不可或缺的工具，尤其是在其他接口无响应的严重挂死情况下。利用BMC的JTAG控制器，所提出的调试器能够在数据中心RMA流程中高效地排查片上系统（SoC）问题，并带来若干关键优势。

关键词 - 远程调试、无探针调试、数据中心、故障分析、硅调试、基础板管理控制器（BMC）、JTAG（Joint Test Actions Group，联合测试行动组）、RDDI（Remote Debug Device Interface，远程调试设备接口）、网络延迟、硬件诊断。

I. INTRODUCTION

现代数据中心的运营复杂性和庞大规模要求硬件具备极高的可靠性，并将停机时间降至最低。退货授权（Return Material Authorization, RMA）流程是管理硬件故障的关键环节，通常涉及复杂的故障分析（failure analysis, FA）以诊断根本原因，对于表现出CPU故障特征的组件尤其如此。传统的硬件调试方法严重依赖物理系统访问和侵入式JTAG探针的使用，在数据中心环境下带来了巨大的后勤和经济挑战 [1][3]。这些方法通常需要耗费大量技术人员时间、使用专用设备，并可能导致系统停机时间延长，从而影响服务可用性并增加运营支出。因此，对高效、可扩展且非侵入式诊断技术的需求至关重要。本文提出了一种专为数据中心环境设计的新型远程“无探针”调试方法。其核心原理是利用服务器主板上基础板管理控制器（Baseboard Management Controller, BMC）中普遍集成的JTAG [2]（Joint Test Action Group，联合测试行动组，IEEE Std 1149.1）控制器。通过利用这一现有硬件能力，无需物理探针或直接访问被测系统（system under test, SUT）即可建立远程调试会话。该方法的一个关键前提是存在可通过BMC固件/软件栈访问的功能正常的JTAG控制器。所提出的方法具有以下几项关键优势：

II. INITIAL REMOTE DEBUG ARCHITECTURE AND LIMITATIONS

初始实现遵循了传统的远程调试范式。在该模型中，主机上的用户使用 ARM-DS 或调试实用程序（scandump、memdump 或 jtag 应用程序）发起调试命令。这些工具与 RDDI（Remote Debug Device Interface，远程调试设备接口）服务器进行通信；RDDI 是一种用于在主机与目标设备之间进行调试通信的协议。该服务器与 Debug ProbeAPI 通信，由后者将 RDDI 命令转换为 RPC（Remote Procedure Call，远程过程调用）。在 BMC 侧，有一个 RPC 服务器监听这些消息，通过 BMC 的 JTAG 接口与目标硬件通信，并建立调试会话。所得到的数据被返回至 RDDI 服务器，经过处理后转发回调试工具，供用户查看。

其概念示意如下：

调试工具（主机）-> RDDI 服务器（主机）-> Probe API（主机）-> 网络（RPC）-> BMC（RPC 服务器 -> JTAG 驱动）-> 目标 SoC

尽管该架构在功能上可用，但性能评估显示，其速度比使用直接连接到主机的物理探针的传统 JTAG 调试慢约 30 倍。根本原因被确定为主机与 BMC 之间产生的过多网络流量。高层调试命令（例如读取一块内存）会被 RDDI 服务器分解为大量单独的 JTAG Shift-IR 和 Shift-DR 操作。在通过所述架构执行时，这些低层操作中的每一个都会引入一次网络往返（主机 -> BMC -> 主机）的延迟。对于复杂的调试序列，这种延迟的累积效应使得该方法在典型的失效分析（FA）工作流程中变得不切实际。

III. OPTIMIZED BMC-RESIDENT DEBUG ARCHITECTURE

为了缓解由网络延迟造成的严重性能瓶颈，我们实施了一项重大的架构修改。核心改动是将负责把高层调试请求转换为低层 JTAG 事务的组件从主机迁移到了 BMC 本身。

修改后的架构在概念上如下图所示：

调试工具（主机）-> 网络 -> BMC（RDDI 服务器 -> Probe API -> JTAG 驱动）-> 目标 SoC

在这一优化模型中，主机上的用户仍然使用其偏好的工具发出相同的高层调试命令。这些高层命令通过网络直接传输到 BMC。RDDI 服务器和 Probe API 逻辑现在驻留并运行在 BMC 上。驻留在 BMC 上的 RDDI 服务器接收高层命令（例如“读取内存地址 0x1000”）。在 BMC 上本地运行的 RDDI 服务器将其转换为所需的低层 JTAG Shift-IR 和 ShiftDR 操作序列。这些低层 JTAG 操作直接（通过 BMC 软件环境内的本地进程间通信或函数调用）传递给 BMC 的 JTAG 驱动。JTAG 驱动与目标 SoC 交互。只有高层命令的最终结果（例如读取到的内存内容）会被打包并通过网络回传给主机调试工具。

IV. PERFORMANCE EVALUATION OF OPTIMIZED ARCHITECTURE

第III节所述的架构转变带来了显著的性能提升。通过在 BMC 上执行 RDDI 服务器和 Probe API，从高层调试命令到低层 JTAG 扫描的转换在本地完成。因此，高频的 Shift-IR/Shift-DR 操作不再经由网络传输。网络通信主要仅限于传输频率较低的高层调试命令及其对应结果。对该优化架构的性能测量表明，其命令执行速度几乎与传统基于探针的调试环境所达到的速度相当。为绝大多数 JTAG 事务消除网络往返延迟是实现这一性能对等的关键因素。这使得远程无探针调试方法在数据中心失效分析（FA）任务中重新具备了实际可行性。

V. DISCUSSION

优化架构的成功凸显了网络延迟对远程 JTAG 操作的关键影响，并证明了将协议智能本地化的有效性。将 JTAG 事务生成逻辑（在本实现中为 RDDI 服务器）迁移到最靠近目标硬件的边缘设备（BMC）上，对于获得可接受的性能至关重要。尽管本实现采用了 RDDI 协议，但其底层原理具有广泛的适用性。核心需求是一种能够完成以下操作的机制：1. 将高层调试请求从远程主机传输至 BMC。2. 在 BMC 上执行逻辑，将这些请求转换为相应的底层硬件（JTAG）交互。3. 利用 BMC 的 JTAG 控制器与目标 SoC 进行交互。4. 将结果返回给远程主机。替代实现有可能采用不同的协议或中间件。例如，可以在 BMC 上开发定制的服务器应用程序，用于解析来自各种调试器的命令。如果开发出相应的服务器组件和 BMC JTAG 驱动接口，与其他行业标准工具（例如 Lauterbach TRACE32）的集成也可能是可行的。其核心要素仍然是 BMC 作为能够执行本地 JTAG 控制的智能调试代理所扮演的角色，而不仅仅是一个被动的物理接口代理。首要前提仍然是 BMC 平台上具备可用且可访问的 JTAG 控制器。确保 BMC 固件和软件为 JTAG 操作提供可靠支持，对于该方法的部署至关重要。所实现的各项收益——减少停机时间、提升效率、节约成本以及可扩展性——使这种远程无探针方法成为在复杂数据中心环境中管理硬件诊断的宝贵工具。它显著降低了对 RMA（退货授权）单元开展详细硅失效分析的门槛，有望更快地识别系统性问题并推动硬件版本的改进。

VI. CONCLUSION

本文提出了一种专为数据中心硅失效分析量身定制的远程无探针调试方法，该方法利用了服务器 BMC 中集成的 JTAG 控制器。其初始架构由于传输底层 JTAG 命令所产生的网络延迟而存在令人难以接受的性能限制。本文提出的关键创新在于一项架构转变，即将调试协议智能（RDDI server 和 Probe API）迁移至 BMC 本身。这一优化将高频 JTAG 事务限制在 BMC 本地执行，大幅减少了网络流量，并消除了由此带来的延迟瓶颈。由此得到的方法实现了与传统基于探针的调试相当的性能，同时保留了远程、非侵入式访问的显著运营优势。这种方法在降低成本、提升诊断效率和增强可扩展性方面带来了显著收益，是大规模数据中心运营中硬件调试实践的一项重大进步。
