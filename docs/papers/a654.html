Decomposed Prompting for Machine Translation Between Related Languages using Large Language Models

DecoMT：使用 LLM 在相关语言间进行机器翻译的 Decomposed Prompting（分解式提示）方法

mediumarXiv提示技术评测基准成本与效率可靠性与安全基于arXiv版本
下载原文 PDF

简介

论文研究相关语言（同语系、词序与词汇高度相似）之间的机器翻译，指出标准 few-shot prompting 要求 LLM 在生成翻译的同时自行保证词序流畅，忽略了这类语言间普遍存在的单调对齐特性，且 LLM 训练数据偏向英语、在低资源语言对上表现弱。作者提出 DecoMT：先将源句切分为词块，用 5-shot 提示基于 encoder-decoder 模型 mT5 XL（3.7B）逐块独立翻译，再利用 mT5 的双向 infilling 能力增量生成考虑上下文的最终翻译。在 FLORES devtest 的多个语言对上，DecoMT 超越 BLOOM、XGLM、mT5 的 Standard Prompting 及 SAP：平均比 BLOOM 高 8 个 chrF++、比同底座 mT5 Standard Prompting 高 13.8 个 chrF++，长句优势尤其明显，off-target 率更低，且 one-shot 设定下依然稳健。代价是需要人工对齐标注示例、推理耗时高于标准提示，且依赖具备 infilling 能力的模型。

问题

标准 few-shot prompting 做机器翻译时，要求模型在生成翻译的同时隐式完成词序重排，没有利用相关语言（同语系、共享 SOV 词序与词汇特征）间普遍存在的单调对齐这一归纳偏置；同时 LLM 训练数据严重偏向英语（如 mT5 中印地语、Malayalam token 仅占 0.8% 和 0.07%），在低资源相关语言对上缺乏足够数据。论文目标是借助单调对齐特性把翻译任务分解简化，提升相关语言间 few-shot 翻译的质量，尤其是长句的翻译充分性。

方法

提出 DecoMT，将 Khot et al. (2023) 的 decomposed prompting 思想应用于机器翻译，把整句翻译分解为两阶段：(1) 独立翻译阶段——将源句切分为约 m 个 token 的词块（m 为在 {3,4,5} 上基于 FLORES devset 调优的超参数），用含 5 个人工单调对齐示例的 few-shot 提示，基于 mT5 XL（3.7B，span-corruption 训练的 encoder-decoder 模型）逐块独立翻译，该阶段可并行；(2) 上下文翻译阶段——利用 mT5 的双向 infilling 能力，将源句前文词块、上一步的上下文翻译、mask 占位符与下一块的独立翻译拼接成提示，增量式 infill 出语境一致的最终翻译（条件独立性假设下逐步推进）。论文还给出独立翻译与上下文翻译两套提示模板的具体构造方式（语言标签、分块、mask 位置等）。

关键结果

FLORES devtest 上，DecoMT 相比 few-shot prompting 的 BLOOM 平均提升 8 个 chrF++ 分数

相比同底座 mT5 的 Standard Prompting，DecoMT 平均提升 13.8 个 chrF++ 点

在低资源语言对 hin↔mal、hin↔mar、hin↔guj、hin↔tel、ind↔zsm、rus↔ukr 上超越所有对比方法（配对 bootstrap 检验 p<0.05）；高资源 spa↔por 上不及 BLOOM

XSTS 人工评估（4 个语言对、每方法 50 句）：DecoMT 在所有语言对上显著优于 mT5 Standard Prompting，在 hin→mar、hin↔guj、ind→zsm 上显著优于 BLOOM，在 hin→mar 上显著优于 SAP

随源句长度增加，DecoMT 的 chrF++ 持续上升而 SAP 下降，长句场景优势明显

加入上下文翻译阶段相对仅独立翻译的单阶段方案带来显著的 chrF++ 提升

DecoMT 的 off-target 翻译率在多数翻译方向上低于各对比方法

one-shot 设定下 DecoMT 保持稳健，SP 与 SAP 大幅退化（如 SAP 在 hin→tel 上 spBLEU 从 19.3 降至 1.3）

运行时剖析（A40 GPU，Marathi→Hindi）：独立翻译可并行、上下文翻译需 T/m 次前向，共 16 次 API 调用合计 96.868 秒，总调用次数少于 SAP，整体快于 SAP 但慢于 Standard Prompting

创新点

将 decomposed prompting（Khot et al., 2023）从复杂推理任务迁移到相关语言间机器翻译，利用单调对齐这一语言学归纳偏置把翻译分解为词块级两阶段流程，让模型免除隐式重排、专注子句结构。与同样基于 mT5 的 SAP 不同，DecoMT 不只利用自回归特性，还利用 encoder-decoder 模型的双向 infilling 能力做上下文精化；与需要从头训练 decoder-only LLM 的工作不同，DecoMT 直接使用现成 mT5；与 Press & Smith (2018) 的 eager translation 相比，翻译单位从单 token 扩展到词块，并新增了基于 infilling 的上下文精化阶段。

理由：论文核心贡献是一种提示技术：把复杂生成任务分解为子任务分别 few-shot 提示，再用 infilling 做上下文精化，属于 3.2 提示技术与模式范畴；其'分块独立生成→增量上下文精化'的提示模式、详细的提示模板构造方式、以及 one-shot 下依然稳健的发现，对团队设计提示有借鉴价值。其评测方法论（自动指标+XSTS 人工对比评估+off-target 错误率+运行时剖析与 API 调用统计）与 3.5 的 LLM 应用评测、成本效率分析相通。但论文的应用场景是相关语言间机器翻译，方法成立的关键前提（单调对齐）是语言学特性，在团队的代码生成、文档、测试辅助、知识库问答等任务中没有直接对应物，且依赖 mT5 这类具备 infilling 能力的 encoder-decoder 模型而非团队常用的自回归 API 模型，因此不直接命中团队技术栈，定为 medium。
