Bounding the Capabilities of Large Language Models in Open Text Generation with Prompt Constraints

用提示约束界定大语言模型在开放文本生成中的能力边界

higharXiv提示技术评测基准可靠性与安全基于arXiv版本
下载原文 PDF

简介

开放文本生成模型的能力边界不清晰，已有分析多聚焦语法、连贯性、毒性等通用文本属性，无法说明模型对提示中具体约束的响应程度。论文提出以提示为中心的分析方法，将约束分为风格类（writing style、tone、mood、characterization、pacing、plot、genre）与结构类（numerical、descriptive、formatting）两大类，为每个约束设计简单自然的 base prompt，再在主题与提示模板维度构造变体，共构建 288 个提示，对 GPT-3 text-davinci-002 逐条约束做人工与自动评测，并在 OPT-176B、BLOOM-176B、GLM-130B 上验证方法通用性。关键结论：数值长度约束失败率随要求长度上升（5/10/20 分别为 0.46/0.78/1），风格与主题配对强烈影响表现，模型表现与人类感知的提示难度无相关（Spearman -0.15）；三种 in-context 缓解策略能一致提升表现但远未达标。

问题

开放生成模型何时成功、何时失败尚不清楚；现有分析集中在语法、连贯性、毒性等与提示无关的通用文本属性，缺乏对'模型能否正确响应提示中约束'的细粒度理解。论文要系统界定 LLM 在带风格与结构约束的开放文本生成提示上的能力边界。

方法

以提示为中心的约束分类法：将约束划分为风格类（基于 Reader's Advisory 分类学的 7 个特征）与结构类（数量、描述性、格式三类）；为每个约束设计 base prompt，再在主题与提示模板维度构造变体，共 288 个提示；每个提示用 GPT-3 text-davinci-002（temperature 0.7、max tokens 1024）生成 10 个输出；风格约束经 Amazon Mechanical Turk 人工 5 点 Likert 评分，结构约束自动计数校验；另做模型规模与温度敏感性实验、其他 LLM 试测，以及三种文献中的 in-context 缓解策略实验。

关键结果

数值结构约束失败率高且随长度要求上升：要求 5/10/20 个词、句或段时失败率分别为 0.46、0.78、1

描述性结构约束方差大：long 类提示的输出长度与 short 类重叠比例达 20%

模型表现与标注者感知的提示难度无相关，Spearman 相关系数为 -0.15

格式约束上代码生成平均失败率 0.2，邮件格式良好（10% 缺签名），学术论文格式基本失败

三种 in-context 缓解策略均带来正向提升（主要改善 humorous tone 提示），但结果仍远低于最优

OPT-176B、BLOOM-176B、GLM-130B 表现远差于 GPT-3，超过一半生成结果退化（如重复提示）

模型规模增大时性能呈上升趋势而非涌现；温度 0.4 与 1.0 在风格任务上略优于 0.7

共构建 288 个提示；风格标注的 Krippendorff's α 为 0.31

创新点

与以往分析通用文本属性（语法、连贯性、毒性）或对抗性手工提示的工作不同，本文按提示中的约束类型对开放生成空间做细粒度分类，分析模型对提示本身的响应；与可控文本生成工作不同，本文纯 in-context 评测，不依赖配对的约束数据集或架构改动，并给出可复用的 base prompt + 变体构造方法。
