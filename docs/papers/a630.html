Make a Choice! Knowledge Base Question Answering with In-Context Learning

做出选择！基于 In-Context Learning 的知识库问答（KBQA）

简介

论文针对知识库问答（KBQA）中标注数据无法覆盖全部 KB schema、rank-based 方法泛化难的问题，以及 LLM 直接生成答案带来的长文本难评测与幻觉风险，提出 McL-KBQA 框架。方法上先用 BERT ranker 对候选逻辑形式打分并取 top-4，把原问题改写成多选题，再通过 ICL 提示让 ChatGPT 从候选中'做选择'，并加入 CoT 问题解释（识别焦点、识别约束、给出答案）辅助判断，最后按 ranker 置信度对两者结果做融合路由。关键结论：5% 训练数据下 ICL 超越 Ranker 9.83 F1；数据充足时 LLM 单独使用劣于 Ranker，但仅对 5% 的问题采用 LLM 结果做融合即可平均提升 0.80；CoT 较 ICL 平均提升 1.21；GrailQA 上 Compositional/Zero-Shot 级别分别提升 1.85 EM/1.94 F1 与 2.68 EM/3.17 F1。对团队而言，'候选约束 + 多选题化 + 置信度路由融合'是把 LLM 可靠嵌入现有系统的可复用设计模式。

问题

KBQA 中 KB 规模庞大，标注数据无法覆盖所有 fact schema，依赖充足标注数据的 rank-based 方法在长尾/低资源场景泛化能力不足；而直接把问题丢给 LLM 生成答案，又面临输出为生成式长文本、与 KB 中由实体短语构成的标准答案不一致导致评测困难或繁琐，以及幻觉（Hallucination）问题。

方法

McL-KBQA 框架：(1) 用基于 BERT 的 ranker 对从 KB 枚举出的候选逻辑形式打分，取 top-k（实验中 4 个）构建多选题，选项内容用 KB 实体的 surface name 而非实体 ID 以便 LLM 理解；(2) prompt 由 Task Description、In-Context Example（从开发集随机采样 2 个）和 Incomplete Entry 三部分组成，让 LLM 通过 ICL 选择选项字母；(3) CoT 版本 prompt 让 LLM 按三步生成问题解释：识别问题焦点、识别约束、给出所选答案，示例解释由 LLM 通过 zero-shot CoT 生成；(4) 推理时设置 stop flag ']' 并用正则表达式从输出末尾匹配选项字母，匹配失败则回退用 ranker 结果；(5) 结果融合：以 ranker 所有候选中的最高分作为问题置信度 s(q)，设阈值 λ（按 5% 融合比例标定），低置信度问题用 LLM 结果替代 ranker 结果。LLM 使用 ChatGPT（gpt-3.5-turbo-0301），temperature 设为 0。

关键结果

WebQSP 上 5% 训练数据设置下，ICL 超越 Ranker 9.83（F1），10% 设置下同样占优

训练数据充足时（30%/50%/100%）ICL 劣于 Ranker，差距从 0.79（30%）扩大到 4.78（100%）

ICL w/fuse 在 30%/50%/100% 三个设置下平均超越 Ranker 0.80，且仅对 5% 的问题采用 LLM 结果

CoT 在所有设置下超过 ICL，平均提升 1.21

GrailQA 全量训练下，Compositional 级别超越 rank 1.85 EM/1.94 F1，Zero-Shot 级别超越 2.68 EM/3.17 F1，I.I.D. 级别 EM 略低但 F1 更高

Few-shot（5%）设置下 LLM 在 19.28% 的问题上优于 rank；全量（100%）设置下仍有 11.59% 的问题优于 rank

选项字母自动匹配有效率：ICL 96.36%、CoT 93.52%；匹配到选项列表外字母（OOL）仅 0.14%/0.06%；结果融合使 H（选到更优结果）问题比例在 5% 设置增加 0.61%、全量设置增加 2.01%

创新点

区别于直接把问题提供给 ChatGPT 让其自由生成答案（评测困难、易幻觉），也区别于让 LLM 生成逻辑形式草稿再迭代绑定 KB 的做法（Li et al., 2023），McL-KBQA 将 KBQA 改写为多选题，让 LLM 在 ranker 提供的候选逻辑形式中'做选择'，输出受限且易于自动解析；并提出基于 ranker 最高分置信度的结果融合策略，按置信度在 ranker 与 LLM 之间路由；同时在 ICL 示例中加入由 LLM 零样本 CoT 生成的问题解释。
