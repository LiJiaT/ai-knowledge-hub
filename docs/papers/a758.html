Conversing with Copilot: Exploring Prompt Engineering for Solving CS1 Problems Using Natural Language

与 Copilot 对话：探索用自然语言提示工程解决 CS1 编程问题

简介

论文系统评估了 GitHub Copilot（底层为 OpenAI Codex）在 166 道 CodeCheck 公开 Python 入门编程题上的表现，并首次探索用自然语言提示工程修复代码生成错误的做法。方法是将题目描述原样输入 Copilot，对失败题目人工改写提示（如追加伪代码式分步算法提示）后重新生成并判题，再对仍失败的题目做独立失败归因。结果显示：47.6% 的题目首次尝试即通过全部测试；剩余 87 题中 60.9% 仅靠修改自然语言描述即可解出；失败可归为 Conceptual、Poor Prompts、Verbose Prompts、Ambiguous 四类，类伪代码的改写最有效，而过长提示会因 Codex 解析能力下降而失败。对团队而言，这是提示工程在代码生成场景的早期实证基准，其失败分类法与“解包概念 vs 控制提示长度”的权衡，对设计代码生成/审查工具的提示策略与评测归因流程有直接参考价值。

问题

此前工作只表明 Codex/Copilot 能在首次尝试中解出约一半典型 CS1 编程题，但对模型容易失败的问题类型，以及生成出错时用户如何通过修改自然语言题目描述（提示工程）来修复错误，几乎无人研究。论文要量化 Copilot 在公开题库上的初始成功率、提示工程对剩余失败题目的修复效果，并归纳失败的共性原因。

方法

在 166 道 CodeCheck 公开 Python 编程题上评测 Copilot：先将题目描述（注释+函数签名）原样粘贴到启用 Copilot 扩展的 VS Code 中；对未通过全部测试用例的题目，由作者人工改写自然语言提示（典型做法是追加伪代码式的分步算法提示、显式说明计算步骤与边界条件），再次生成并判题；最后由未参与提示改写的作者对仍失败的 34 题基于原始提示、改写提示与人工解答独立归因，划分为 Conceptual、Poor Prompts、Verbose Prompts、Ambiguous 四类。

关键结果

166 题中 79 题（47.6%）在首次尝试（提示原样输入）即通过全部测试用例

初始未解出的 87 题中，仅通过自然语言修改题目描述即解出 53 题（60.9%）

34 道最终失败题归因：Conceptual 15 题、Verbose Prompts 11 题、Poor Prompts 4 题、Ambiguous 4 题；涉及 6 个特定概念的题目 Copilot 全部失败

CodeCheck 题目平均每题 5.1 个测试用例，“正确性”以通过全部测试用例定义

类伪代码的提示改写最有效；除 SNL 类别外，提示工程在所有初始失败的题目类别中均有一定效果

创新点

此前对 Codex 的评测多基于私有题库且只测首次成功率（如 Finnie-Ansley et al.）；本文首次在公开数据集上系统探索“用提示工程修复代码生成失败”这一交互模式，给出可复现的公开基准与失败类型分类法，并指出“解包概念”与“控制提示长度”之间的张力（Codex 难以解析长提示），以及通过重写而非追加来改写提示的可能方向。
