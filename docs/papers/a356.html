Instruction Bleed: Cross-Module Interference in Prompt-Composed Agentic Systems

Instruction Bleed：提示组合式 Agentic 系统中的跨模块干扰

简介

论文针对提示组合式 Agentic 系统（行为逻辑由多个 markdown/模板模块拼接进同一上下文窗口、由 LLM 通过 attention 解释）中从业者反复报告的失效模式：修改一个提示模块会静默改变语义无关模块的行为。作者将其形式化为 compositional behavioral leakage（CBL），根源是 transformer self-attention 对拼接模块没有形式化隔离边界。他们在部署中的职位评估 Agent（career-ops，Claude Sonnet 4.6，144 次试验）上用三通道扰动协议（容量/内容/格式）验证：仅语义内容通道产生可检测配对效应（Cohen's d=0.63），且无任何推荐翻转——这种亚阈值漂移对检查决策的标准 QA 不可见，但会在大量决策中累积并传入下游排序与聚合。论文进一步给出组合一致性、模块交互回归、格式扰动鲁棒性、模型迁移测试四类提示模块回归测试框架，并指出被调研系统均未实现任何一类。

问题

提示组合式 Agentic 系统中存在从业者所称的 'instruction bleed'：编辑一个非目标提示模块会静默改变语义无关的目标模块行为，且无共享变量或可执行依赖可解释；现有 Agent 基准均不测量这种跨模块行为干扰。论文要给出 CBL 的操作化定义、可复用检测协议与可证伪预测，把跨模块干扰测量确立为提示组合式 Agent 评测的必要环节。

方法

提出 CBL 操作定义：对非目标模块的编辑 e 若引起目标模块行为的可检测配对漂移（配对效应 bootstrap CI 不含零）即判定泄漏。设计可复用三通道扰动协议：C0 基线、C1 容量（追加无关 200 行模块）、C2 内容（向共享规则文件追加语义无关的 'Professional Chef' archetype）、C3 格式（保义结构变更）。在部署的职位评估 Agent career-ops 上以 12 个 JD × 3 次独立运行、Claude Sonnet 4.6 共 144 次试验测量 cv-match 分数，用 Cohen's d、bootstrap 95% CI（10,000 次重采样）与 Bonferroni 校正的 Wilcoxon 符号秩检验分析；并给出四类回归测试框架与三条可证伪预测（跨模型差异、语义距离梯度、阈值穿越随干预幅度扩展）。

关键结果

C2 主检验：向共享规则文件追加一个语义无关的 'Professional Chef' archetype，使 cv-match 产生配对效应 d=0.63（Δ=+0.17，bootstrap 95% CI [+0.03, +0.31] 不含零），12 个 JD 中 8 个上移；条件内 ICC=0.925

对照条件均为零效应：C1（追加无关 200 行模块）d=-0.11、C3（格式扰动）d=-0.29，bootstrap 95% CI 均含零，排除了'任何新增上下文都降低性能'与纯格式通道的解释

所有条件下均无推荐翻转（no recommendation flips），漂移处于亚阈值区间，对检查决策而非分数分布的标准 QA 不可见

实验规模：12 个 JD × 3 次独立运行 × 4 条件 = 144 次试验（Claude Sonnet 4.6）；基线 cv-match 均值 2.72（SD=1.23）

成对交互测试复杂度为 O(n²)：OpenClaw 的 10K+ 社区技能产生超过 5000 万个配对组合；被调研的四个系统（OpenClaw、career-ops、OpenHands、aider）均未实现任何一类提示模块回归测试

创新点

首次把从业者非正式说法 'instruction bleed' 形式化为可操作定义与可测量现象，并论证其与已知失效轴（对抗注入、认知退化、多 Agent 故障传播、组合式隐私泄露）正交：AgentDojo、QSAF、MAS-FIRE 等均不测量同一 Agent 初始化上下文中共驻提示模块的同步行为干扰；同时将格式敏感性（Sclar 等）与 proactive interference 从受控任务扩展到真实 Agent 行为输出，并刻画了文本级拼接组合这一系统类（区别于 DecomP、ModularPrompt、PRopS 等通过显式数学或 API 级机制隔离模块的方案）。

Ching-Yu Lin 1 Yifan Liu 1

Abstract

提示组合式智能体系统（prompt-composed agentic systems）的实践者报告了一种反复出现的失效模式：编辑某一个提示模块会悄然改变其他模块的行为，即使它们之间并不存在共享变量或可执行依赖。我们将这一现象形式化为组合行为泄漏（compositional behavioral leakage, CBL）：即共享同一上下文窗口的模块之间的干扰。CBL 的根源在于架构层面的非隔离性：Transformer 自注意力机制在相互拼接的模块之间不提供任何形式化边界。我们在一个已部署的职位评估智能体（Claude Sonnet 4.6，144 次试验）上，通过一个可复用的三通道协议对 CBL 进行了探测，该协议沿体量（volume）、内容（content）与形式（form）三个通道对非焦点模块施加扰动。只有内容通道产生了可检测的配对效应（Cohen's d = 0.63，bootstrap 95% 置信区间不包含零）；没有任何推荐发生翻转——这一亚阈值状态对标准质量保证（QA）而言不可见，

1. Introduction

提示组合式智能体系统（prompt-composed agentic systems）——即智能体的行为在运行时由自然语言模块组装而成，而非以可执行代码的形式编写，并由大语言模型（LLM）将组合后的上下文解释为智能体的策略——是一种快速增长的部署模式。这些系统的从业者已经报告了一种反复出现的失效模式：编辑一个提示模块会悄然改变某个无关模块的行为，而没有任何共享变量、工具调用或可执行依赖能够解释这一现象（Subrahmanyam, 2025）。因此，风险的所在是组合机制本身，而非任何单个模块。OpenClaw（2026）在生产规模上典型地体现了这种部署模式：379K GitHub 星标和超过 10K 个由社区编写的技能模块，用户将人格定义（SOUL.md）、能力模块（SKILL.md）与编排规则（AGENTS.md）组合成没有任何单一作者能够完全审计的智能体配置。

同样的模式在多种机制选择中反复出现——markdown 约定（Steinberger, 2026; Fern´ andez de Valderrama, 2026）、模板引擎（Wang et al., 2024）以及 Python 类继承（Gauthier, 2023）——其中非平凡的行为逻辑由 LLM 所解释的文本承载，而代码仅限于确定性 I/O（§2，表 1）。

“将提示模块组合起来就会得到其各自行为的组合”这一架构假设并未得到 transformer 自注意力的支持——后者在组合后的上下文中计算全局成对交互，而不具备任何模块级隔离："### Persona" 标题只是一种书写约定，而非命名空间边界。前摄干扰（proactive interference）（Wang & Sun, 2025）与覆盖有界组合泛化（coverage-bounded compositional generalization）（Chang et al., 2026）共同预测：每一种全新的模块组合都是一次分布偏移，其行为后果无法从逐模块评估中推导得出。

然而，目前没有任何现有的智能体基准测试（benchmark）衡量修改一个提示模块是否会悄然改变某个语义上无关模块的行为——这使得模块集偏移下的组合行为成为已部署智能体的首要安全性与可靠性问题。

2.1. The Pattern

提示组合式智能体系统（prompt-composed agentic system）是指这样一类系统：其中非平凡的行为决策逻辑——评分量规、工作流排序、角色设定、工具选择标准——被编码在由人工编写的文本文件中，由大语言模型（LLM）通过注意力机制加以解释，而非通过运行时（runtime）来执行。

2.2. Four Systems

表1调研了四个开源的提示组合式智能体系统，其组合机制横跨一个谱系：从 markdown 约定（Steinberger, 2026; Fern´ andez de Valderrama, 2026），经由 Jinja2 模板（Wang et al., 2024），到 Python 类继承（Gauthier, 2023）。在所有情形下，行为逻辑都驻留在由 LLM 通过注意力机制加以解释的文本之中；代码仅处理确定性的 I/O。随着系统走向成熟，组合方式不断向外迁移（约定 → 模板 → 类继承 → 提示管理服务）——这等于默认承认文本层面的组合是脆弱的。然而，部署最广泛的系统（OpenClaw，以及数千个代码仓库中的 AGENTS.md/CLAUDE.md）仍然在文本层面进行组合。附录 A 提供了各系统的逐一描述以及完整的成熟度演进模式。这种脆弱性在何时、以何种方式显现尚缺乏形式化刻画，这正是我们在 §3 中引入相应定义的动因。

3.1. Operational Definition

设 M = { m 1 , . . . , m n } 为已部署并拼接进大语言模型（LLM）输入上下文的提示模块集合，并令 M ( j ← e ) 表示对非焦点模块 m j 施加编辑 e 之后的同一模块集合。设 s i ( x ; M ) 表示焦点模块 m i 在输入 x 上对应的可观测分数或决策。

当一项并非旨在影响焦点行为的编辑 e 引起可检测的成对偏移时，我们称该系统表现出组合行为泄漏（compositional behavioral leakage, CBL）：

更严格的单例比较 B ( m i |M ) ≈ B ( m i | { m i } ) 是一种组合一致性检验，可视为该回归视角的一个特例。本文聚焦于部署系统场景：对非焦点提示模块的局部编辑是否会在完整部署提示下悄然改变焦点模块的行为。

CBL 与三种相邻的失效模式不同。组合隐私泄漏（Patil et al., 2025）：多智能体输出聚合暴露敏感信息（隐私 vs. 行为；多智能体 vs. 单智能体拓扑）。认知退化（Atta et al., 2025）：跨多步执行的纵向状态漂移（运行时累积 vs. 初始化干扰）。提示注入：对抗性外部输入颠覆行为（恶意 vs. 意外）。从业者非正式地将 CBL 称为“指令渗漏”（instruction bleed）(Subrahmanyam, 2025)；我们将其形式化。

3.2. Mechanisms Predicting CBL

Transformer 大语言模型（LLM）的四个特性使 CBL 具有合理性，并产生可检验的预测。每一项特性都贡献了一种独特的干扰机制；它们共同使组合语法本身成为一种行为变量。

注意力是全局的。Transformer 自注意力在整个输入范围内计算词元之间的两两交互。不存在任何架构机制将注意力限制在单个提示模块内的词元上：### Persona 标题只是一种统计性线索，而非作用域边界，其有效性完全取决于预训练数据中针对类似格式的训练分布先验。因此，基于分隔符的隔离只是一种行为预期，而非保证。这种非隔离特性本身并不能证明任何特定系统中存在渗漏，但它消除了“分隔符分隔的模块会彼此独立行事”这一假设的形式化依据。

前摄干扰。Wang and Sun (2025) 证明，LLM 的检索准确率随累积的干扰上下文呈对数线性下降，即使目标内容被置于紧邻查询之前的位置也是如此。提示工程缓解措施（“忽略之前的输入”、显式作用域指令）效果有限。较早的提示模块会主动劣化后续模块的处理——这是一种工作记忆瓶颈，单模块测试无法检测到它，因为该干扰仅在组合条件下才会显现。

3.3. Existence Proof on a Deployed Agent

We test for CBL in career-ops, a prompt-composed jobevaluation agentic system. The focal module scores job descriptions on a 1-5 rubric across multiple weighted dimensions. We measure cv match , the dimension most directly capturing the module's core evaluation function: how well a candidate's background aligns with the job requirements.

Conditions. Against an unmodified baseline (C0: the deployed system prompt as shipped), we define three conditions that each perturb the non-focal modules along a distinct channel: C1 (module addition - volume ): baseline + an unrelated 200-line recipe-evaluation module. C2 (semantic modification - content ): baseline with a semantically irrelevant archetype appended to the shared rules file (Appendix B). C3 (format perturbation - form ): baseline with meaning-preserving structural changes (heading levels, emoji markers, section reordering) to non-focal modules.

C2 is the primary test: the edit is localized to a non-focal behavioral specification, while the measured outcome is the focal cv-match score. Under the system's stated modular semantics, the added archetype should not systematically change this score; a paired shift therefore indicates crossmodule interference.

4. Related Work

智能体故障模式评估。AgentDojo（2024）评估对抗性注入；QSAF（2025）提出针对认知退化的运行时缓解措施；MAS-FIRE（2026）评估多智能体故障传播；Patil 等人（2025）评估组合式隐私泄露。上述工作均未测量单个 Agent 初始化上下文中共存提示模块之间的同步行为干扰。

提示敏感性与上下文干扰。Sclar 等人（2024）记录了由语义保持的格式变化引起的准确率波动；PI-LLM（2025）表明检索性能呈对数线性下降，且这种下降对提示工程缓解措施具有抵抗性。我们的贡献将这些发现从受控任务扩展到真实 Agent 的行为输出。

模块化提示。DecomP（2023）通过多次调用编排来分解任务；ModularPrompt（2022）、PRopS（2023）和 Smart MoP（2025）通过软提示以及可微或 softmax 门控实现模块化。这些方法均通过显式的数学或 API 级机制来隔离模块；而我们研究的系统则在文本层面通过拼接进行组合，除注意力机制外没有任何隔离。

组合泛化。Skill-Mix（2024）表明前沿模型能够组合技能，但随技能数量增加而出现退化。Chang 等人（2026）形式化地表明，组合泛化受训练分布覆盖范围的约束；Dziri 等人（2023）表明 Transformer 在组合深度增加时会坍缩为模式匹配。因此，当新颖的模块组合缺乏覆盖时，模型层面的组合能力不足以保证干净的组合。

Impact Statement

本文识别了提示组合式智能体系统中的一种失效模式，该模式可能影响基于评分的决策的可靠性。在此类评分会影响个人结果的应用中——如招聘、信贷、分诊——即使是阈下（subthreshold）的行为偏移也会引发公平性方面的担忧。我们的贡献是诊断性的：我们对一种既有现象进行了形式化描述与测量，以便为缓解措施提供支持，而非引入可能被滥用的新能力。

A. Extended System Descriptions

本附录详细阐述表 1 中总结的四个提示组合式智能体系统，给出各系统的具体描述以及 §2 中所引用的成熟化模式。

OpenClaw。OpenClaw（2026）（37.9 万 GitHub stars）以最大规模体现了这一范式。用户编写人格文件（SOUL.md）、能力模块（SKILL.md）与编排规则（AGENTS.md），这些内容在启动时被拼接进系统提示词（Steinberger, 2026）。超过 1 万个由社区编写的技能可从公共注册表安装，且技能上下文之间没有任何沙箱隔离——组合完全由大语言模型（LLM）的注意力机制来解析。

career-ops。career-ops（2026）是一个职位评估流水线，使用 18 个带有显式交叉引用的 markdown 模式文件。所有行为逻辑——原型分类体系、评分细则、决策阈值——均驻留在 markdown 中；代码仅处理输入/输出（I/O）。

OpenHands。OpenHands（2024）使用 Jinja2 模板化来实现模块化组合，但渲染后的提示词在到达 LLM 之前仍会被拼接进单个上下文窗口。

aider。aider（2023）将提示词编码为 Python 字符串常量，置于继承自 CoderPrompts 基类的类中。这是其中最接近代码的机制——但这些字符串仍然是通过注意力机制来解释的自然语言行为规范。

成熟化模式。随着系统走向成熟，组合逐渐从提示词迁移到代码或外部服务中（约定 → 模板 → 类继承 → 提示词管理服务）——这等于默认承认文本层面的组合是脆弱的。然而，部署最广泛的系统（OpenClaw，以及数千个代码仓库中的 AGENTS.md/CLAUDE.md）仍然在文本层面进行组合，其组合在运行时由 LLM 的注意力机制解析，而非通过任何显式的隔离原语。
