WebGPT: Browser-assisted question-answering with human feedback

WebGPT：基于浏览器辅助与人类反馈的问答

简介

论文针对长文本问答（LFQA）质量落后于人类的问题，提出不改进检索与合成组件本身，而是用人类反馈把两者更好地结合起来：让 GPT-3 在一个基于文本的网页浏览环境中调用 Bing 搜索、点击链接、滚动并摘录引用，再基于引用撰写带参考来源的答案。训练上采用 behavior cloning（约6,000条人类示范）、reward model（约21,500条人类两两比较）、RL 与 rejection sampling 四种方法，最优模型为 175B BC + best-of-64。结果显示其答案在 56% 的情况下被人类偏好于人类示范者、69% 偏好于 Reddit 最高赞答案，TruthfulQA 上真实率 75%，且 rejection sampling 收益显著大于 RL。对团队而言，这是"搜索即工具 + 状态摘要作为上下文 + 引用支撑可信度 + 人类偏好评测"的早期完整范式，其环境设计、上下文组织与评测方法论至今仍有直接参考价值。

问题

长文本问答（LFQA）要求对开放式问题生成段落长度的回答，现有系统性能落后于人类，而已有工作多聚焦于分别改进信息检索与答案合成两个组件。论文要解决的是：如何用现成的搜索引擎与 GPT-3，通过更忠实的训练目标（人类示范与人类偏好反馈）直接优化答案质量，并通过让模型在浏览时收集引用来降低人类评估事实准确性的难度。

方法

设计了一个基于文本的网页浏览环境：模型每步收到环境状态的文字摘要（问题、当前页面光标处文本等），须输出搜索、点击链接、滚动、引用摘录等有限命令之一，随后以全新上下文重复该循环，跨步记忆仅保留在状态摘要中；摘录的页面标题、域名与文本被记录为引用，浏览结束后模型基于问题与引用撰写最终答案。训练流程包括：用约 6,000 条人类示范做 behavior cloning、用约 21,500 条人类比较训练 reward model、对 reward model 做 RL（PPO）与 rejection sampling（best-of-n）；最优模型为 175B BC + best-of-64，并通过在 episode 末尾插入 answering-only episodes 提升样本效率。

关键结果

175B best-of-64 模型的答案在 56% 的情况下被人类偏好于人类示范者的答案，在 69% 的情况下被偏好于 ELI5（Reddit）最高赞答案

TruthfulQA 上答案真实率为 75%、既真实又有信息量的比例为 54%，所有 WebGPT 模型在两项指标上均优于所有 GPT-3 基线，但仍低于人类水平

rejection sampling 收益显著：175B best-of-64 BC 模型被偏好 68% 优于 175B BC 模型；175B RL 模型被偏好 58% 优于 175B BC 模型；RL 与 rejection sampling 结合未带来显著额外收益

Scaling 规律：示范数据翻倍使策略 reward model 分数提升约 0.13；比较数据翻倍使 reward model 准确率提升约 1.8%；策略参数翻倍提升约 0.09；reward model 参数翻倍提升约 0.4%

TriviaQA 上 175B BC 模型在无 test-train 重叠问题上略优于 UnitedQA-E，在有重叠问题上略差

数据规模：约 6,000 条示范、约 21,500 条比较（reward model 训练用约 16,000 条）；标注一致性为研究者-标注者 74%、标注者-标注者 73%

在 episode 末尾插入 15 个 answering-only episodes 使 RL 样本效率提升约 2 倍

创新点

与 DPR、REALM、RAG 等将检索建模为可微过程并端到端训练检索器不同，论文直接把检索外包给 Microsoft Bing Web Search API，把重点放在用人类反馈（behavior cloning、reward modeling、RL、rejection sampling）优化整体答案质量；并要求答案附带浏览中收集的引用以支持人类对事实准确性的评估（该想法此前由 Metzler et al. [2021] 提出）；据论文结果，其模型在 ELI5 上达到对人类示范者 56% 的偏好率，展示了类人水平的文本浏览器使用能力。
