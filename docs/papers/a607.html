Fact-Checking Complex Claims with Program-Guided Reasoning

基于程序引导推理的复杂声明事实核查（ProgramFC）

简介

该论文解决复杂声明的事实核查问题：真实世界声明往往需要收集多条证据并做多步推理，而已有方法要么缺乏可解释性、要么依赖大量任务特定标注数据。方法上提出 PROGRAMFC，采用'程序生成-执行'范式：先用 Codex 通过 in-context learning（仅 20 个示例）为声明生成 Python 风格的推理程序，再由解释器逐步执行，把每个子任务委派给 Question/Verify/Predict 等专用函数，支持开卷（BM25 检索）与闭卷（参数知识）两种证据设置，并生成 N=5 个候选程序做多数投票聚合。关键结论：在 HOVER 与 FEVEROUS 上超过 7 个 few-shot 基线，推理深度越大优势越明显；程序引导的迭代检索将 recall@10 最高提升 37.1%；用 80M 小模型做子任务求解器可媲美 11B 端到端模型，但计算耗时约为端到端模型的 45 倍。

问题

验证真实世界的复杂声明需要收集多条证据并进行多步推理；现有事实核查模型要么推理过程缺乏可解释性，要么需要大量任务特定训练数据。论文希望在 few-shot 条件下构建既可解释又数据高效的事实核查模型。

方法

提出 PROGRAMFC，采用'程序生成-执行'范式：用 Codex 以 in-context learning（20 个 (claim, program) 示例、temperature 0.7 采样解码）生成 Python 风格推理程序，每步为 V_i = f_i(A_i) 形式的函数调用；再由解释器顺序执行程序，将各子任务委派给 Question()、Verify()、Predict() 三个专用子任务函数，支持开卷（BM25 检索）与闭卷（仅参数知识）设置；生成 N=5 个多样化候选程序并多数投票聚合；开卷设置下按程序步骤做迭代式逐步检索。

关键结果

在 HOVER 与 FEVEROUS-S 的 8 项评测中 7 项取得最佳，超过 7 个 few-shot 基线

HOVER 上 ProgramFC (N=5) 在 2-hop/3-hop/4-hop 声明上平均超过基线 10.38%/11.37%/14.77%，推理深度越大优势越大

DeBERTaV3-NLI 的 F1 从 2-hop 的 77.22 降至 4-hop 的 60.49（下降 21.7%），而 ProgramFC 仅下降 11.7%

相比直接用 FLAN-T5 一步验证，程序分解平均带来 6.0%（gold evidence）/4.5%（open-book）提升，4-hop 声明上分别达 14.9%/6.7%

聚合 N=5 个推理程序比单程序平均提升 1.5%

迭代检索的 recall@10 在所有数据集上超过一步检索，HOVER 4-hop 上最大提升 37.1%

用 FLAN-T5-small (80M) 作子任务求解器，在 4-hop 声明上可达到 137 倍大的 FLAN-T5-XXL (11B) 端到端推理的可比性能

错误分析：300 个错误预测样本中无语法错误；2-hop 声明 71% 的程序正确，声明越复杂语义/结构错误比例越高

闭卷设置下多数模型在 HOVER 上仅略高于随机猜测；CoT 比直接提示平均高 2.7 分

计算耗时约为端到端 FLAN-T5 模型的 45 倍

创新点

与原始 CoT 用单一 LLM 同时完成分解与问答不同，PROGRAMFC 仅用 LLM 生成推理程序作为解题蓝图，把子任务委派给专用函数，降低对语言模型的负担并便于接入检索器等组件；与注意力权重、逻辑规则、证据摘要等事后解释不同，程序本身既是推理引导也是解释；属于 tool-augmented language model 思路在事实核查上的实例化。
