Structure Guided Large Language Model for SQL Generation

简介

该论文针对 LLM 在 Text-to-SQL 任务中难以理解复杂数据库结构、准确解析用户意图并生成语法正确 SQL 的问题，提出结构引导框架 SGU-SQL。方法上，先将自然语言查询（句法解析+指代消解）与数据库 schema 分别建模为图结构，用 RGAT 图神经网络通过对比训练实现 query-schema 的结构感知链接；再基于上下文无关语法树把生成任务按非终结节点分解为子任务，引导 LLM 依据子任务上下文增量生成 SQL。在 Spider 与 BIRD 两个基准上全面超越 SOTA，Spider-dev 执行准确率达 87.95%；其结构化分解提示比 CoT 平均高 5.03%，迁移到 GPT-4 可带来近 11% 提升。对团队最有价值的结论是：朴素 CoT 分解对 SQL 这类强结构输出生成无效甚至有害，按输出语法结构动态分解、配合结构化的 schema 上下文链接才是提升关键。

问题

LLM 在 Text-to-SQL 中面临三大障碍：❶自然语言用户意图模糊（如 last quarter、better than average 等表述难以精确解析）；❷自然语言术语到复杂数据库表/列的映射困难（schema 复杂、命名不直观、跨表同名列易混淆）；❸SQL 语法结构复杂（嵌套子查询、聚合函数、窗口操作等要求高精度）。已有分解式方法因 SQL 的声明式结构与查询概念和数据库元素间的复杂关联，难以有效拆解任务。

方法

SGU-SQL 包含三个核心组件：(1) 图结构构建——将用户查询（经 context-free grammar 句法解析与 coreference resolution）与数据库 schema（表/列节点及外键等关系边）分别表示为图；(2) 结构感知链接——用 Relational Graph Attention Network (RGAT) 编码两类图，先字符串匹配出候选节点，再对每个候选构建 enclosing subgraph 并以对比训练（正/负样本）学习查询概念与数据库元素的匹配分数，并补充预定义语义关系；(3) 语法引导分解生成——将查询语法树的每个非终结节点映射为 SQL 子任务，LLM 以自然语言查询加子任务上下文（父节点、兄弟节点等）为输入逐段生成 SQL 组件，最终从根节点组合成完整 SQL。

关键结果

SGU-SQL 在 Spider-dev 上执行准确率达 87.95%，在 Spider 与 BIRD 两个基准上超越 11 个 fine-tuning 类、7 个 structure-learning 类、11 个 in-context-learning 类 SOTA 基线

结构化分解提示相比 CoT 平均提升 5.03%，相比 few-shot prompting 平均提升 4.98%

CoT 在 PaLM-2 上相比 naive few-shot prompting 反而下降 1.08%，说明简单分解对 Text-to-SQL 无效

将 SGU-SQL 提示策略迁移到不同 LLM：PaLM-2 提升 4%、CodeX 提升 3%、ChatGPT 提升 5%、GPT-4 提升近 11%，且推理能力越强的 LLM 获益越大

相比基线模型错误总数减少约 33.5%，其中 schema-linking 类错误减少约 38%，Group-by 与 Join 类错误减少 35%

消融实验：去掉分解策略 Spider-dev -5.60%、BIRD-dev -8.02%；去掉结构感知链接 Spider-dev -5.33%、BIRD-dev -6.49%；去掉查询图 -3.45%/-2.87%；去掉数据库图 -2.14%/-3.54%

GPT-4o 骨干下 BIRD dev 执行准确率 69.28%，高于 PURPLE（68.12%）、CHESS（68.31%）、E-SQL（65.58%）、Distillery（67.21%），仅低于使用 Gemini 1.5 Pro 且带 query fixer 的 CHASE-SQL

在 BIRD challenging 集上，训练与推理耗时均低于 DIN-SQL 与 MAC-SQL，原因是图结构方法减少了对多次 GPT-4 API 调用的依赖

创新点

区别于使用固定分解模式的 DIN-SQL、以及依赖 LLM 黑盒理解做分解的 ACT-SQL/MAC-SQL，SGU-SQL 依据用户查询的上下文无关语法树动态分解生成任务，使分解与 SQL 的元操作结构对齐；同时用经对比训练的 RGAT 图神经网络做 query-schema 结构链接，替代将 schema 以纯文本直接输入 LLM 的做法；生成过程单遍完成，不依赖执行反馈迭代修复。
