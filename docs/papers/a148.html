GNN-RAG: Graph Neural Retrieval for Large Language Model Reasoning

GNN-RAG：面向 LLM 推理的图神经网络检索

简介

论文解决 KGQA 中 RAG 检索质量不足的问题：基于 LLM 的检索器难以处理 KG 的复杂多跳图结构，检索不全或含噪都会拖累 LLM 推理。方法上提出 GNN-RAG：先由 GNN 在稠密 KG 子图上做答案节点分类得到候选答案，再抽取问题实体到候选答案的最短路径作为推理路径，文本化后作为 LLM RAG 的上下文输入；并设计检索增强（RA），将 GNN 检索与 LLM 检索（或双 GNN 集成）的路径取并集提升召回。关键结论：在 WebQSP 与 CWQ 上达到 SOTA，7B 微调 LLM 即超过或持平 GPT-4，多跳/多实体问题 F1 领先 8.9-15.5 个百分点，且不增加额外 LLM 调用，可部署于单张 24GB GPU。其'检索质量决定 RAG 上限、检索器与推理器分工、多检索器融合'的思路对团队 RAG 与知识库问答建设有直接借鉴价值。

问题

KGQA 的 RAG 流程中，检索性能高度依赖所检索到的 KG 事实；现有基于 LLM 的检索方法无法有效处理 KG 中复杂的图结构信息，在多跳问题上表现不佳，且检索到不相关信息会干扰 LLM 推理。

方法

GNN-RAG 框架：(1) GNN 作为稠密子图推理器，在问题相关子图上做节点分类（答案 vs 非答案），输出高概率候选答案；(2) 用最短路径算法抽取问题实体与候选答案之间的 KG 路径作为推理路径，按 '{entity} → {relation} → {entity}' 格式文本化；(3) 文本化路径与问题一起填入 prompt 模板，供微调后的 LLM（LLaMA2-Chat-7B）做 RAG 推理。另提出 RA 检索增强：推理时将 GNN 检索路径与 LLM 检索器（RoG）路径取并集（GNN-RAG+RA），或将两个配备不同预训练 LM（SBERT/LMSR）的 GNN 路径集成（GNN-RAG+Ensemble），兼顾多跳与单跳问题的召回。

关键结果

在 WebQSP 与 CWQ 两个 KGQA 基准上取得 SOTA；7B 微调 LLM 的 GNN-RAG 超过或持平 GPT-4（ToG+GPT-4）

多跳与多实体问题上 answer F1 领先竞争方法 8.9-15.5 个百分点；对 RoG 在多跳问题上 F1 领先 6.5-17.2（WebQSP）/8.5-8.9（CWQ）个百分点

GNN-RAG+RA 在 Hit 上超 RoG 5.0-6.1 个百分点、超 ToG+ChatGPT 最多 14.5 个百分点；较最佳 GNN 方法 Hits@1 领先 5.3-9.5、F1 领先 0.7-10.7 个百分点

作为检索器接入不同 LLM 时提升普遍：ChatGPT 的 Hit 较 RoG/ToG 提升最多 6.5 个百分点；对 Alpaca-7B、Flan-T5-xl 等较弱 LLM 提升最多 13.2 个百分点，且无需重训 LLM

效率：ToG+GPT-4 估计成本超 $800，GNN-RAG 可部署在单张 24GB GPU；相同 LLM 调用次数下较 vanilla LLM 提升 149-182%（F1），LLM 检索改用 greedy 解码会损失 8.3-9.9 个百分点 Hit

检索分析：深度 GNN（L=3）在多跳问题上比 LLM 检索器与浅层 GNN 更高效（Answer Coverage 更高、#Input Tokens 更少）；GNN 弱于单跳语义匹配，RA 在单跳问题上再提升 0.8-2.6 F1

MetaQA-3 上 Hit@1 达 98.6%；弱 GNN（NSM/GraftNet）检索较 ReaRev 低 9.2-9.8 个百分点（H@1）

Prompt 消融显示 GNN-RAG 在三种不同 prompt 模板下均优于 RoG，对 prompt 选择鲁棒

创新点

已有 KGQA 中 LLM-based 检索（ToG、RoG）用 LLM 同时承担检索与推理，需多次 beam-search 生成才能覆盖多跳路径；GNN-RAG 将 GNN 重新定位（repurpose）为检索器，利用其处理复杂图结构的能力做稠密子图推理，LLM 仅负责最终推理，形成'GNN 检索 + LLM 推理'的 RAG 分工。并通过 Answer Coverage/#Input Tokens 的检索分析与定理刻画 GNN 擅长多跳、弱于单跳语义匹配的边界，据此设计 GNN+LLM 混合检索增强（RA），在不增加 LLM 调用的前提下提升效果。
