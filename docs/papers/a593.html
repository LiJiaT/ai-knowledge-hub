Tab-CoT: Zero-shot Tabular Chain of Thought

Tab-CoT：零样本表格化思维链（Tabular Chain of Thought）

简介

该论文针对 zero-shot 场景下难以给 CoT 推理注入显式结构的问题，提出 Tab-CoT：在问题后附加 '|step|subquestion|process|result|' 这样的表头作为提示，让 LLM 以逐行填表的方式生成二维结构的推理过程，再用 'the answer is' 提示从表格中抽取最终答案。表格的行列结构使模型能同时沿行（步骤推进）与列（字段对齐）推理，输出比常规 CoT 更简洁、更易解析。在 6 个算术推理数据集上，zero-shot Tab-CoT 配合 code-davinci-002 在 6 项任务中 5 项超过常规 zero-shot CoT，平均提升 2.2%；few-shot 下平均超过 CoT 1%。消融显示去掉任一列都会掉点（去掉 subquestion 平均降 5.4%），且 code 模型比 text 模型更适合表格推理。对团队而言，这是一种零训练成本、可直接复用的提示模式，适合需要结构化、可解析中间推理的自动化流水线。

问题

zero-shot 提示难以向 CoT 推理过程注入结构；已有的结构化推理提示方法（如 Least-to-Most、PAL）需要针对不同领域做专门的提示工程或定义多个变量，难以维护和追踪。论文希望找到一种任务无关、zero-shot 可用、能让推理过程显式高度结构化的提示机制。

方法

Tab-CoT 采用两段式提示：(1) table generation——在问题后附加表格表头（如 '|step|subquestion|process|result|'），利用 '|' 作为 OpenAI 模型可识别的表格分隔符，迫使 LLM 逐行填表完成 step-by-step 推理；(2) answer extraction——在生成的表格后附加 'the answer is' 提示抽取最终答案。提出 structure-promoting scheme：step 列组织行序、subquestion 列纵向形成逐步指令、process 列承载推理过程、result 列强制每步给出（中间）答案。表格的二维结构支持横向（行内）与纵向（跨行）同时推理；还可选取 3 个不同表格 scheme 做 3 路多数投票（self-consistency）提升鲁棒性。

关键结果

zero-shot 下，Tab-CoT（code-davinci-002）在 6 个算术推理数据集中的 5 个超过最佳常规 zero-shot CoT，平均提升 2.2%，且在所有任务上显著优于 standard prompting

Tab-CoT 下 code 模型比 text 模型高 4.0%；而常规 CoT 下 text 比 code 高 10.9%（standard prompting 下差距为 15.7%），说明表格提示更能释放 code 模型的推理能力

消融实验：从 '|step|subquestion|process|result|' 中去掉任一列都会导致性能下降；去掉 subquestion 平均降 5.4%，去掉 step 列降幅最大

few-shot 下 Tab-CoT 平均超过 few-shot CoT 1%，其中 SVAMP 上差距达 6.5%

示例中 zero-shot CoT 生成 140 词，Tab-CoT 仅生成 28 词，输出更简洁

用 3 个不同表格 scheme 做 3 路多数投票（self-consistency）可进一步提升整体性能与鲁棒性

在 GPT-3.5-turbo-0301 上 Tab-CoT 仍优于常规 zero-shot CoT；13B 的 code-cushman-001 不具备表格 CoT 能力（除 AQUA 外准确率不到 10%）

Coin Flip 上更 task-specific 的 scheme '|step|initial coin state|flip or not|next coin state|' 仅达 68.0% 准确率，因其禁用了纵向推理

创新点

与 Least-to-Most、PAL 等需要任务特定提示工程、few-shot 样本或外部工具的结构化方法不同，Tab-CoT 仅用一个表头即可在 zero-shot 下注入强结构，且表格 scheme 无需关心语法、易于编写。以往工作多从已有表格数据中抽取信息，而该方法在推理过程中同时生成表格并从表格中抽取答案；论文还通过实验系统揭示了 LLM 在表格上的横向+纵向二维推理现象，以及 code 模型与表格格式的适配性。
