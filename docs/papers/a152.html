TableRAG: Million-Token Table Understanding with Language Models

简介

LM 表格理解通常要把整张表放进提示，面对大表会遇到上下文长度限制、Lost-in-the-Middle 位置偏置以及随规模增长的成本与延迟。论文提出 TableRAG，一个专为表格设计的 RAG 框架：先用 LM 做表格化查询扩展，分别生成面向 schema 与单元格值的查询，再通过 schema 检索（列名+类型+示例值）与 cell 检索（对去重列-值对独立编码，并用频率感知的编码预算 B 截断），只把关键信息交给 ReAct 式 program-aided solver 生成程序作答，使输入 token 复杂度与表大小无关。作者还基于 Arcade 与 BIRD-SQL 构建了两个百万 token 级基准（ArcadeQA、BirdQA）。实验显示 TableRAG 在多个 LM 上准确率与检索质量均为最优，schema/cell 检索分别最高带来 9.4%/11.5% 提升，并在 WikiTableQA 上超过已有 SOTA。其查询扩展、预算化检索与成本分析对团队的知识库问答与长上下文管理有直接借鉴价值。

问题

LM 表格理解方法通常需要把整张表放入提示，导致上下文长度超限（如 100 列×200 行即超 40,000 token）、Lost-in-the-Middle 位置偏置以及随表规模增长的计算成本与延迟；已有的行-列检索方法（如 ITR、TAP4LM）仍需编码整行整列，对百万单元格级别的表不可行，且把长行/列压缩成固定大小向量会掩盖语义（尤其当内容是数值等语义稀疏内容时）。

方法

TableRAG 是面向表格理解的 RAG 框架，包含四个核心组件：(1) 表格化查询扩展——用 LM 针对问题分别生成面向 schema 与单元格值的多条查询；(2) schema 检索——仅编码列名，检索结果附带数据类型与示例值（数值/日期列给 min/max，类别列给最高频 3 个值）；(3) cell 检索——对去重后的列-值对独立编码建库，并引入频率感知的编码预算 B（论文取 10,000），只编码最高频的 B 个值；(4) program-aided solver——基于 ReAct 的 Agent 通过 python_repl_ast 执行 Python 程序作答。整体 token 复杂度为编码 O(min(D,B))、推理 O(K)，均与表大小无关。

关键结果

构建两个百万 token 级新基准：ArcadeQA（平均 79,000 行、最多 700 万单元格）与 BirdQA（平均 62,000 行、峰值 1,000 万单元格），并将 TabFact 合成扩展至 1000×1000（百万单元格）

在 GPT-3.5-turbo、Gemini-1.0-Pro、Mistral-Nemo-Instruct-2407 三个 LM 上，TableRAG 在 ArcadeQA 与 BirdQA 上均取得最高准确率，优于 ReadTable、ReadSchema、RandRowSampling、RowColRetrieval

检索质量评估中，TableRAG 在列检索与单元格检索的 recall/precision 上均为最优

合成 TabFact 规模实验中，TableRAG 随表扩大从 83.1 温和降至 68.4（1000×1000），而 ReadTable 在 100×100 及以上因上下文长度限制直接失败

消融实验：schema 检索最高带来 9.4% 准确率提升，cell 检索最高带来 11.5% 提升；查询扩展在所有数据集与 LM 上一致提升性能

在 WikiTableQA 小规模基准上超过 TaBERT、Text-to-SQL、Binder、Dater 等已有方法

token 复杂度分析：编码 O(min(D,B))、推理 O(K)，与表大小无关；从 10^6 个元素计算去重值在个人笔记本上仅需 60 ms

创新点

区别于整表入提示（ReadTable）、只读 schema（ReadSchema/Text2SQL 类）与行-列整体编码检索（ITR、TAP4LM），TableRAG 首次将 schema 检索与选择性单元格值检索、频率感知截断相结合，使 LM 输入长度与表规模解耦；单元格级独立编码避免了长行/列压缩成固定向量的语义损失；同时首次构建了百万 token 级的表格理解评测基准填补评测空白。
