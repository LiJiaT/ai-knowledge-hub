InftyThink: Breaking the Length Limits of Long-Context Reasoning in Large Language Models

InftyThink：突破大语言模型长上下文推理的长度限制

简介

长链推理（Long-CoT）随序列长度呈 O(n²) 计算增长，且受最大上下文限制导致推理被截断。InftyThink 把整体式推理改造为'短段推理+中间总结'的迭代范式：每段在高效 token 预算内生成，用 <summary> 标签总结当前进展，下一段仅以 <history> 中的摘要为上下文继续推理，形成锯齿状内存占用曲线，使推理深度与上下文窗口解耦。作者还提出三步数据重建流水线，将 OpenR1-Math 的 220K 长推理样本按语义切分并用 Llama-3.3-70B 生成摘要，扩展为 333K 迭代式 SFT 训练实例。实验显示 Qwen2.5-Math-7B 在 MATH500/AIME24/GPQA_diamond 上提升 2%/11%/9% 且推理延迟下降；OpenThoughts 数据上准确率提升 7-8 个百分点、延迟降低约 30-40%。关键工程启示：纯 prompt（免训练）方式实现该范式会掉点且延迟显著更高，落地需 SFT 让模型适配迭代格式。

问题

长上下文推理范式存在三大瓶颈：decoder 架构计算随序列长度二次增长导致资源开销过大；推理受最大上下文长度（max_length）限制，复杂问题的推理被截断而无法得出结论；多数模型预训练上下文窗口仅 4k-8k token，超出边界后性能退化。现有方法（如 CoT-Valve、TokenSkip、LightThinker）多在单次连续推理链内做压缩，未解决根本的计算扩展问题。

方法

InftyThink 将整体式推理改造为多段迭代：每轮在高效 token 预算内生成推理段，用特殊 token <summary></summary> 输出当前进展摘要；下一轮仅以 <history></history> 包裹的前序摘要为上下文继续推理，直到某轮产出结论而非摘要即终止（设 max_iters=10 防止死循环）。配套数据重建流水线：(I) 按语义边界将长推理切分为不超过 η（4k）的片段；(II) 用 Meta-Llama-3.3-70B-Instruct 基于累积推理轨迹 (RP1,...,RPi) 生成摘要以保持全局连贯；(III) 重组为多轮训练实例做 SFT。摘要生成 prompt 采用多轮对话模板（附录 P）。

关键结果

Qwen2.5-Math-7B 在 MATH500/AIME24/GPQA_diamond 上分别提升 2%、11.04%、9.03%（摘要表述为 3-11% 提升）

Qwen2.5-Math-1.5B 三个基准分别提升 4.33%、10.00%、9.41%；小模型相对收益最大，随模型规模增大收益递减

数据重建将 OpenR1-Math 220K 样本扩展为 333K 迭代式训练实例（η=4k），训练总 token 差异小于 5%（6543 vs 6257 步）

OpenThoughts 数据上平均准确率提升 7-8 个百分点，平均推理延迟降低约 30-40%

代码任务：HumanEval 提升 8-10%，MBPP 提升 3-5%

上下文命中分析：16k 限制下 AIME24 有 32% 样本未完成推理，放宽到 32k 后 MATH500 仍有 10% 被长度截断

消融：纯 prompt（免训练）实现迭代推理导致性能轻微下降且延迟显著更高；摘要器模型规模（1.5B-70B）对最终性能影响可忽略；RoPE 线性插值（4k→32k）在所有基准上逊于 InftyThink

η=2k/4k/6k 均稳定优于 baseline 且无统一最优值；AIME24 上性能随迭代轮次 1→10 持续上升，第 10 轮比第 5 轮 AIME25 约再提升 5%

创新点

与已有工作在单次连续推理链内做压缩（CoT 链压缩、KV cache 压缩、长度惩罚 RL）不同，InftyThink 改变推理范式本身：以'分段推理+周期性摘要'实现推理深度与上下文窗口/计算成本的解耦，无需修改模型架构即可获得无界推理深度与有界内存占用（锯齿状模式）。同时提供了把现成长 CoT SFT 数据集系统性重建为迭代格式的自动化流水线，并证明摘要器模型规模对效果影响可忽略、小至 1.5B 的摘要器即可低成本完成数据转换。
