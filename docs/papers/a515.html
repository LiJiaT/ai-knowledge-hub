Prompt Programming for Large Language Models: Beyond the Few-Shot Paradigm

面向大语言模型的 Prompt 编程：超越 Few-Shot 范式

简介

论文质疑 GPT-3 时代 few-shot 提示的通行解读，认为示例的主要作用是在模型已学会的任务空间中'定位任务'（task location），而非运行时元学习。作者在 WMT'14 Fr-En 翻译任务上实验，发现仅含语言名与冒号的极简 0-shot prompt 的 BLEU 超过原 GPT-3 论文风格的 10-shot prompt，且 1-shot 因示例的'语义污染'反而显著差于 0-shot，说明模型 0-shot 能力被普遍低估。基于此，论文从自然语言符号学视角系统化 prompt 编程方法：直接任务指定、示例指定、文化锚点（memetic proxy）代理指定、以'约束行为'思路排除不想要的续写、通过 serial reasoning 为封闭式问题提供'草稿空间'并延迟结论，以及让模型自己生成任务特定 prompt 的 metaprompt 编程。关键结论是：prompt 应按自然语言写作规律设计并追求'只允许想要的行为'，metaprompt 可自动化 prompt 生成并支撑大规模评测，同时需防范多步生成中的 derailment 风险。

问题

主流 few-shot 提示范式可能无法充分探测大模型的已有能力，且对示例作用的解释（元学习）存在误导。论文要澄清 few-shot 示例的真实功能是任务定位而非运行时学习，并建立一套超越 few-shot 的自然语言 prompt 编程方法论，以更好地控制和评测大语言模型。

方法

以 GPT-3（OpenAI API 的 Babbage/Curie，engine=davinci, temperature=0）为案例，在 WMT'14 Fr-En 翻译任务上用 SacreBLEU 对比 0/1/10-shot 不同 prompt 格式；随后提出自然语言符号学框架下的 prompt 编程方法体系：(1) 直接任务指定（构造 signifier）；(2) 示例指定（将示例嵌入明确其独立性的上下文）；(3) memetic proxy（用人物/情境等文化锚点编码复杂意图，如师生对话框架）；(4) 约束行为视角（prompt 不仅要与期望续写一致，还要与不期望续写不一致）；(5) serial reasoning（step-by-step、self-criticism/debate、用 'Let's consider each of these answer choices' 等种子延迟结论、基于逐 token 条件概率信号在推理结束时注入 'Thus, the correct answer is'、fill-in-the-blank 模板控制 derailment）；(6) metaprompt 编程（如 'Let's solve this problem by splitting it into steps'、Expert Generator 叙事模板），把编写任务特定 prompt 的工作交给模型本身。

关键结果

在 WMT'14 Fr-En 翻译任务上，仅包含两种语言名称与冒号的极简 0-shot prompt 的 BLEU 超过原 GPT-3 论文风格的 10-shot prompt（具体数值见论文 Table 1，正文文本未列出数字）

colon prompt 的 1-shot 显著差于 0-shot，作者归因于 1-shot 示例造成的语义污染（semantic contamination），并指出该现象在多任务的 low-shot prompt 中普遍存在

原 GPT-3 论文中表现最差的 0-shot prompt（尤其是问答类基准）大多可通过使其更接近人类自然语言书写习惯的简单格式修改而改进，即 GPT-3 的 0-shot 基线被显著低估

创新点

区别于当时以微调、梯度式 prompt 优化、专用适配网络和动态示例选择为主的研究路线，本文将散落于博客与社区的 0-shot 自然语言 prompt 技巧初步形式化；提出 few-shot 的作用是'任务定位'而非元学习的新解读；引入 memetic proxy、'约束行为'设计观、仅靠 prompt（无需人在回路或专用架构）实现的 serial reasoning，以及 metaprompt 编程（模型自生成 prompt）等概念，并给出改进基准评测的具体方向。
