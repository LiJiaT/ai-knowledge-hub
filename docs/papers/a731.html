Large Language Models in the Workplace: A Case Study on Prompt Engineering for Job Type Classification

工作场所中的大语言模型：面向职位类型分类的提示工程案例研究

简介

该论文是 Bright Network 的工业案例研究，解决真实生产环境中的 Graduate Job Classification 任务：每天超过 2 万条职位发布中自动判断是否适合应届毕业生，且要求在 95% 召回约束下尽量提高精度。作者对比了 keyword/regex、SVM、ULMFiT、DeBERTa-V3 等监督方法与 GPT-3.5 系列 LLM 的 zero-shot/few-shot 分类，并以 ChatML 格式系统迭代提示词（system message 角色设定、zero-shot CoT、mocked-exchange 确认、指令重申、命名助手、正反馈等）。关键结论是：精心设计的 zero-shot gpt-3.5-turbo 提示在 P@95%R 上超过最佳监督方法约 6 个百分点，提示迭代将 F1 从 65.6 提升到 91.7；其中角色指令带来最大单项提升（+5.9 F1），而 few-shot CoT 在所有尝试中均不如 zero-shot。论文还提出 Template Stickiness 度量输出格式遵从性，并坦承无法从理论上解释为何命名、正反馈等微小改动会显著影响性能。

问题

在真实生产环境中自动判断职位发布是否适合应届毕业生（Graduate Job Classification）：每天超过 25,000 条职位中仅不到 5% 适合毕业生，漏报会将有价值的职位从求职者视野中移除，误报过多则使推荐列表噪声过大；同时该任务依赖对职位描述中微弱语言信号的理解。论文借此系统评估 LLM 提示工程对下游分类性能的影响。

方法

在统一的 10,000 条 gold standard 数据集（7,000 训练/3,000 测试，分层划分）上对比 keyword/regex、SVM+tf-idf、ULMFiT、DeBERTa-V3 微调与 GPT-3.5 系列（text-davinci-002/003、gpt-3.5-turbo）的 zero-shot/few-shot 分类；主指标为 GRAD 标签的 Precision@95% Recall。提示工程按 ChatML 格式逐项消融：zero-shot 基线、few-shot CoT、Zero-shot CoT（Let's think step by step）、system message 中的角色与任务指令（rawinst/sysinst/bothinst）、mocked-exchange 确认、指令重申、loose/strict 答案模板、命名助手、正反馈等；并提出 Template Stickiness（输出符合指定格式、无需额外解析的比例）作为格式遵从性度量。

关键结果

精心设计的 zero-shot gpt-3.5-turbo 分类器优于所有其他模型，P@95%R 比最佳监督方法高 6%（正文第 4 节称在 P@95%R 指标上领先 7.2 个百分点）

基线 zero-shot 提示仅达 F1 65.6（Recall 70.6），最终提示达 F1 91.7、Recall 97%

以 system message 提供角色描述加任务指令带来最大单项提升 +5.9 F1；mocked acknowledgement 再 +1.3 F1 并使模型达到 95% 召回阈值

few-shot CoT 提供示例在所有尝试中均不如 zero-shot 分类，作者推测是示例过度偏置了模型推理

DeBERTaV3 在 P@85%R 上最高，但在 P@95%R 上被 davinci-003 与 GPT-3.5 超越；davinci-002 未能达到 95% 召回阈值

strict/loose 答案模板显著提高 Template Stickiness 但降低分类性能；命名助手与正反馈等微小改动均带来性能提升

创新点

区别于纯学术基准工作，这是少见的真实生产环境（每日 2 万+ 职位、已部署上线）下的提示工程系统消融案例：以生产约束导向的 P@95%R 指标对比 LLM 与监督微调方法，量化了 system message 角色、mocked-exchange、命名、正反馈等常被非正式讨论但缺乏实证的提示技巧的实际影响，并提出 Template Stickiness 这一输出格式遵从性度量；同时给出 few-shot CoT 在该任务上反而劣于 zero-shot 的反直觉实证。
