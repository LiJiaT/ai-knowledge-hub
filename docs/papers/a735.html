Choice Over Control: How Users Write with Large Language Models using Diegetic and Non-Diegetic Prompting

选择优于控制：用户如何使用 diegetic 与 non-diegetic 提示与 LLM 协同写作

mediumarXiv提示技术人机协作基于arXiv版本
下载原文 PDF

简介

论文研究用户在与 LLM 协同写作时如何通过两类提示影响模型：diegetic prompt（作为叙事一部分的草稿文本）与 non-diegetic prompt（不进入最终文档的显式指令）。作者基于 GPT-3（text-davinci-edit-001）构建四种 UI 变体（1 个或 3 个建议 × 有/无指令输入框）加无建议基线，开展 129 人被试内实验，每人完成五段短写作，并记录交互日志与问卷。关键结论：用户整体偏好从多个建议中选择，而非通过写指令控制生成；写 non-diegetic 指令有认知成本（构思与模式切换），仅约五分之一的建议请求附带指令，且以关键词风格为主；指令能把单建议 UI 的接受率从 0.45 提升到 0.65，但仍不及三建议的 0.74；用户还会有策略地组织草稿与请求时机来引导模型。对团队而言，这为内部 AI 工具的"多候选 vs 指令输入"交互设计与用户提示引导提供了实证依据。

问题

论文要解决的问题是：缺乏对终端用户在写作中如何通过草稿文本（diegetic prompt）与显式指令（non-diegetic prompt）两种方式影响 LLM 生成的理解，以及 UI 设计（建议数量、是否提供指令入口）如何影响用户行为、建议接受率与主观感受。研究问题为：How do users write with Large Language Models using diegetic and non-diegetic prompting?

方法

提出 diegetic/non-diegetic 提示的概念框架作为 HCI 分析视角；实现集成式 Web 写作原型（ReactJS + CKEditor5 前端、FastAPI 后端，调用 GPT-3 text-davinci-edit-001，使用"Complete the sentence"等默认指令前缀），将行内单建议、三建议弹窗列表与零-shot 指令弹窗文本框结合；采用 2×2 被试内设计（指令有/无 × 建议 1/3 个）加无建议基线，129 名 Prolific 众包工人各写五段文本，顺序完全平衡；通过交互日志用（广义）线性混合模型 LMM 与 GEE 做统计，Likert 问卷测主观感受，开放反馈用 Grounded Theory 编码，并用 LanguageTool 评估文本质量。

关键结果

共触发 3097 次建议会话；总体接受率均值 0.64（SD 0.29）：单建议 0.55、三建议 0.74、无指令 0.59、有指令 0.69；单建议 UI 下接受率从无指令的 0.45 升至有指令的 0.65，但仍低于三建议

参与者共发送 397 条指令，人均 3.08 条（SD 3.40），平均长度 14.20 字符（2.52 词）；约 19%（每五次一次）的建议请求附带指令；风格上关键词式最常见（171 次），其次祈使式（59 次）、疑问式（12 次）

单建议比三建议在句中更晚约 1.5 词才请求建议（10.93 vs 9.48 词，相对增加 15.3%），且更少在句首（21.70% vs 31.02%）和转折词后（11.80% vs 14.03%）请求

偏好数据：75 人偏好多建议 vs 23 人偏好单建议；21 人偏好可写指令的 UI vs 24 人偏好无指令 UI

GEE 分析：单建议被评得更分心（x=1.95, p<0.005）、更少帮助（x=0.60, p=0.02）、更多手动编辑（x=1.91, p<0.005）、控制感更低（x=0.67, p=0.03）、多样性更差（x=0.67, p=0.04）；指令被评得更分心（x=2.03, p<0.0005）、更多手动编辑（x=1.54, p=0.02），但更能影响建议文本（x=1.92, p<0.001）

共提交 87,640 词，每篇均值 134 词（SD 54）；单建议与有指令时文本显著更短（约少 6-10 词），三建议时更长；拼写/语法错误率 0.0025/词，3.5%（23/645）文本偏离所选主题；接受率与相关工作可比（74% vs 72%），基于指令的接受率（64%）远高于侧边栏设计的 17.6%

创新点

首次提出 diegetic 与 non-diegetic 提示的概念区分作为 HCI 分析视角：此前系统要么只用草稿文本（隐式选择 diegetic 信息），要么把指令提示作为主要交互输出（如 AI Chains、PromptMaker、Story Centaur）；本文首次把零-shot 指令输入直接集成进建议式文本编辑器并研究两类提示的组合使用。同时给出首个大规模（N=129）的建议触发时机分析（此前仅有 N=4 的小规模分析），揭示用户会策略性地用草稿内容与请求时机引导模型，即"主动型"而非仅"被动反应型"的建议使用行为。

理由：论文的核心贡献是提示的人机交互视角：diegetic（草稿即隐式上下文）与 non-diegetic（显式指令）的区分，与团队"上下文组织 vs 显式提示设计"的日常关切相关；"选择优于控制"、写指令有认知与切换成本、关键词式提示最常见等结论，可为内部 AI 工具（代码补全、文档起草、审查建议）的交互设计与面向用户的提示引导提供实证依据；其接受率、触发时机、指令使用率等交互指标也可作为人机协作评测的方法参考。但论文本身是 GPT-3 上的短篇创意/议论文写作 HCI 研究，不涉及 Agent 架构、RAG、上下文窗口管理或工程自动化场景，方法与结论需迁移才能落地，故评为 medium 而非 high。
