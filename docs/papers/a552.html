Using Large Language Models for Knowledge Engineering (LLMKE): A Case Study on Wikidata

使用 Large Language Model 进行知识工程（LLMKE）：基于 Wikidata 的案例研究

简介

论文面向 ISWC 2023 LM-KBC 挑战赛任务：给定来自 Wikidata 的（主语实体, 关系）对，用 LLM 预测零个或多个宾语实体字符串并链接到对应 Wikidata QID，探索 LLM 能否用于知识库的自动补全与纠错。方法上提出 LLMKE 两阶段流水线：先做知识探测，比较 question prompting、triple completion prompting 与检索增强上下文（Wikipedia 首段+Infobox JSON、IMDb 等）三种提示设置，均配 3 个 few-shot 示例并要求返回 Python list 格式；再做 Wikidata 实体映射，用 MediaWiki API 取候选后按关系特点采用 case-based/keyword-based/LM-based 三级消歧。最终以 GPT-4 取得 macro-F1 0.701（各关系从 1.00 到 0.328 不等），获 Track 2 第一名。关键发现：LLM 知识可靠性随领域剧烈波动；检索上下文对 gpt-3.5-turbo 提升 0.055 但对 GPT-4 仅 0.004 且 21 个关系中只有 10 个改善；结论是全自动知识工程尚不可行，仍需 human-in-the-loop。

问题

如何用预训练 LLM 完成 Wikidata 知识库补全任务：给定主语实体与关系，预测宾语实体字符串并正确链接到 Wikidata QID（而非止步于字符串层面）；同时实证评估 LLM 在不同领域关系上的知识可靠性，确定 LLM 在何种条件下可用于知识库（如 Wikidata）的自动补全与纠错。

方法

提出 LLMKE 流水线，分两步：(1) 知识探测——设计三类提示设置：question prompting（自然语言问句）、triple completion prompting（不完整三元组）、retrieval-augmented context（将 Wikipedia 词条首段与 Infobox JSON、以及 IMDb 等关系特定来源作为上下文，采用两步提示：先让模型凭自身知识作答，再结合上下文对比后自行决定是否修改答案）；答案空间有限的关系在提示中注入全部候选；所有设置均用 3 个训练集样本做 few-shot，并要求以 Python list 格式返回。(2) Wikidata 实体映射——用 MediaWiki Action API 的 wbsearchentities 获取候选实体，再按关系特点选择三种消歧方法：case-based（硬编码映射，如 mercury 映射到化学元素 Q925）、keyword-based（按候选实体描述中的共同关键词过滤）、LM-based（将候选 QID 的 label/description 字典拼入提示交由 LLM 判别）。模型使用 gpt-3.5-turbo 与 GPT-4。

关键结果

整体 macro-averaged F1 达 0.701（0.7007），各关系 F1 从 1.00（PersonHasNobelPrize）到 0.328（PersonHasEmployer）不等；LLMKE 获 ISWC 2023 LM-KBC 挑战赛 Track 2 第一名

GPT-4 整体优于 gpt-3.5-turbo；三种设置中检索增强上下文设置表现最佳

检索增强相对 question prompting：gpt-3.5-turbo F1 提升 0.055，GPT-4 仅提升 0.004；GPT-4 在 21 个关系中只有 10 个从上下文设置中获益

改进消歧方法带来平均 F1 提升：gpt-3.5-turbo +0.0256，GPT-4 +0.0289；13 个存在消歧错误的关系中 3 个（CompoundHasParts、PersonPlaysInstrument、RiverBasinsCountry）被完全解决

gpt-3.5-turbo 在 2 个关系上超过 GPT-4，表明不同 LLM 包含不同知识，互补集成可能提升性能

LLM 在定义域/值域受限的关系上表现好（如地理类关系 F1 0.581~0.855），在公开人物雇主、职业等无限答案空间关系上表现差

创新点

以往用 LLM 做事实补全的工作大多止步于字符串层面，本文推进到将抽取的知识链接到 Wikidata 实体（QID），形成可落地的知识图谱构建能力；同时系统比较了三种提示设置与三种消歧方法，并通过离线评测揭示 LLM、Wikipedia 与 Wikidata 三者之间的知识鸿沟（如 Ferrari 母公司信息 Wikidata 过时而 LLM 结合 Wikipedia 预测正确），提出可用 LLM 预测与真值的偏差作为 Wikidata 质量问题的检测信号，以及用 LLM 丰富 Wikidata 实体 label/alias 的方向。
