Why Do LLM-based Web Agents Fail? A Hierarchical Planning Perspective

为什么基于 LLM 的 Web Agent 会失败：一个分层规划的视角

简介

该论文针对 LLM Web Agent 在真实长程网页任务上失败原因难以定位的问题，指出端到端成功率指标掩盖了失败来源。作者提出分层规划评测框架，把 Agent 能力拆为高层规划、低层执行与重规划三层，在 Mind2Web-Live 的 104 个真实网站任务上，用专家标注对齐的高层计划对 gpt-5-nano、claude-haiku-4.5、gemini-flash-2.5 做过程化评测，并对比自然语言与 PDDL 两种计划表示。关键结论有三：PDDL 结构化表示让计划更简洁且与人类计划对齐更高（matched rate 84.6% vs 70.6%）；即使给定人类计划，低层执行仍是主要瓶颈（成功率仅 36.4%）；一轮基于探索反馈的重规划能显著提升子目标完成率与任务成功率。对团队而言，这套分层诊断指标与 LLM-as-Judge 校验流程可直接用于 Agent 产出的过程化评测与失败归因。

问题

现有 LLM Web Agent 评测主要依赖端到端成功率，无法区分失败究竟来自任务理解偏差、高层策略缺陷、计划到 UI 动作的落地失败，还是环境偏离预期时的恢复能力不足。论文要建立一套能对 Agent 失败做细粒度归因的过程化（process-based）评测方法。

方法

提出分层规划（hierarchical planning）评测框架，将 LLM Web Agent 拆解为三层能力：高层规划（将任务分解为子目标，对比自然语言 NL 与结构化 PDDL 两种表示）、低层执行（将子目标落地为具体 UI 动作，对比 Expanded / Action Object / Action ID 三种动作空间）、重规划（子目标失败后做局部调整或全局重规划，限一轮）。子目标是否完成由 LLM-as-Judge 做 postcondition 检查判定。在 Mind2Web-Live 测试集（104 个真实网站任务）上，利用专家 key-node 标注生成并人工校正高层参考计划，设计 perfect match / missing / decomposed / unmatched 等对齐指标，以及子目标完成率、计划完成率、动作有效性、幻觉链接率、动作重复率、冗余率等执行与失败模式指标，对 gpt-5-nano、claude-haiku-4.5、gemini-flash-2.5 进行系统评测。

关键结果

即使给定人工编写的高层计划，gpt-5-nano 执行器的计划完成率仅 38.5%、最终任务成功率仅 36.4%，低层执行是主要瓶颈

PDDL 计划比 NL 计划更对齐人类计划：perfect match 67.7% vs 60.6%，matched rate 84.6% vs 70.6%，unmatched 15.4% vs 29.4%，missing 2.2% vs 4.2%，且计划更短、低层动作序列更紧凑

失败模式量化：10.4% 的失败源于同一动作重复执行超过 3 次；34% 的动作未引起 DOM 变化；超过 16% 的动作发生在目标网站域之外；32% 的 goto 动作指向不存在的链接

一轮重规划显著提升子目标完成率与整体任务成功率，但计划与人类计划的对齐度下降（NL perfect match 60.6%→56.1%、matched 79.6%→65.0%；PDDL missing 2.2%→14.5%），PDDL 比 NL 更稳定

模型对比（人类计划条件下成功率）：gpt-5-nano 36.4% > claude-haiku-4.5 29.2% > gemini-flash-2.5 17.3%；gemini-flash-2.5 冗余动作率最高（41.2%，对比 claude-haiku-4.5 的 25.6% 与 gpt-5-nano 的 34.2%）

LLM-as-Judge 可靠性：postcondition 检查与人工标注一致率 82%（41/50），最终评测一致率 86%（43/50）

68%（NL）与 73%（PDDL）的分解步骤能把原本不可执行的子目标变为可执行，但过度分解紧凑子目标会损害可执行性

创新点

区别于以往只报告端到端成功率的评测方式，首次将 web agent 评测解耦为高层规划、低层执行与重规划三个维度做过程化失败归因；据作者所述，这是首个把 PDDL 等形式化规划表示引入 web agent 的工作；并基于 Mind2Web-Live 的专家 key-node 标注构建了人工对齐的高层参考计划数据与配套评测框架（已开源）。
