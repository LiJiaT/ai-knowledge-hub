Making Language Models Better Tool Learners with Execution Feedback

用执行反馈让语言模型成为更好的工具学习者（TRICE）

简介

LLM 在工具调用上普遍存在“不会判断何时该用工具”的问题：对模型自身能解决的简单任务强行引入工具，反而会因工具类型选错、输入生成错误或未有效利用返回结果而传播错误。论文提出 TRICE，一个两阶段端到端训练框架：先用 ChatGPT 为模型答错的问题自动生成工具 API 伪标签构造数据，第一阶段 Behavior Cloning 用 instruct-tuning 让模型模仿工具调用行为，第二阶段 RLEF 以工具执行结果构造五级奖励（答案正确性 × 工具使用是否与 gold 一致），用 ranking loss 强化模型选择性用工具。实验显示 6-7B 模型经 TRICE 训练后可比肩甚至超越 GPT-3.5（TRICE-MIX 下 Alpaca/Vicuna 分别高出 2.9%/4.1%），且第二阶段能显著缓解过度依赖工具与工具学习不足两类失效。对团队而言，其“何时用工具”的问题框架与执行反馈评测思路对 Agent 工具调用策略设计很有启发，但方法本身依赖模型微调。

问题

现有 tool learning 方法（包括监督微调与 prompt 工程路线）往往让 LLM 不加区分地使用工具；对模型本身能轻松解决的简单任务引入工具反而传播错误，具体表现为工具类型选择不当、工具输入生成错误、未有效利用工具返回结果。论文研究的核心问题是：能否教会 LLM 何时以及如何使用工具（when and how to use tools），实现选择性工具调用，同时弥补工具学习不足并抑制对工具的过度依赖。

方法

TRICE 两阶段端到端框架。数据准备：用未微调 LLM 直接作答，答对的样本标记为无需工具（t=None），答错的样本用 ChatGPT 在 few-shot 提示下生成伪标签工具 API，得到带“工具需求”信息的训练集 D_tool。Stage I Behavior Cloning：以 instruct-tuning 方式监督微调，让模型掌握工具 API 调用格式并形成初步的选择性用工具能力。Stage II RLEF：对每个问题收集 k 个候选回答（来自 ChatGPT、InstructGPT、Vicuna-7B、Alpaca-7B 及 D_tool 规整的 gold 回答），按“答案正确性 + 工具使用与 gold 是否一致”做五级打分（TrueYes > TrueNo > FalseYes > FalseNo），用 length-normalized 序列概率让 LLM 拟合该排序，以 ranking loss（权重 α）加 SFT loss 联合训练防止偏离原参数。全程用 LoRA 高效微调，覆盖 Math Reasoning（calculator）、Question Answering（WikiSearch）、LAMA（QA 模型 Atlas）、Multilingual QA（NLLB 翻译器）四类任务。

关键结果

TRICE-SPLIT：Alpaca 与 Vicuna 与 GPT-3.5 基本持平，平均仅低 1.3% 与 0.4%；相比 few-shot 基线，ChatGLM 提升 14.0%、Alpaca 提升 15.3%、Vicuna 提升 11.9%

TRICE-MIX：跨任务混合训练比 TRICE-SPLIT 平均再提升 4.0% 以上；Alpaca 与 Vicuna 分别超越 GPT-3.5 2.9% 与 4.1%

泛化性：Vicuna (TRICE-MIX) 在未见数据集（MultiArith、AddSub、SQuAD）上优于 TRICE-SPLIT；在 HotpotQA 上配合未见工具（retriever）比 few-shot 方式高 6.7%

阶段分析：仅训 Stage II（TRICE-II）效果不佳，Stage I 是稳定工具学习的基础；Stage II 后多数任务工具使用率下降（缓解过度依赖），LAMA 的工具使用率上升（弥补学习不足）

训练效率：全部训练可在单张 80G A800 GPU 上 10 小时内完成；但 RL 训练过久会导致性能显著下降，最优性能通常出现在前 10-40 步

创新点

与以往 tool-augmented 方法让模型“盲目”用工具不同，TRICE 教模型“选择性”用工具；与以往依赖人类偏好或固定模型反馈的反馈学习框架不同，论文引入 RLEF，直接以工具执行结果作为强化信号，并通过 ChatGPT 自动生成工具 API 伪标签避免人工标注，用“答案正确性 × 工具使用一致性”的五级评分同时优化“是否用工具”与“如何用工具”两个决策。
