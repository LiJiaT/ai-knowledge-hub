简介

RAG 系统的评估通常依赖人工标注的参考答案或模型内部概率，这在缺乏标注数据、使用闭源 API 模型时难以实施，而困惑度等传统指标又与下游表现不相关。论文提出 Ragas，一个 reference-free 的 RAG 自动评估框架，围绕三个维度设计指标：Faithfulness（将答案分解为细粒度陈述并逐条验证能否从检索上下文推断，按支持比例计分）、Answer Relevance（由答案反向生成候选问题，计算与原问题的 embedding 余弦相似度）和 Context Relevance（让 LLM 抽取回答问题所需的关键句子，按占比计分以惩罚冗余上下文）。作者构建 WikiEval 数据集（50 个 Wikipedia 页面、双人标注）验证指标与人类判断的一致性，结果显示 Ragas 显著优于直接打分（GPT Score）与直接排序（GPT Ranking）两个基线，其中 Faithfulness 最准确、Context Relevance 最难评估。框架已开源并与 llama-index、Langchain 集成，可直接嵌入 RAG 开发工作流。

问题

RAG 系统评估困难：性能同时受检索模型、语料、LLM 和 prompt 影响，需要多维度评估；实践中常用困惑度评估，但既不能预测下游表现，又依赖闭源 API 模型无法提供的 token 概率；QA 式评估依赖参考答案，而实际构建 RAG 系统时通常没有人工标注数据。论文要解决的问题是：在无参考答案（reference-free）条件下，如何自动化、多维度地评估 RAG 系统的检索与生成质量。

方法

提出三个完全自包含、无需参考答案的指标，全部通过 prompting LLM（gpt-3.5-turbo-16k）实现：(1) Faithfulness：先用 LLM 将答案分解为陈述集合 S，再逐条用验证 prompt（要求先给出简要解释再输出 Yes/No 结论）判断能否从检索上下文推断，得分 F=|V|/|S|；(2) Answer Relevance：让 LLM 基于答案生成 n 个候选问题，用 text-embedding-ada-002 计算各候选问题与原问题的 cosine 相似度取平均，惩罚不完整或冗余的答案；(3) Context Relevance：让 LLM 从上下文中抽取回答问题所需的关键句子（不得改写原句），按句子占比计分，惩罚冗余信息。同时构建 WikiEval 评测集（50 个 2022 年后事件的 Wikipedia 页面，ChatGPT 生成问答，双人标注三维度判断），以成对比较方式与 GPT Score、GPT Ranking 两个基线对比。框架与 llama-index、Langchain 集成并开源。

关键结果

人工标注者间一致性：faithfulness 与 context relevance 约 95%，answer relevance 约 90%

在 WikiEval 成对比较中，Ragas 指标与人类判断的一致性（accuracy）显著高于 GPT Score 与 GPT Ranking 两个基线（Table 1 报告了 accuracy，但具体数值未在提供的正文中展示）

Faithfulness 预测总体高度准确；answer relevance 一致性较低，主要因两个候选答案间差异细微；context relevance 是最难评估的维度

WikiEval 数据集规模：50 个 Wikipedia 页面（2022 年后事件），每页由 ChatGPT 生成一个问题及基于引言部分的回答

创新点

区别于依赖参考答案的指标（BERTScore、MoverScore、BARTScore）和依赖 token 概率或模型内部状态的方法（GPTScore、Azaria & Mitchell 的隐藏层分类器，均不适用于 API 模型），Ragas 完全 reference-free 且只需 API 访问；针对 RAG 特有的三个质量维度分别设计指标，其中 faithfulness 采用'陈述分解+逐条验证'的分解式评估而非整体打分；此外作者表示未找到满足需求的公开数据集，因此构建了带三维度人工判断的 WikiEval 数据集。

Abstract

我们提出 Ragas（R etrieval A ugmented G eneration As sessment），一个用于对检索增强生成（RAG）流水线进行无参考评估的框架。RAG 系统由检索模块和基于大语言模型（LLM）的生成模块组成，为 LLM 提供来自参考文本数据库的知识，使其能够充当用户与文本数据库之间的自然语言层，从而降低幻觉风险。然而，评估 RAG 架构颇具挑战性，因为需要考虑多个维度：检索系统识别相关且聚焦的上下文段落的能力、LLM 以忠实方式利用这些段落的能力，以及生成本身的质量。借助 Ragas，我们提出了一套指标，可用于评估这些不同维度，而无需依赖作为基准真值的人工标注。我们认为，这样一个框架能够为加快 RAG 架构的评估周期做出关键贡献，鉴于 LLM 的快速普及，这一点尤为重要。

1 Introduction

语言模型（Language Models, LMs）捕获了大量关于世界的知识，这使它们能够在不访问任何外部来源的情况下回答问题。将语言模型视为知识库的这一思想在 BERT（Devlin et al., 2019）问世后不久便已出现，并随着规模越来越大的语言模型的推出而得到更加牢固的确立（Roberts et al., 2020）。尽管最新的大语言模型（Large Language Models, LLMs）已经掌握了足以在各种问答基准测试（benchmark）上与人类表现相媲美的知识（Bubeck et al., 2023），但将 LLM 用作知识库的想法仍然存在两个根本性的局限。首先，LLM 无法回答关于其训练之后发生的事件的问题。其次，即使是最大的模型也难以记住训练语料库中仅被偶尔提及的知识（Kandpal et al., 2022; Mallen et al., 2023）。解决这些问题的标准方案是采用检索增强生成（Retrieval Augmented Generation, RAG）（Lee et al., 2019; Lewis et al., 2020; Guu et al., 2020）。回答问题的过程本质上包括从语料库中检索相关段落，并将这些段落连同原始问题一起输入给语言模型。虽然早期的方法依赖于专门的语言模型来进行检索增强的语言建模（Khandelwal et al., 2020; Borgeaud et al., 2022），但近期的工作表明，仅仅将检索到的文档添加到标准语言模型的输入中也能取得良好效果（Khattab et al., 2022; Ram et al., 2023; Shi et al., 2023），从而使检索增强策略能够与仅可通过 API 获取的 LLM 结合使用。

尽管检索增强策略的实用性显而易见，但其实施需要大量的调优，因为整体性能会受到检索模型、所考虑的语料库、语言模型或提示（prompt）表述等多种因素的影响。因此，对检索增强系统进行自动化评估至关重要。在实践中，RAG 系统通常依据语言建模任务本身来评估，即通过在某个参考语料库上测量困惑度（perplexity）来进行。然而，这类评估并不总能预测下游性能（Wang et al., 2023c）。此外，这种评估策略依赖于语言模型的概率，而某些封闭模型（例如 ChatGPT 和 GPT-4）无法获取这些概率。问答是另一种常见的评估任务，但通常只考虑具有简短抽取式答案的数据集，这可能无法代表系统的实际使用方式。

为解决这些问题，本文提出 Ragas 1，一个用于自动评估检索增强生成（RAG）系统的框架。我们关注参考答案可能不可用的场景，此时除了检索段落的有用性之外，我们还希望估计正确性的各种代理指标。Ragas 框架与 llama-index 和 Langchain——构建 RAG 解决方案时使用最广泛的两个框架——实现了集成，从而使开发者能够轻松地将 Ragas 集成到其标准工作流程中。

2 Related Work

使用大语言模型（LLM）估计忠实度

检测 LLM 生成回答中的幻觉这一问题已得到广泛研究 (Ji et al., 2023)。多位作者提出了利用少样本提示策略预测事实性的想法 (Zhang et al., 2023)。然而，近期分析表明，现有模型在使用标准提示策略时难以检测幻觉 (Li et al., 2023; Azaria and Mitchell, 2023)。其他方法则依赖于将生成的回答与外部知识库中的事实相关联 (Min et al., 2023)，但这并非总是可行。

还有一种策略是检查分配给各个 token 的概率，此时我们预期模型对幻觉回答的置信度会低于对事实性回答的置信度。例如，BARTScore (Yuan et al., 2021) 通过考察在给定输入的条件下生成文本的条件概率来估计事实性。Kadavath et al. (2022) 使用了这一思路的一种变体。基于 LLM 在回答多项选择题时能提供校准良好的概率这一观察，他们实质上将验证模型生成回答的问题转化为一个询问该回答是真是假的多项选择题。Azaria and Mitchell (2023) 则不考察输出概率，而是提出在 LLM 某一隐藏层的权重上训练一个监督分类器，以预测给定陈述是否为真。尽管该方法表现良好，但由于需要访问模型的隐藏状态，它并不适合通过 API 访问 LLM 的系统。

对于不提供 token 概率访问的模型，例如 ChatGPT 和 GPT-4，则需要不同的方法。SelfCheckGPT (Manakul et al., 2023) 通过改为采样多个回答来解决这一问题。其核心思想是事实性回答更加稳定：当回答符合事实时，可以预期不同的采样结果在语义上趋于相似，而对于幻觉回答则不太可能出现这种情况。

Automated evaluation of text generation systems

除了事实性之外，LLM 还被用于自动评估所生成文本片段的其他方面。例如，GPTScore (Fu et al., 2023) 使用一个指定所考察方面（例如流畅性）的提示，然后依据给定的自回归语言模型（LM），基于所生成 token 的平均概率对文本段落进行评分。这种使用提示的想法此前也已被 Yuan et al. (2021) 考虑过，不过他们使用的是较小的微调 LM（即 BART），并未观察到使用提示带来的明显收益。另一种方法则直接要求 ChatGPT 通过给出 0 到 100 之间的分数，或以 5 星制给出评级，来评估给定答案的某个特定方面 (Wang et al., 2023a)。值得注意的是，通过这种方式可以获得很强的结果，但其局限在于对提示的设计较为敏感。一些作者不再对单个答案进行评分，而是专注于利用 LLM 从多个候选答案中选出最佳答案 (Wang et al., 2023b)，这通常是为了比较不同 LLM 的性能。然而，使用这种方法需要谨慎，因为答案呈现的顺序可能会影响结果 (Wang et al., 2023b)。

就标准答案（ground truth answers）——或更一般地说，生成结果——在文献中的典型使用方式而言，大多数方法都依赖于一个或多个参考答案的可用性。例如，BERTScore (Zhang et al., 2020) 和 MoverScore (Zhao et al., 2019) 使用由预训练 BERT 模型产生的上下文化嵌入（contextualised embeddings）来比较生成答案与参考答案之间的相似度。BARTScore (Yuan et al., 2021) 同样使用参考答案来计算诸如精确率（precision，估计为在给定参考答案的条件下生成所生成答案的概率）和召回率（recall，估计为在给定所生成答案的条件下生成参考答案的概率）等方面的指标。

4 The WikiEval Dataset

为了评估所提出的框架，我们理想情况下需要带有的人工判断标注的“问题-上下文-回答”三元组示例。这样我们便可以验证我们的指标在多大程度上与人类对忠实性、回答相关性和上下文相关性的评估相一致。由于我们尚不知道有任何公开可用的数据集可用于此目的，我们创建了一个新数据集，我们将其称为 WikiEval 4。为了构建该数据集，我们首先选择了 50 个维基百科页面，这些页面涵盖自 2022 年初以来发生的事件 5。在选择这些页面时，我们优先考虑了近期有编辑的页面。对于这 50 个页面中的每一个，我们随后要求 ChatGPT 基于页面的引言部分提出一个可以回答的问题，所使用的提示如下：

表 1 中的结果表明，与两种基线方法的预测相比，我们所提出的指标与人工判断的一致程度要高得多。对于忠实度，Ragas 的预测总体上非常准确。对于回答相关性，一致性较低，但这在很大程度上是由于两个候选回答之间的差异往往非常细微所致。我们发现上下文相关性是最难评估的质量维度。特别是，我们观察到 ChatGPT 在从上下文中挑选出关键句子的任务上常常表现吃力，尤其是在上下文较长的情况下。

6 Conclusions

我们强调了针对检索增强生成（RAG）系统进行自动化无参考评估的必要性。特别地，我们论证了对一个评估框架的需求，该框架能够评估忠实度（即回答是否以检索到的上下文为依据）、回答相关性（即回答是否切中问题）以及上下文相关性（即检索到的上下文是否足够聚焦）。为支持此类框架的开发，我们引入了 WikiEval，这是一个包含针对这三个不同方面的人工判断的数据集。最后，我们还介绍了 Ragas，即我们对所考虑的三个质量维度的实现。该框架易于使用，即使缺乏任何真值（ground truth），也能为 RAG 系统的开发者提供有价值的洞见。我们在 WikiEval 上的评估表明，Ragas 的预测与人工预测高度一致，尤其是在忠实度和回答相关性方面。
