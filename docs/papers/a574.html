In-Context Learning User Simulators for Task-Oriented Dialog Systems

简介

任务型对话系统（TODS）在部署前需要用户模拟器做可控测试，但传统方案要么手工定义规则（agenda-based），要么需要大量标注数据训练模型，成本高且难跨域迁移。论文提出用 LLM 的 in-context learning 能力构建用户模拟器：prompt 由任务描述（含 persona/role 修饰）、少量示例对话、目标用户目标和累积对话历史组成，逐轮生成用户话语，无需微调，并比较了随机与基于 Jaccard 相似度的示例选择策略。在 MultiWOZ 2.1 + ConvLab-2 上的结果显示：prompt-based 模拟器的目标达成率不及规则基线（其中 GPT-3.5 最好），但生成话语的词汇多样性达到甚至超过人类训练数据，更适合测试系统 NLU 的鲁棒性。论文还给出系统的 prompt 消融（shot 数量、任务描述、结构化 vs 描述式需求）与错误分析，揭示了 NLU 误分类、模拟器中途放弃目标、幻觉与角色混淆等问题，是'用提示工程把 LLM 变成自动化测试工具'的一份实证参考。

问题

为任务型对话系统（TODS）构建用户模拟器，用于部署前在受控环境中测试与评估系统。传统用户模拟器要么依赖手工规则定义（如 agenda-based 方法，不可迁移到新域），要么需要大量标注数据来训练/微调模型，耗时且昂贵。论文探索能否仅凭一个用户目标和少量示例对话，利用 LLM 的 few-shot/in-context learning 能力直接生成多样、符合目标的用户话语，免去规则定义与微调。

方法

提出 prompt-based 用户模拟器：每轮 prompt 由任务描述（persona/role 修饰语）、K 个带需求描述的示例对话（shots）、目标用户目标 g_t 和累积对话历史拼接而成，以 'CUSTOMER:' 结尾强制 LLM 生成用户侧话语，输出经后处理只保留用户话语后回传给被测对话系统。示例选择比较随机采样与基于用户目标 domain/slot 集合 Jaccard 相似度的 Top-K 选择两种策略。架构包含 prompt builder、LLM、后处理，以及可选评测组件（用户/系统两侧 BERT NLU 将话语转成 dialog acts 以追踪目标达成）。基座模型为 GPT-3.5、FLAN-T5、LLaMa，在 ConvLab-2 + MultiWOZ 2.1 上与 agenda-based 基线（ABUS-T/ABUS-D）对比，并做 prompt 消融（0-6 个 shots、任务描述变体、结构化 bullet points vs 描述式需求）与温度对词汇多样性影响的分析。

关键结果

目标达成指标上 agenda-based 规则基线（ABUS-T/ABUS-D）整体优于 prompt-based 模型；prompt-based 模型中 GPT-3.5 最好，其后为 FLAN-T5 和 LLaMa（具体数值见表 2，正文未列出）

prompt-based 模型在不到 45% 的对话中会在完成目标前提前终止；GPT-3.5 因更执着的行为表现出更高的完成率

LLM 生成话语的词汇多样性达到甚至超过人类训练数据：GPT-3.5 在 SE、CE、HDD、MTLD 上超过 ABUS-T，在 SE 和 HDD 上超过抽样训练集；prompt-based 模型的 unique unigram/bigram/trigram 数显著高于 ABUS-T/ABUS-D

Jaccard 相似度示例选择对较小模型（LLaMa、FLAN-T5）更有利，但在词汇多样性上不优于随机采样；温度从 0.7 提到 0.9 持续提升 FLAN-T5 的词汇多样性

Prompt 消融（FLAN-T5）：任务描述中加入 persona/role 修饰带来显著提升（0-shot 亦然）；增加 shot 数先提升后进入平台期（疑似超出 LLM 输入空间）；结构化 bullet points 需求表示未显著改善任务达成；在任务描述中加入域名无提升

训练集用户话语平均比 GPT-3.5 与 ABUS-T 的短约 4 个 token

实验设置：每实验 200 条 seeded dialogs；MultiWOZ 2.1 含 10,433 段对话、7 个域

创新点

据作者所述，此前对 LLM few-shot 能力用于用户模拟的探索非常有限。与 agenda-based（需手工规则、不可跨域）和数据驱动（需标注数据与训练资源）路线不同，该方法无需微调、只需用户目标加少量示例对话即可跨域使用，并系统给出了 prompt 设计消融（shot 数、任务描述、结构化格式）以及模拟器与对话系统交互的错误分析，同时揭示了 LLM 模拟器在词汇多样性上的独特测试价值。
