In-context Examples Selection for Machine Translation

面向机器翻译的 In-context 示例选择

简介

论文系统研究使用 LLM 做机器翻译时，in-context 示例的选择、数量、领域与排序如何影响输出质量。作者将示例分为 task-level（传递任务格式与知识）与 example-specific（提供与测试源句相关的信息）两类：前者在开发集上按 BLEU 自动优选单条提示，后者用 BM25 检索相似示例后，通过 n-gram 召回重排序策略在约 3096 token 的有限上下文窗口内最大化覆盖测试源句词项。关键结论：一条噪声无关示例可使 BLEU 跌至 1，而单条优选 task-level 提示即可媲美 16 条随机 few-shot 示例；重排序后的检索示例在 4 个跨领域数据集中的 2 个上超过 kNN-MT 基线，且无需构建稠密 token 级数据存储，更省内存与算力；两类提示拼接使用可获得互补增益。该工作对团队做示例选择、检索增强与上下文组织有直接参考价值。

问题

in-context learning 做机器翻译时，示例通常从与测试集同分布的开发集中随机采样，但示例的选择、数量、领域与排序对翻译质量的影响尚不清楚，尤其在 out-of-domain 场景下'什么样的 in-context 示例才是好示例'缺乏系统研究。

方法

将 in-context 示例分为两类并分别构造：1) task-level 提示——从训练集候选池中枚举示例，将其分别拼接到开发集各源句上生成译文，按 BLEU 排序选出单条最优提示；2) example-specific 提示——用 BM25 从平行语料库检索 top-100 候选，再用基于 n-gram 召回的重排序算法（对已覆盖的源句 n-gram 按因子 λ=0.1 降权、阈值 1.0，迭代选择）在约 3096 token（16-20 条示例）的上下文窗口内最大化测试源句 n-gram 覆盖。最后将 task-level 与 example-specific 提示简单拼接使用。实验基于 XGLM 7.5B，用 sacreBLEU（附录含 Comet）评测。

关键结果

1-shot 噪声无关示例导致 BLEU 低至 1；即使与最优提示拼接（best-then-worst / worst-then-best），最好结果 31.43 仍低于仅用最优 task-level 提示的 32.14

100 条随机 1-shot 提示的 BLEU 分布差异高达 20 BLEU

单条 task-level 提示在 4 个翻译方向中的 2 个（De-En、Ru-En）优于 16 条随机 few-shot 示例

16 条 BM25 示例相对 task-level 提示平均提升 1.41 BLEU；重排序策略在 q_max=1 和 16 下均一致优于原始 BM25 排序

跨领域场景：领域内 task-level 示例在 1-shot/16-shot 下平均 +1.4/+2.7 BLEU；R-BM25 单条示例在 Law 领域相对 task-level 提示最高提升 23 BLEU

task-level + R-BM25 拼接在 4 个跨领域数据集中的 2 个（Medical、IT）超过 kNN-MT，且无需强基座 MT 模型或推理期 token 级检索；Comet 指标下在 3/4 领域超过 kNN-MT

task-level 提示候选池从 100 扩到 1000 仅提升 0.5 BLEU；数据存储 100k + q=16 的 BLEU 等效于 200k + q=1

task-level 提示对顺序更不敏感（各设置下标准差更低）；最优示例排序为最相似示例放左侧

推理开销：单张 V100（32G）上 2000 条测试、16 条 in-context 示例需 3-4 小时

创新点

不同于以往用稠密检索器或 PLM 嵌入空间选示例（且多针对分类/QA 任务），论文针对 MT 提出免训练的 BM25 + n-gram 召回重排序示例选择方法，显式在有限上下文窗口内最大化源句词项覆盖，解决 BM25 独立打分导致 top 候选信息重复的问题；并首次系统刻画了 MT 场景下示例选择、排序与领域的影响，相比 kNN-MT 无需构建与查询稠密 token 级数据存储，更省内存与算力。
