Grammar Prompting for Domain-Specific Language Generation with Large Language Models

Grammar Prompting：面向领域特定语言生成的大语言模型文法提示方法

简介

论文解决 LLM 仅凭少量 in-context 示例难以生成领域特定语言（DSL）字符串的问题：DSL 的领域抽象与语法在预训练中罕见，几个示例无法传达其组合式输出空间的约束。方法上提出 grammar prompting：为每个演示示例附加一个'最小充分'的专用 BNF 文法（可由完整 DSL 文法解析示例输出自动得到），推理时 LLM 先预测专用文法、再按文法规则生成程序，并配合基于 Earley 解析器的投机式约束解码保证语法有效性。实验覆盖语义解析（SMCalFlow、GeoQuery、Overnight）、PDDL 规划与 SMILES 分子生成，显示该方法在多数设置下显著优于标准 prompting，在组合泛化与未见函数零样本场景提升尤为明显。对团队而言，这是把形式化约束注入提示与解码的结构化提示技术，可用于工具调用生成与结构化输出可靠性保障，但需注意对 SQL、正则等常见语言无收益，且约束解码约增加 3 倍 API 调用。

问题

LLM 通过少量 in-context 示例可完成许多自然语言任务，但在生成高度结构化语言的字符串（如语义解析到复杂 DSL）时难以泛化：DSL 包含领域特定抽象与语义，且在预训练语料中很少甚至从未出现，其组合式输出空间的语法结构无法仅凭几个示例充分传达，因此少样本 DSL 生成对 LLM 仍然困难。

方法

提出 grammar prompting：假设拥有专家定义的完整 BNF 文法 G，为每个演示示例 (x, y) 附加'最小充分'专用文法 G[y]（G 的规则子集，可通过用 G 解析 y 自动抽取，无需人工标注），推理时 LLM 先预测专用 BNF 文法、再在该文法条件下生成程序。该方法可视为 chain-of-thought 的变体，但中间推理步骤是形式文法而非自然语言。另提出基于 Earley 解析器的投机式约束解码（Algorithm 1）：先让 LLM 投机解码完整程序，解析失败时取最长合法前缀并从合法终结符集合中按 LLM 概率修正，从而在 API-only LLM 上保证语法有效性并控制调用成本。

关键结果

少样本语义解析（SMCalFlow/GeoQuery/Overnight，16-32 示例，Codex）：grammar prompting 即使不用约束解码也显著优于标准 prompting，并超过提供更多结构信息的 derivation tree prompting 基线

约束解码所需 LLM API 调用次数约为无约束解码的 3 倍；预测文法与 oracle 文法之间仍存在较大性能差距

组合泛化（GeoQuery 的 Template/TMCD/Length splits）：grammar prompting 在所有 split 上优于标准 prompting；NewFunc 设置下对 8 个未见函数的零样本使用显著优于标准 prompting

为 BNF 规则附加自然语言注释：SMCalFlow +1.0%、Overnight-Blocks +0.5%，GeoQuery 无提升

分子生成（GPT-3.5，SMILES）：Acrylates 与 Chain Extenders 在有效性、多样性、可合成性（Retro score）、类别归属四项指标上均显著优于标准 prompting，Isocyanates 结果好坏参半；两种 prompting 方法 Retro score 均超过图文法基线

PDDL 规划（GPT-3.5，Pyperplan）：Blocks 域显著提升搜索效率并保持 100% 成功率；Depot 域使用 macro 动作时成功率比最佳对比基线高 20%；Satellite 域 100% 成功率且扩展节点数比 No LLM 基线减少 57%

负结果：对预训练中常见的 DSL（正则表达式、SQL）grammar prompting 无任何改进

创新点

与 chain-of-thought 等用自然语言中间步骤的方法不同，首次将形式文法（BNF）作为 prompt 中的中间推理变量；与需人工 verbalize 推理步骤的 CoT 不同，专用文法可通过解析输出自动获得；相比在同步文法中嵌入可学习神经组件的已有工作，本文是'纯 LLM'的实例化，完全依赖 in-context learning 完成学习部分；同时将文法约束与投机解码结合，以适配无法逐步干预解码的 API-only LLM。
