Learning to Rewrite Prompts for Personalized Text Generation

学习重写 Prompt 以实现个性化文本生成（Learning to Rewrite Prompts for Personalized Text Generation）

简介

论文研究在 LLM 参数冻结、只能通过 API 以文本 prompt 交互、无法微调的现实场景下，如何自动优化个性化文本生成的提示词。方法在多阶段个性化框架（检索→排序→摘要→综合）产出的初始 prompt 基础上，训练一个 T5-11B 的 prompt rewriter，只重写其中依赖用户上下文的摘要与综合组件：先通过对 summary/synthesis 元素随机化生成 65 个变体、用冻结 LLM 逐一评估 Bleu 择优构造标签做监督学习以压缩搜索空间，再用 PPO 以生成质量为 reward 端到端强化学习。在邮件、Amazon 评论、Reddit 三个数据集上，SL+RL 训练的 RewriterSlRl 显著优于原始 prompt 及单独 SL 或 RL 的版本；仅 SL 效果接近原始 prompt，仅 RL 会生成无意义 token。分析发现冻结 LLM 对上下文噪声比微调模型更敏感，rewriter 学到删除离题摘要、重复关键关键词、按出现顺序重排等可解释模式，这些模式还能指导人工改写 prompt 并带来方向一致的提升。

问题

在 LLM 是参数冻结的黑盒、只能通过 API 访问、无法微调的典型场景下，如何自动优化用于个性化文本生成的 prompt——尤其是其中依赖用户个人上下文的摘要与综合组件——使冻结 LLM 产出更贴近目标用户的文本。已有 RL 提示优化工作只针对输入无关的 instruction 部分，搜索空间小；而上下文相关组件的搜索空间巨大，直接用 RL 难以搜索。

方法

基于 FtPersLlm 多阶段框架（用即时上下文作 query 检索并排序用户历史文档，再经摘要模型与关键词综合模型组装 prompt），新增基于 LLM 的写作风格综合作为第三类综合组件。训练一个比生成器更小的序列到序列模型（T5-11B）作为 prompt rewriter，仅重写 summary 与 synthesis 两个组件：SL 阶段对元素做随机化（打乱顺序并随机删除尾部元素）生成 65 个 prompt 变体，用冻结 LLM（PaLM 2，temperature=0）逐一评估 Bleu，选最佳变体为标签训练 rewriter（标签中剔除不变组件以提升训练效率）；RL 阶段用 PPO，以生成文档与 ground-truth 的 Bleu 为 reward 继续训练，动作空间覆盖全词表从而可引入新词。训练与测试用户不重叠（85/5/10 划分）。

关键结果

作为 SL 标签的最佳 prompt 变体在全部三个实验数据集上将 Bleu 比原始 prompt 提升约 10 个点（原文：improve Bleu by 10 over original prompts on all datasets）

RewriterSlRl 在邮件、Amazon 评论、Reddit 三个数据集上均以 0.01 显著性水平（paired t-test）大幅优于 Original；RewriterSl 仅与 Original 相当或略好；RewriterRl（无 SL 预训练）因搜索空间过大表现差，生成的 prompt 含无意义 token

将 SL 标签生成的 prompt 变体数从 65 降到 4，RewriterSlRl 性能差异不具统计显著性，可大幅降低训练成本

推理成本由对 LLM 生成器的 API 调用主导（rewriter 为更小的 T5-11B），且重写后的 prompt 更短，可能进一步降低用户成本

减小 rewriter 模型尺寸会导致性能下降，但各尺寸 T5 仍带来可观的 prompt 重写收益

用学到的模式人工改写原始 prompt（如去掉 summary、保留 keywords+writing style、Email 场景采用统一的 thorough 风格描述）后，改进方向与 RewriterSlRl 一致且明显提升，但所有人工变体仍显著低于 RewriterSlRl

创新点

与已有 RL 提示优化工作（优化输入无关、跨样本共享的 instruction 部分）不同，本文直接优化个性化生成中依赖输入/上下文的组件（summary、synthesis），通过无限制编辑操作应对大得多的搜索空间，并提出 SL+RL 链式训练范式（SL 压缩搜索空间、RL 端到端优化）。与先前'RL 学到的 prompt 不合语法、人类不可读'的结论相反，本文学到的 prompt 人类可读且能提炼出可指导人工改写的可解释规则。场景限定为仅能通过 API 访问的冻结 LLM（离散 hard prompt），区别于需要访问模型参数的 soft prompt 方法（prefix tuning、prompt tuning）。
