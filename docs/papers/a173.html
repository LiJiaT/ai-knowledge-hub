Infinite-LLM: Efficient LLM Service for Long Context with DistAttention and Distributed KVCache

Infinite-LLM：基于 DistAttention 与分布式 KVCache 的高效长上下文 LLM 服务系统

简介

LLM 服务的请求上下文长度高度动态（从 1 到 2000K tokens），静态模型并行与实例内固定资源分配无法同时高效服务长短请求：长请求的 KVCache 耗尽显存、压低 batch size，短请求又因模型被过度切分而计算低效。论文提出 Infinite-LLM 服务系统，将 attention 层从推理实例中解耦：DistAttention 借助 online softmax 式的等价数学变换，把 attention 与 KVCache 沿序列维切成小块分布到多实例计算，解码时只需传输 KB 级 query 而非 GB/TB 级 KVCache；集群 GPU 显存池化后，实例以 debtor/creditor 方式借还显存，由基于性能模型的贪心算法与 gManager/rManager 两层架构统一调度。在 32 张 A100 集群上，相比 vLLM 吞吐提升 1.35-3.4x，支持的上下文长度达 vLLM-multi 的 2x-19x，DistAttention 比 RingAttention 快 7.7x-19.8x。该工作属于推理服务基础设施层优化，与团队应用层能力域无直接对应。

问题

现有 LLM 服务系统采用静态模型并行与固定资源分配，难以适应请求上下文长度的高度动态性（从 1 到 2000K tokens）：为长请求配置高并行度会使短请求遭受过度模型切分与通信开销；长请求的 KVCache 占满实例显存会压缩 batch size、拉低 GPU 计算利用率，而短请求实例的空闲显存又无法被其他实例上的长请求利用，导致实例内模型并行低效、集群级显存与计算利用率无法同时饱和，整体吞吐受限。

方法

三项核心创新：(1) DistAttention——受 online softmax 启发对 attention 做等价数学变换，将 attention 与 KVCache 切分为规则小块（MicroAttention）分布到多实例计算，远端实例只需回传 query 向量与两个浮点值（e_j、m_j），聚合计算 FLOPs 不足总量的 1%，避免每步解码传输 GB/TB 级 KVCache；(2) 集群级显存池化——实例分为借入显存的 debtor 与出借显存的 creditor，基于可实验标定的性能模型用贪心算法决定 KVCache 子块在实例间的迁移 placement，并将 KVCache 迁移与本地推理计算重叠以隐藏通信；(3) gManager（集中式全局管理器）+ rManager（与实例同址的分布式管理器）架构，通过 heartbeat、move_kvcache、try_move_kvcache 协议实现松耦合的全局状态跟踪、调度与容错。

关键结果

在 4 节点 32 张 A100 (80GB) 集群、上下文长度从几条到 2000K tokens 的负载上，Infinite-LLM 相比 state-of-the-art 方法（vLLM）吞吐提升 1.35-3.4x

与 vLLM-multi 相比，短上下文 trace（ShareGPT4）上吞吐提升约 1.35x-1.73x；与 vLLM-single 相比，长上下文 trace（L-Eval 及线上长请求分布）上吞吐提升 1.4x-3.4x

相比受单实例显存限制的 vLLM-multi，Infinite-LLM 支持长 2x-19x 的上下文且短序列吞吐相当；相比 vLLM-single，短长度上吞吐高 1.4x-5.3x

在 4 GPU、LLaMA2-13B 维度、4K-256K 上下文范围内，DistAttention 比 TP（按 head 划分）快 1%-25%，比 RingAttention 快 7.7x-19.8x

KVCache 迁移开销：每 decode step 迁移 32 tokens 时实例吞吐下降 8.6%；迁移 16 tokens 时与关闭迁移的实例吞吐完全相同（通信可与计算完全重叠）

微基准中一对 debtor/creditor 实例迁移 200 个 KVCache block 时，聚合吞吐从约 6500 tokens/second 提升到约 8800 tokens/second

创新点

与 ORCA、vLLM、DeepSpeed-FastGen、DistServe 等以整个请求为调度粒度的系统不同，Infinite-LLM 将 attention 层从推理过程中解耦（attention disaggregation），可按 KVCache 任意子块（子序列）粒度跨实例调度，粒度更细、更灵活；与面向训练的 RingAttention/context parallelism 不同，DistAttention 通过等价数学变换避免每步解码传输大块 KVCache，且与原 attention 数学等价、对模型精度无害；与 Sliding Window Attention、H2O、StreamingLLM 等稀疏 KVCache 方案不同，本方案不淘汰 KVCache、不牺牲精度。
