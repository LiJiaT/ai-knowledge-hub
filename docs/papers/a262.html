简介

论文针对的问题是：数学研究的日常是长期、有状态、高度迭代的探索过程（管理不确定性、综合文献、跟踪分支假设），而聊天界面转瞬即逝、专用引擎缺乏全局上下文，缺少把各类 AI 能力编排成长期协作工作流的一层。Google DeepMind 据此构建 AI co-mathematician：一个基于标准 Gemini 模型、不含任何定制模型训练的 agentic harness。系统以有状态 workspace 与共享文件系统承载项目状态，采用项目协调 Agent→workstream 协调 Agent→专用子 Agent 的层级多智能体架构并行推进目标，Agent 间经内部消息系统通信，并以硬性程序约束（代码须测试通过且经 reviewer Agent 接受）加上人在回路双向干预来抑制幻觉与投机取巧。关键结论：系统在 FrontierMath Tier 4 取得 48%（23/48）的新高分，显著超过其基座 Gemini 3.1 Pro 的 19%；早期数学家用户用它解决了 Kourovka Notebook 开放问题等真实研究任务。论文同时主张，对这类交互式 Agent 应采用人在回路、覆盖更广能力的评测范式。

问题

数学研究的日常是长期、有状态、高度迭代的探索，但现有 AI 支持存在编排缺口：标准聊天界面天然转瞬即逝，专用引擎（形式证明器、进化搜索等）缺乏更广上下文，研究者不得不在对话式头脑风暴、形式证明器与计算脚本之间充当'人工连接组织'；软件工程的 AI 编排环境（如 Claude Code、OpenAI Codex）又只为代码生命周期优化，不适配数学的独特抽象、证明与产物。论文要构建一个让数学家以人在回路方式驱动 AI Agent 开展开放式研究的原生工作台，覆盖 ideation、文献检索、计算探索、定理证明与理论构建全流程。

方法

核心是一个纯 harness（基于标准 Gemini 模型，明确不依赖任何定制模型行为或训练）：1) 有状态 workspace：项目全部信息存于共享文件系统，Agent 层级经内部消息系统通信并设有清晰升级路径；2) 层级多智能体：项目协调 Agent 先通过交互式 onboarding 与用户对话细化并确认研究目标，再将其分解为并行 workstream，各由 workstream 协调 Agent 执行线性动作序列，并可用子 Agent 创建工具派生专用子 Agent（文献检索、证明（含 Gemini Deep Think）、编码等）；3) 可靠性机制：硬性程序约束——代码未通过测试且未经 reviewer Agent 接受不得标记完成；失败探索作为持久记录保留，迫使协调 Agent 向用户披露不确定性并主动求助；4) 工具集：计算密集型文献检索、web 查询、云端多机并行代码执行、子 Agent 创建；5) 产出：经审查的 LaTeX 长文等原生数学产物，以及供用户判断进度的增量报告。

关键结果

FrontierMath Tier 4：排除两道公开样题后正确解决 48 题中的 23 题，准确率 48%，为所有已评测 AI 系统中的新高分；其基座模型 Gemini 3.1 Pro 单次调用为 19%

FrontierMath 上解出了 3 道此前没有任何已评测系统解出的问题，同时也有 2 道此前至少被一个系统解出的问题未能解出

内部基准（100 道未泄露的研究级数学问题、答案可代码校验）：显著优于单次调用 Gemini 3.1 Pro 与单次调用 Gemini Deep Think（正文未给出具体数值，见图 5）

真实使用案例：M. Lackenby 借助系统解决了 Kourovka Notebook 开放问题 21.10（有限群是否允许 'just finite presentation'，答案为肯定）；G. Bérczi 的两个 Stirling 系数猜想获得证明（处于详细人工审查中）并附计算证据；S. Rezchikov 的 Hamiltonian 系统关键引理获得经得起核查的证明

创新点

区别于端到端自主解题系统（AlphaProof、Aletheia）、进化搜索系统（AlphaEvolve）和转瞬即逝的聊天界面，本文把'编排层'作为核心贡献：有状态 workspace、层级委托与并行 workstream、硬性程序约束、双向人在回路（系统卡住时也会主动向用户求助）、原生数学产物（LaTeX 长文）输出；并强调系统是模型无关的 harness，可为未来接入 AlphaProof/Aletheia/AlphaEvolve 等引擎预留位置。评测理念上主张从静态解题基准转向人在回路与协作效能的度量。
