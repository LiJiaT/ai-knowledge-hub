Are LLMs All You Need for Task-Oriented Dialogue?

LLM 就是任务型对话（Task-Oriented Dialogue）所需的一切吗？

简介

论文评估 instruction-finetuned LLM 在任务型对话（TOD）中不做微调、开箱即用的能力：能否在多轮对话中精确跟踪 belief state 并与外部数据库交互。作者构建了一条纯 in-context 的 LLM pipeline，每轮依次完成领域检测、状态更新（仅输出本轮变化的 slot-value 对、要求 JSON 格式）、再据状态查询数据库并生成 delexicalized 回复；可选地用 FAISS 向量库按上下文相似度检索领域内 few-shot 正例与构造的负例注入提示。在 MultiWOZ 2.2 与 SGD 上以 zero-shot/few-shot × 预测/oracle 状态四种变体测试五个 instruction-tuned 模型（含 ChatGPT、Tk-Instruct 等）。关键结论：LLM 在显式状态跟踪上显著落后监督式专用模型；但给定正确 belief state 时能较成功地引导对话完成，few-shot 示例稳定带来提升；人工交互评测中模型实际表现优于单轮自动指标的预期，错误可分为可通过提示工程修复的与幻觉等固有错误两类。

问题

instruction-finetuned LLM 在开放域聊天中表现出色，但面对需要遵循预定结构、精确处理信息并与外部 API/数据库交互的任务型应用时，其不微调（zero-shot/few-shot in-context learning）的开箱即用能力如何？论文以任务型对话（TOD）为测试床，系统评估 LLM 在多轮任务完成、显式 belief state 跟踪与数据库交互上的能力边界。

方法

构建免微调的 LLM TOD pipeline：每轮对话进行三次 LLM 调用——(1) 领域检测；(2) belief state 更新（只输出当前轮新增/变化的 slot-value 对，要求 JSON 格式，全局状态逐步累积，遵循 MinTL 的状态更新思路）；(3) 用更新后的状态查询数据库，将状态与 DB 结果一并放入提示生成 delexicalized 回复。可选的上下文存储：以对话上下文（前两轮 user+system 话语）为 key，经 sentence-transformers embedding 编码后存入 FAISS 向量库，按相似度检索领域内 few-shot 示例（含通过随机替换 slot 值构造的负例）注入提示。实验设置 zero-shot/few-shot × 预测/oracle belief state 四种变体，在 MultiWOZ 2.2 与 SGD 上评测五个 instruction-tuned 模型（正文提及 ChatGPT、Tk-Instruct、GPT-NeoXT、OPT-IML），并结合自动指标与人工交互评测及错误分析。

关键结果

显式 belief state 跟踪上 LLM 与监督式专用模型存在巨大差距，也低于 Hu et al. (2022) 用 few-shot in-context learning 报告的 JGA 43.13%（本文各模型具体数值在论文表格中）

ChatGPT 在状态跟踪与对话成功率上均明显优于其余测试模型；响应生成方面 Tk-Instruct 与 ChatGPT 大致持平，但 BLEU 总体远低于监督 SOTA

提供 oracle belief state 时，部分模型的响应生成/对话引导达到与早期 finetuned SOTA 相当的水平；作者声称其 zero-shot 结果在 MultiWOZ 与 SGD 的无监督 TOD 建模上建立了 SOTA

few-shot 检索示例通常提升对话成功率（oracle 状态下对所有模型一致有效）；每域仅存 10 个示例（约 MultiWOZ 训练集的 0.6%）即可获得主要收益，继续扩大示例池不再带来性能提升

错误分析（每模型约 20 个失败对话）：幻觉出现在约 10-20% 的检查对话中；GPT-NeoXT 与 OPT-IML 在超过 50% 的失败对话中生成超出要求的内容；Tk-Instruct 约 10% 的情况直接复制提示示例中的 belief state

人工交互评测（6 名标注者）：ChatGPT 与 Tk-Instruct 实际表现优于自动指标预期，ChatGPT 在对话成功与 JGA 上均更优且所需澄清轮次更少

使用 oracle domain 检索示例并未提升性能、某些情况下反而变差，说明模型自身的领域检测对检索已足够

创新点

与以往需在域内数据上微调的 LM-based TOD 工作（Peng et al. 2021、Lin et al. 2020 等）不同，本文完全依赖预训练 instruction-tuned LLM 的 in-context learning、不做任何微调，以测出模型的开箱即用能力；相比 Hu et al. (2022) 仅用 LLM 做 belief state 跟踪（SQL 生成形式），本文覆盖完整 pipeline（领域检测+状态跟踪+数据库检索+响应生成），并引入向量库检索 few-shot 正例与人工构造负例的上下文存储机制，以及自动指标与人工交互评测结合的系统评估。
