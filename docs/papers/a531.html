Understanding In-Context Learning from Repetitions

从重复现象理解 In-Context Learning

higharXiv提示技术思维链与推理可靠性与安全基于arXiv版本
下载原文 PDF

简介

这篇论文从'表面重复'的视角解释 LLM in-context learning (ICL) 的作用机制。作者通过掩蔽与随机扰动示范中的各组成部分，实证提出 token co-occurrence reinforcement：任意两个 token 会随上下文共现次数增加而强化连接，该效应源于模型对训练似然最大化的优化。实验表明这种强化是双刃剑：一方面，格式词（'Answer:'、选项名）足以约束输出空间并驱动模型复现 'Let's think step by step.' 等 CoT 模式，即使问题与选项内容被完全掩蔽；另一方面，非信息性短语或失衡的示范答案会形成虚假连接，把输出系统性引向特定选项（D 类准确率从 0.52 升至 0.78，其余从 0.63 降至 0.58）。对团队而言，它为 few-shot 示范设计给出可操作准则：标签均衡、示范精简、避免不必要的重复模式。

问题

In-context learning (ICL) 的工作机制仍是开放问题。已有研究多关注 input-label mapping 与 demonstration construction 等因素，但很少研究 ICL 行为与文本表面特征（surface features）之间的关联。本文试图从表面重复模式的角度解释 ICL 为何有效，以及为何在上下文变化时会脆弱、失败。

方法

采用特征中心（feature-centric）视角：将示范分解为格式 token（'Input:'/'Answer:'）、输入、输出等部分，通过随机 token 替换与掩蔽逐步扰动示范，量化表面模式与生成概率的关系；实证提出 token co-occurrence reinforcement（任意两个 token 因上下文共现次数增加而强化连接，区分为 successive 与 distant reinforcement）；在约 5.7B token 的 wikipedia-english-2022 预训练语料上统计词复现概率，论证该效应源于模型对训练似然最大化的优化；用注意力掩蔽实验定位内部机制（每个 token 迭代关注其相邻前一 token）；最后在 MMLU 与 GSM8K 上通过掩蔽格式词、注入非信息性短语、重排示范答案等消融实验，验证强化对 ICL 的有益与有害影响。

关键结果

重复句子 'Answer is A' 10 次后，LLaMA-7B 在 'Answer is' 后生成 'A' 的概率从 0.03 提升至接近 1.0

successive reinforcement（相邻 token）仅几次重复即可将概率从 0 提升至 0.4；distant reinforcement（远距离 token）提升至 0.2 且对 token 间距离不敏感

MMLU 上掩蔽示范中的问题与选项内容不影响约束标签空间，而替换 option names 与 answer indicators 后该能力大幅下降

GSM8K 上掩蔽分隔符 '//' 后，示范带来的 'Let's think step by step.' 概率增益几乎消失

在答案为 D 的示范中注入非信息性短语（如 'Please kindly provide your answer.'）显著提升 D 类样本准确率，代价是 A、B、C 准确率下降

示范中答案 D 占比提高时，D 类样本准确率从 0.52 升至 0.78，A/B/C 类从 0.63 降至 0.58

预训练 267M 模型时掩蔽重复特征导致比掩蔽随机 token 更差的收敛损失，说明利用重复特征有助于似然优化

阻止 token 关注其前一个 token 后，强化强度降低约十倍

LLaMA（7B-65B）、OPT（125M-30B）以及附录中的 LLaMA-2、Mistral、GPT-J 均表现出 token 强化效应，且模型越大强化越强

创新点

与从 input-label mapping、贝叶斯推断、meta-optimization/implicit finetuning、induction heads 等角度解释 ICL 的已有工作不同，本文以论文自述的 novel perspective 从 surface repetitions 与强化特征理解 ICL，将 ICL 视为不同强度 token 强化连接的组合而非输入-标签映射，同时解释了 ICL 的成功（约束输出空间、模式跟随）与失败（虚假连接导致的输出偏置），并把文本生成中的 repetition/self-reinforcement 问题与 ICL 能力联系起来。
